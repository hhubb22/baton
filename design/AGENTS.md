# Baton Elyx 设计项目

此目录管理 Baton Web UI 的界面设计。`.elyx` 保存设计，`elyx.json` 保存项目配置。产品行为以仓库 `specs/` 为准；设计稿独立于 `web/` 里的代码，代码按设计稿实现。

## 项目结构

- `index.elyx`：设计系统总览。
- `tokens/`：浅色语义颜色（默认）、`theme=dark` 覆盖、Project 头像底色、间距、圆角和骨架尺寸。
- `foundations/`：文字样式。
- `controls/`：基础控件和图标。图标都是 `icons.glyph` 的变体，实例里用 `@with-variant(icons.<名称>)` 换图标。
- `blocks/`：组合区块。`project-page.elyx` 是完整的 Project 页，`thread-list.elyx` 是完整的 Thread 页，screens 里的页面状态都是它们的实例。`thread-detail.elyx` 收着 Thread 详情的全部状态；`new-thread.elyx` 是位置菜单和模型菜单，`enroll-dialog.elyx`、`file-preview.elyx` 是接入设备和文件预览。
- `screens/`：完整页面，一类页面一个文件，同一页面的不同状态放在同一文件的多个画板里。
- `resources/assets/`：SVG 图标，24 视框、1.7px 描边、黑色单色。

## 设计规则

- 青色（`agent`、`agentText`、`agentSoft`）只用于 Project Agent：它的标识、运行中状态和它给出的建议。用户主操作用蓝色 `accent`，即发送和主按钮；卡片里的次要动作用 `accentSoft` 底配 `link` 文字。侧栏的 Baton 标识用近黑色，保证一屏只有一处实心蓝。
- 一屏最多一个实心主按钮，其余用 secondary 或 ghost。
- 浮层最多两层。需要第三层时改用弹窗，并替换当前弹窗。
- 弱化文字用 `muted` 或 `faint`，不用透明度。`faint` 只给占位符和元信息。
- 主对话是一列：用户消息、Project Agent 的回复、卡片、状态片和输入区共用最宽 720px 的同一列，左右边缘对齐。用户消息是右对齐的浅灰气泡，Project Agent 的回复是靠左的正文，没有头像和名字。
- Thread 详情和主对话用同一套聊天样式：发给 Agent 的消息是右对齐气泡，Project Agent 发的在气泡左下角带它的青色标识，你发的不带；Agent 的回复是靠左的正文，开头一行可展开的过程记录，收着这一轮的工具调用、命令和文件改动，点开时从设备读取，设备离线时写明暂不可查看；执行中的一轮把这一行换成往上走的计时器，下方展开实时输出，这一轮结束后收起；附件收在正文后的卡片里；关联的事项以卡片出现在时间线里。标题栏只放名称和状态；设备和目录是 Thread 输入区下方一行浅色小字，Agent 写在输入区的提示文字里。
- 文案写短句，不写说明书。能靠交互表达的（点开、展开、悬停），不写成文字。时间、设备、发送方这类背景信息交给惯例：时间和用时悬停显示，执行环境放在输入区附近，发送方用标识区分。文字留给需要说明原因或下一步的状态，例如「离线，暂不可查看」「排队中 · 撤回」。
- 输入区白底、发丝线外框、两层浅阴影、20px 圆角，提示文字在上，工具栏在下：左边是全圆角选择片（位置、模型）和分段切换，右边是 32px 圆形发送按钮。主对话输入区只给 Project Agent 发消息，没有选择片。Agent 不单独做选择片，写在提示文字里，例如「给 Codex 发消息」；Thread 输入区的模型选择片只列这个 Agent 的模型。Thread 详情替换概览栏时，输入区上方显示状态片，汇总执行中、等待设备和等你决定的数量。
- Project Agent 一轮里的内容按顺序排：先是一行可展开的过程记录，收着这一轮执行的命令和记忆修改，每条一行，点开在原位展开；然后是 Thread 卡片，这一轮开过或发过消息的 Thread 每个占一行；最后是正文。Thread 行写状态点、名称、目录的最后一段，右侧是设备 · Agent 和状态；执行中只显示这一轮往上走的计时器，其余状态只显示状态名。点 Thread 行在右侧打开详情。
- Thread 页顶部是新建 Thread 的输入区，选位置和模型，发出第一条消息即新建；位置写成「目录 · 设备」，预填默认设备上次用的目录，模型预填这个位置上次用的 Agent 和模型。网页上新建的 Thread 不属于 Project，不选 Project，也不设执行时限。侧栏的新建按钮跳到 Thread 页并聚焦这个输入区。输入区下面是占满宽度的分组列表，按设备、Project 和是否归档筛选。点一行在右侧打开详情，列表收起 Project 和目录两列；这里的详情没有返回按钮。
- 等待和异常状态（等待设备、状态未知、执行中设备离线、已停止、无法恢复、已归档）用输入区上方的横幅表达。Thread 不能再继续时（已归档、无法恢复、启动失败）不显示输入区；已归档和无法恢复的横幅没有动作，启动失败的动作是「查看设备」。
- 注册凭据只在弹窗里显示和复制，注册命令从环境变量或标准输入读入凭据，不把凭据写进命令行参数。
- 文件预览从设备实时读取，设备离线或路径不在登记目录内时只显示原因和动作，不显示旧内容。
- 卡片只有两种：Thread 卡片和等你决定的事项，Thread 里的附件列表沿用同样的外观。卡片用 `surface` 底、`hairline` 外框、14px 圆角和两层浅阴影，行之间不加分隔线。事项的选项是带序号的浅灰行。
- 状态点只有六种颜色：蓝执行中，灰等待设备、空闲、已归档或离线，绿设备在线，红已停止，橙状态未知或等你处理，青 Project Agent 运行中。Baton 不判断一轮成功还是失败，没有表示成功或失败的颜色。具体含义由旁边的文字说明。
- 每个等待或异常状态都配一句标题和一句说明，能处理时才配一个动作。
- 不可用的操作保持可点，点击后说明原因，不用禁用态表达。
- 表面分四级：`canvas` 主内容区、`panel` 侧栏与概览栏、`surface` 卡片输入区弹窗、`subtle` 悬停与标签底色。边框用 `borderSoft`、`border`、`borderStrong`（8%、11%、16%），卡片和输入区外框用更浅的 `hairline`（6%）配浅阴影。
- 界面字体 PingFang SC，字重只用 Regular、Medium、Semibold；代码用 Paper Mono，含中文的等宽内容用 Maple Mono CN。常用字号 20、15、14、13、12。控件高度 20、28、32，圆角 4、6、8、12；卡片 14，气泡 18，输入区 20，分段切换、选择片和状态片用全圆角。
- 文案按 specs 的说法写，例如「Project Agent」「Thread」「排队」「插入」「等待设备」「事项」。

## 编写注意

- Elyx 保留字不能作声明名，例如 `where`、`use`、`type`、`data`、`in`、`ref`，完整列表见 `elyx man syntax`。
- `@with-variant` 只能写在实例内部的子块上；要直接用某个变体，写成 `name = frame : file.variant {}`。
- `insert`、`remove` 的参数按词法查找，要写完整路径，例如 `remove(page.projectPage.main.transcript.typing)`。
- 组件声明不写 `left` 时以 x=0 居中，画板和组件示例都写明 `left`、`top`。
- 插进 slot（例如弹窗的 `content`）的子图层，在变体和实例里要写在 `content { }` 下覆盖。
- Paper Mono 没有中文字形，含中文的等宽文字用 Maple Mono CN；代码文字里用空格缩进，不用制表符。
- 用 `subrange` 把正文里的路径或命令设成 Paper Mono，不拆成多个文字图层。实例覆盖里的 `subrange` 会被 normalize 删掉，需要时在实例里新建文字图层。

## 验证

使用 Elyx skill 和 CLI 检查解析后的组件、实例和布局。修改 `.elyx` 后，运行 `elyx normalize -w <文件>` 和 `elyx diagnostics design`，并渲染受影响的页面。命令均从仓库根目录运行。渲染截图写入被 Git 忽略的 `design/renders/`，验证日志保留在仓库外。
