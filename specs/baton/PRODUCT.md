# Baton 行为规格

Status: approved
Owner: 待指定
Basis: 《Baton 需求描述》及其后续讨论。Project Agent 见 [Project Agent 行为规格](../project-agent/PRODUCT.md)，事项见 [Agent Inbox 行为规格](../agent-inbox/PRODUCT.md)；那里的「用户」即本文的员工。

## 概述

员工在自己的多台设备上（Ubuntu 开发机、Windows、macOS、Linux PC、虚拟机）运行 batond，通过 Baton 的网页统一使用各设备上的 Codex、Kiro、Pi 等 Agent。

每次使用就是一个 Thread：在某台设备的某个目录里，和某个 Agent 的一段会话。员工可以自己开 Thread，也可以把一件长期的事交给 Project，由 Project Agent 替他在合适的设备上开 Thread、发消息、读回复。

中心（Coordinator 与 PostgreSQL）保存账号、设备、Thread 记录、Project 和事项。Thread 的完整历史留在设备上，中心只保存每条回复和附件，供设备离线时查看。设备主动连接中心，中心不需要访问设备，设备之间也不直连。

## 首版范围

| 能力 | 首版约定 |
|---|---|
| 设备接入 | Ubuntu 开发机；Windows、macOS、Linux PC；虚拟机可独立注册 |
| Thread | 在指定设备、目录、Agent 和模型上开会话，多轮对话、停止、恢复、归档 |
| Project | 每个 Project 一个 Project Agent 和一个主对话，见 Project Agent 行为规格 |
| Agent Inbox | 等员工决定的事项，见 Agent Inbox 行为规格 |
| 网页 | 设备与默认设备、Thread 列表与内容、实时输出、受限文件浏览、Project、Agent Inbox |
| 大文件 | 不经设备控制连接；附件可以引用现有传输通道中的文件，不提供中央文件存储 |

Agent 支持目标是 Codex、Kiro、Cursor、Pi。各系统上实际交付哪些 Agent 和能力见 D1，未验证的组合不显示为已支持。

本期不包括：中央设备登记与租约、危险命令逐条审批、实验室无人值守节点、模型 API 代理、执行 Agent 之间直接委托、Plane 等外部工单触发、设备之间的文件传输。

## 术语

| 术语 | 含义 |
|---|---|
| 员工 | Baton 的使用者，拥有自己的设备、Thread 和 Project |
| 设备 | 运行 batond、有稳定 ID 的一份运行环境；宿主机与虚拟机可以是不同设备。员工给设备起的名字在界面上代表它 |
| 默认设备 | 员工选定的一台设备，新建 Thread 时默认选中它，Project Agent 也优先在它上面运行 |
| Agent 类型 | Codex、Kiro、Cursor、Pi 等可接入的执行 Agent |
| Thread | 某台设备上某个目录里和某个 Agent 的一段会话，对应 Agent 自己的原生会话。属于员工，可以属于一个 Project |
| Turn | Thread 里的一轮：从一条消息发出，到 Agent 停下来等待下一条消息为止。一轮里 Agent 可以有多条回复 |
| 回复 | Agent 在一轮里给出的一条消息，可以带附件 |
| 附件 | 回复引用的文件或代码提交，例如日志、截图、生成的文件。Baton 不区分附件的用途 |
| Project、Project Agent、主对话 | 见 Project Agent 行为规格 |
| 事项 | Project Agent 请员工处理的一件事，见 Agent Inbox 行为规格 |

## 行为

### 身份与设备

**R-01｜员工隔离**

员工只能查看和操作自己的设备、Thread、文件、Project、对话、记忆和事项。这一限制适用于网页、Project Agent 的工具调用和设备上报。请求引用其他员工的对象时拒绝，不向其设备发送任何内容。

**R-02｜设备注册与身份**

员工登录后获得有有效期、绑定本人身份的注册凭据，用它注册 batond。`batond up --coordinator https://主机` 在首次运行时注册并连接，已有本地身份时复用；`--workspace` 在连接前幂等登记已存在的绝对目录为可浏览目录，符号链接解析为真实路径。未指定 workspace 且本机没有浏览目录配置文件时，`up` 和 `run` 默认开放当前用户主目录；已有空列表表示用户已移除所有目录，重启不补回主目录。注册默认以主机名作为显示名并自动识别系统，可显式指定。注册成功后，中心保存设备 ID、员工、名字、系统和注册时间，向设备签发可吊销的连接凭据。设备在本地身份文件中保存中心 HTTPS 地址，后续 `batond run` 或 `batond up` 自动推导 WSS 连接地址；显式 `--relay` 优先，身份文件没有中心地址时须提供该参数。

设备重启、改名或网络地址变化不产生新身份。凭据失效时，设备显示认证失败，不反复注册成新设备。同一身份不能被两个同时运行的环境共用，冲突时阻止第二个环境接管。账号来源和凭据期限见 D2。

**R-03｜连接与在线状态**

batond 主动建立到中心的 TLS WebSocket 连接，断线后自动退避重连。网页显示在线状态和最后联系时间。重连后尚未完成状态同步的设备不显示为可用。心跳与离线判定时限作为部署配置公开。

同一 batond 的新连接替换旧连接后，旧连接迟到的断开事件不能把设备标为离线。连接成功、设备已同步、Thread 执行状态分别表示，不能互相代替。

**R-04｜凭据吊销**

员工可以吊销本人设备的连接凭据。吊销保存后即拒绝该凭据的新操作，断开现有连接；只有新连接已被禁止、已有连接已关闭，界面才显示已生效。中心重启后仍拒绝已吊销凭据。吊销不等于已经停止离线设备上的 Agent，界面要说明这一点。历史记录保留。

**R-05｜默认设备**

员工没有默认设备时，选择最早注册的有效设备并保存，不因重连或新增设备而重算。员工可以改为本人的其他有效设备；选择离线设备时提示离线，仍允许保存。默认设备被吊销时提示重新选择，不自动切换。

**R-06｜设备能力**

设备上报已接入的 Agent 类型、版本、可用模型和默认模型，以及可用能力（新建、排队、插入、停止、恢复、换模型），缺少程序、认证或配置时显示具体缺项。设备还上报：是否装有 Project Agent Runtime、各模型订阅的登录状态、员工登记的目录、这些目录中发现的代码仓库、是否允许 Project Agent 执行命令及使用的 shell。订阅凭据不离开设备。员工在该设备使用 `batond login openai-codex|xai` 完成 Project Agent 的订阅登录，使用 `batond subscriptions` 查看本地状态及登录指引；命令无需先注册或连接中心。网页设备详情支持为在线且已同步的本人设备发起设备码登录，显示授权网址、验证码和有效期，支持复制验证码；用户在授权网址完成确认，设备后台轮询并在结束后立即刷新订阅状态。网页在设备报告已登录后显示 `Signed in`，取码失败或验证码过期时支持重新获取。同一订阅服务的新登录会取消旧登录，后台登录最长等待 15 分钟。登录与守护进程使用相同的系统用户和 Runtime 凭据目录，在线设备自动上报状态。状态查询不刷新凭据或请求模型，Runtime 缺失或探测失败时返回错误。选择设备不支持的 Agent 或操作时，在执行前返回原因。

### Thread

**R-07｜新建 Thread**

新建 Thread 需要设备、工作目录、Agent 类型和第一条消息，可以指定模型；设备未指定时用默认设备，模型未指定时用这个 Agent 在该设备上的默认模型。工作目录必须位于该设备登记的目录内并且已经存在。员工在网页上新建的 Thread 不属于 Project；属于 Project 的 Thread 由 Project Agent 新建（Project Agent PA-18）。请求带客户端生成的标识，用同一标识重发相同内容时返回原 Thread，内容不同时返回冲突。

模型可从设备上报的目录选择，也可手填模型 ID；目录用于发现与补全，显式 ID 由原生 Agent 判定是否可用。

中心保存 Thread 后返回 Thread ID；设备离线时 Thread 处于「等待设备」，设备上线并同步后开始。条件不满足（目录不存在、Agent 不可用等）时，Thread 进入「已停止」并显示原因，不改派到其他设备。

**R-08｜发消息**

员工可以向自己的 Thread 发消息。Agent 空闲时，消息开启新的一轮。Agent 正在处理时，发送方选择一种方式：

| 方式 | 行为 | 支持范围 |
|---|---|---|
| 排队（queue，默认） | 这一轮结束后，作为下一轮的第一条消息发出。排队的消息按发送顺序处理，在发出前可以撤回 | 所有 Agent。由设备上的 Worker 保存，这一轮结束后发出 |
| 插入（steer） | 加入当前这一轮，Agent 在下一个可以接收输入的时机读到它 | 只在 Agent 原生支持时提供，由设备能力上报（R-06） |

开启新一轮的消息可以换模型，从这一轮起使用新模型；插入的消息沿用当前这一轮的模型。Agent 不支持换模型时，整个 Thread 使用新建时的模型，换模型的请求在执行前返回原因。

Agent 不支持插入时只能排队；需要立即改变方向时，先停止这一轮再发消息。每条消息带客户端生成的标识，确认丢失后用同一标识查询或重发，不会被 Agent 收到两次。设备离线时消息等待设备，界面显示等待。

**R-09｜回复与 Turn**

Agent 在一轮里的每条回复按顺序记录。适配器报告 Agent 已停下来等待输入时，这一轮结束；到达执行时限或被停止时，这一轮也结束，并记录原因。中心保存每条回复的有界正文和附件引用，设备离线时仍可查看；完整回复、工具调用和命令输出保存在设备（R-15）。Baton 不要求 Agent 交回固定结构，也不判断这一轮是成功还是失败，结论由读回复的人或 Project Agent 判断。

过程记录有步骤被截断时，网页保留完整步骤和已取得的片段，在被截断的步骤旁标明缺口。

回复正文超过 32 KiB 时，中心保存开头和结尾。设备保存普通回复的全文与 shell 原始输出，网页可以逐段继续读取或下载当前片段。完整内容默认保留 30 天，设备可配置保留天数；设备离线、内容过期或已删除时，网页显示具体原因，中心保存的片段仍可查看。

**R-10｜Thread 状态**

| 状态 | 含义 |
|---|---|
| 等待设备 | 已保存，设备离线或尚未同步 |
| 执行中 | Agent 正在处理一轮 |
| 空闲 | 这一轮已结束，可以发下一条消息 |
| 已停止 | Agent 进程已退出或无法启动，附原因；能力允许时可以恢复（R-12） |
| 状态未知 | 无法确认 Agent 是否还在运行，或无法确认最后一条消息是否被收到（R-13） |
| 已归档 | 员工归档，不再接收消息 |

界面同时显示设备连接状态和最后一次报告的时间，不把过去的执行中当成当前事实。执行中显示这一轮已经过的时间。

**R-11｜停止与归档**

员工可以停止 Thread 当前的一轮，排队中尚未发出的消息一起撤回。界面显示停止请求已发送及确认情况；只有设备确认停止后，Thread 才变为空闲或已停止。Agent 1 分钟内没有停下时，Baton 结束 Agent 进程，Thread 变为已停止，下一条消息按 R-12 恢复原会话。停止不回滚已经发生的文件修改、命令或设备动作。员工可以归档 Thread，归档前先停止正在进行的一轮。

**R-12｜恢复**

Agent 进程退出后，如果设备和 Agent 支持恢复、本地历史仍在，员工发消息时 Baton 恢复原会话，Thread ID 不变。恢复不重放历史里的工具调用。无法恢复时返回原因；员工可以新开一个 Thread，不伪装成原会话已恢复。

**R-13｜不确定的情况**

设备断线、Worker 崩溃、回执丢失可能让 Baton 无法确认一条消息是否被 Agent 收到，或 Agent 是否还在运行。这时 Baton 先查询设备上的同一会话：能确认仍在运行就继续跟踪，能确认已收到就补回回复。仍无法确认时标为状态未知，不自动重发消息、不重新运行。员工看过情况后可以继续发消息。

**R-14｜期限**

等待设备没有期限，设备上线后再开始。每一轮有执行时限，默认 2 小时。员工可以在网页新建 Thread 时设置，也可以在已有 Thread 中修改，包括延长正在进行的一轮。时限是每轮的总时长，从该轮开始计算；修改不会重置开始时间。网页和 API 接受 1～2,147,483,647 秒的整数。设备收到设置后应用于当前和后续各轮，离线时先保存并等待设备上线。到达时限时，Baton 停止这一轮并记录原因，员工仍可以随时显式停止。

### 数据与界面

**R-15｜数据位置**

| 数据 | 保存位置 |
|---|---|
| 账号、设备、Thread 记录、每条消息与回复的有界正文、附件引用、Thread 状态变化 | 中心 |
| Project、主对话、输入队列、项目记忆、事项、Project Agent 的运行记录 | 中心 |
| 完整回复与 shell 原始输出，以及 Agent 原生会话的工具调用和中间过程 | 设备 |
| 模型订阅凭据、设备上的密码 | 设备 |

网页查看完整历史时，经权限检查从设备分页取回；设备离线时显示暂不可取回，本地数据已删除时显示历史缺失，中心保存的回复不受影响。执行 Agent 不能读取 Project Agent 的主对话或项目记忆。

**R-16｜实时输出**

员工可以看 Thread 的实时输出。流断开时显示中断，重连后从设备补取；无法补齐时标出缺口。中心只为传输使用有界缓存，不把流经的输出持久化。一台设备输出过多时，其他设备的消息、停止和状态确认不受影响；输出超限可以丢弃并标出缺口，控制消息不能丢失。

**R-17｜网页**

网页按设备和 Project 列出 Thread，显示状态、设备、目录、Agent 和最后活动时间。Thread 列表上方是新建 Thread 的输入区：位置（设备和目录）预填默认设备上次用的目录，模型预填这个位置上次用的 Agent 和模型，输入第一条消息发出即新建。Thread 页面显示消息、回复、附件和实时输出，提供发消息、换模型、撤回排队消息、停止和归档。操作失败时显示原因，不以按钮点击成功代替设备上的操作成功。本期只针对桌面浏览器，不发推送通知。

**R-18｜附件与文件浏览**

附件引用包含所在设备或存储位置、路径或资源标识和访问状态，不能只是一条无法判断属于哪台设备的本地路径。代码提交作为附件时写仓库地址和完整 commit SHA，之后工作区的修改不影响它。

员工可在设备本机或网页设备详情中添加、移除允许浏览的目录。选目录弹窗保留设备切换和目录树，同时支持直接输入设备路径，添加后选中该目录作为新对话位置。远程设置要求设备属于本人、在线且已同步，并等待设备确认保存；同一路径重复添加返回已有目录。网页只能列出这些目录中的内容，查看受限大小的文本预览，截断时明确标记。符号链接和 Windows 目录联接解析后仍必须位于允许范围内。越界、未授权或设备离线时拒绝并说明原因。附件指向登记目录中的文件时，可以直接打开预览；设备离线时显示暂不可查看，不显示过期内容。

大文件、二进制内容和完整日志不经设备控制连接传输，控制消息只携带引用和受限预览。

### 可靠性与安全

**R-19｜中心重启与不可用**

中心重启会断开设备连接。batond 自动重连并同步，同步完成前设备不显示为可用。设备上正在进行的一轮继续执行，未送达的回复和状态保存在设备本地，恢复后补报；同一条回复在中心只保存一份。中心无法保存时不接受新 Thread 和新消息。Project Agent 的每一步都要先保存到中心，中心不可用时它在本地期限到达前停止，已开的 Thread 不受影响。

**R-20｜batond 重启**

batond 重启后保留设备身份和本地历史，尝试确认原 Agent 是否仍在运行：仍在时继续跟踪，不能确认时标为状态未知。历史文件损坏或被删除时明确显示原因。

**R-21｜授权边界**

Baton 强制执行员工隔离、设备归属和工作目录范围。Agent 在目录内能做什么由 Agent 自身的权限和设置决定，Baton 不宣称提供命令沙箱。员工在某台设备上开启「允许 Project Agent 执行命令」后，Project Agent 可以在登记目录下执行任意命令，开关默认关闭。

**R-22｜敏感数据**

设备密码和模型订阅凭据留在设备，不发给中心，也不放进消息。设备令牌、注册凭据不进入日志。中心不持久化实时输出和完整会话历史。

**R-23｜可追溯性**

设备、Thread、Project、事项和 Project Agent 的每次运行都有可关联的标识。Thread 由谁新建、每条消息由员工还是 Project Agent 发出、停止、归档、默认设备变更、凭据吊销都记录操作者和时间。中心提供在线设备、连接、收发量、队列占用和 Thread 状态分布等诊断信息，不附带完整会话内容或秘密。

**R-24｜容量**

按约 110 名员工、约 220 台设备规划。压测场景：500 台在线设备、100 个同时执行的 Thread、每秒 100 个网页请求、每秒 200 条设备消息，持续 24 小时，并注入中心重启、设备掉线和数据库暂时不可用。压测前约定合格阈值，没有阈值时只记录观测结果。

**R-25｜协议扩展与发布兼容**

协议接收方忽略不认识的字段，消息携带协议版本，新增能力通过可选字段声明。产品在实验室阶段统一使用当前结构，可以重建数据库和设备账本，不维护此前开发版本的读取、升级或摘要兼容分支。正式发布并确定版本号后，才要求已发布版本之间的增量兼容，并为支持的版本组合提供验证。

## 验收

| 场景 | 条件与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| 三类 PC 接入 | 在 Windows、macOS、Linux 上注册与重连 | 设备身份稳定、能力准确，虚拟机可独立显示 | R-02、R-03、R-06 |
| 多轮 Thread | 在一台设备上新建 Codex Thread；Agent 执行中先插入一条消息，再排队一条消息 | 插入的消息在当前这一轮被读到；排队的消息在这一轮结束后开启下一轮；同一个原生会话；中心保存每条回复 | R-07～R-10 |
| 换模型 | 新建 Codex Thread 时指定模型，下一条消息换成另一个模型；对不支持换模型的 Agent 发同样的请求 | 两轮分别使用指定的模型，仍是同一个原生会话；不支持时在执行前返回原因，消息不发出 | R-06～R-08 |
| 排队可靠性 | Kiro 执行中排队两条消息，然后重启 Worker | 两条消息在这一轮结束后按顺序各发一次，没有丢失或重复 | R-08、R-13 |
| 离线等待 | 设备离线时新建 Thread 并发消息，之后设备上线 | 上线前显示等待设备；上线后开始，消息只被收到一次 | R-07、R-08 |
| 重复提交 | 用同一标识重复新建 Thread、重复发消息 | 只有一个 Thread，Agent 只收到一次消息；内容不同时返回冲突 | R-07、R-08 |
| 回执丢失 | 消息发出后断开连接，使 Baton 无法确认 Agent 是否收到 | 查询原会话；仍不能确认时标为状态未知，没有自动重发 | R-13 |
| 停止竞态 | 分别在一轮开始前、执行中、刚结束时停止 | 状态符合设备确认，界面不宣称已回滚 | R-11 |
| 恢复 | Agent 进程退出后发消息 | 支持恢复时继续原会话，Thread ID 不变；不支持时返回原因 | R-12 |
| 中心故障 | 执行中重启中心，短时停止数据库 | 设备重连，同步前不可用；这一轮继续，回复补报且不重复 | R-19 |
| 吊销竞争 | 吊销与认证、重连同时发生，随后重启中心 | 已吊销凭据不能继续操作；新连接不被旧连接的断开事件标为离线 | R-03、R-04 |
| 输出洪泛 | 设备 A 持续大量输出，设备 B 同时收消息和停止；浏览器慢读 | B 的操作持续得到处理，缓冲有界，输出缺口可见 | R-16 |
| 数据位置 | 一轮结束后让设备离线 | 中心仍能显示所有回复和附件引用；完整历史显示暂不可取回 | R-15 |
| 附件 | 回复带一个日志文件和一个 commit；之后设备离线 | 设备在线时可预览日志；离线时显示暂不可查看；commit 始终显示仓库和 SHA | R-18 |
| 越权与越界 | 请求其他员工的 Thread；访问登记目录外的文件 | 都被拒绝，没有返回内容 | R-01、R-18 |
| 协议扩展 | 当前消息带接收方不认识的可选字段；缺省未声明的可选能力 | 已知字段与核心行为保持正确；未知能力不启用 | R-25 |
