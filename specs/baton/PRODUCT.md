# Baton 行为规格

Status: draft
Basis: 《Baton 需求描述》及其后续讨论。Project Agent 见 [Project Agent 行为规格](../project-agent/PRODUCT.md)；那里的「用户」即本文的员工。

Thread 执行模式在创建时选择并持久保存，原生待审批请求通过 Thread 交给员工。发布与升级使用签名清单、固定入口及可恢复迁移；完整行为和验收范围见 [发布行为规格](../release/PRODUCT.md)。

## 概述

员工在自己的多台设备上（Ubuntu 开发机、Windows、macOS、Linux PC、虚拟机）运行 batond，通过 Baton 的网页统一使用各设备上的 Codex、Kiro、Pi 等 Agent。

每次使用就是一个 Thread：在某台设备的某个目录里，和某个 Agent 的一段会话。员工可以自己开 Thread，也可以把一件长期的事交给 Project，由 Project Agent 替他在合适的设备上开 Thread、发消息、读回复。

中心（Coordinator 与 PostgreSQL）保存账号、设备、Thread 的输入、回复、过程记录和事件、Project，设备离线时仍可查看中心历史。原生会话与超出中心上限的完整输出留在设备上，中心保存有界正文和附件引用。设备主动连接中心，中心不需要访问设备，设备之间也不直连。

## 首版范围

| 能力 | 首版约定 |
|---|---|
| 设备接入 | Ubuntu 开发机；Windows、macOS、Linux PC；虚拟机可独立注册 |
| Thread | 在指定设备、目录、Agent 和模型上开会话，多轮对话、停止、恢复、归档 |
| Project | 每个 Project 一个 Project Agent 和一个主对话，见 Project Agent 行为规格 |
| 网页 | 设备与默认设备、Thread 列表与内容、实时输出、受限文件浏览、Project |
| 大文件 | 不经设备控制连接；附件可以引用现有传输通道中的文件，不提供中央文件存储 |

Agent 支持 Codex、Kiro、Cursor、Pi，能力按设备上的安装与认证报告开放，系统和版本不限。验证范围保留在诊断中，准入规则见 D1。

本期不包括：中央设备登记与租约、危险命令逐条审批、实验室无人值守节点、模型 API 代理、执行 Agent 之间直接委托、Plane 等外部工单触发、设备之间的文件传输。

## 行为

### 身份与设备

**R-01｜员工隔离**

员工只能查看和操作自己的设备、Thread、文件、Project、对话和记忆。这一限制适用于网页、Project Agent 的工具调用和设备上报。请求引用其他员工的对象时拒绝，不向其设备发送任何内容。

**R-02｜设备注册与身份**

员工登录后获得有有效期、绑定本人身份的注册凭据，用它注册 batond。`batond up --coordinator https://主机` 在首次运行时注册并连接，已有本地身份时复用；`--workspace` 在连接前幂等登记已存在的绝对目录为可浏览目录，符号链接解析为真实路径。未指定 workspace 且本机没有浏览目录配置文件时，`up` 和 `run` 默认开放当前用户主目录；已有空列表表示用户已移除所有目录，重启不补回主目录。注册默认以主机名作为显示名并自动识别系统，可显式指定。注册成功后，中心保存设备 ID、员工、名字、系统和注册时间，向设备签发可吊销的连接凭据。设备在本地身份文件中保存中心 HTTPS 地址，后续 `batond run` 或 `batond up` 自动推导 WSS 连接地址；显式 `--relay` 优先，身份文件没有中心地址时须提供该参数。

设备重启、改名或网络地址变化不产生新身份。同一身份不能被两个同时运行的环境共用，冲突时阻止第二个环境接管。账号来源与一次性注册凭据期限见 D2。

设备连续 30 天没有实际业务活动后，连接凭据闲置过期。期限从注册、重新认证或最近一次有效业务活动中最晚的时间计算，以中心时间为准。仍有业务的设备持续使用，无需每隔固定天数重新认证。

| 活动 | 是否延长闲置期限 |
|---|---|
| 本设备实际接受新的 Thread 操作、执行回合或上报新的执行结果 | 是；已验证仍在执行的回合持续视为活跃 |
| 本设备运行 Project Agent 处理前台输入、执行前台工具 | 是；有效前台运行持续视为活跃 |
| 用户主动发起且由设备成功处理的文件读取、目录配置、订阅登录或执行权限设置 | 是 |
| 心跳、连接、重连、状态同步、能力探测、网页自动轮询与实时输出订阅 | 否 |
| 后台记忆整理、自动维护、失败请求、相同操作或报告的重复投递 | 否 |
| 仅在中心排队、尚未交付设备的请求，或其他设备上的业务 | 否 |

闲置期限到达后，中心停止向该设备派发新业务，关闭已有连接，设备与网页显示需要重新认证；设备本地尚未补报的结果继续保留。过期后到达的新请求、旧结果和后台工作不能自行恢复凭据。中心过去保存的执行中状态不能单独阻止过期。

员工在网页为自己的原设备领取一次性重新认证凭据，在设备本地执行重新认证；成功后保留设备 ID、注册顺序、默认设备选择、Thread 归属、目录配置和本地历史。请求重试不得重复创建设备或替换多次凭据。重新认证不重发结果不确定的历史输入，未补报结果按原身份补报。已吊销设备拒绝重新认证；本地身份材料丢失时显示原因，另行注册新设备，不自动接管原设备。

**R-03｜连接与在线状态**

batond 主动建立到中心的 TLS WebSocket 连接，断线后自动退避重连。网页显示在线状态和最后联系时间。重连后尚未完成状态同步的设备不显示为可用。心跳与离线判定时限作为部署配置公开。

同一 batond 的新连接替换旧连接后，旧连接迟到的断开事件不能把设备标为离线。连接成功、设备已同步、Thread 执行状态分别表示，不能互相代替。

**R-04｜凭据吊销**

员工可以吊销本人设备的连接凭据。吊销保存后即拒绝该凭据的新操作，断开现有连接；只有新连接已被禁止、已有连接已关闭，界面才显示已生效。中心重启后仍拒绝已吊销凭据。吊销不等于已经停止离线设备上的 Agent，界面要说明这一点。历史记录保留。

**R-05｜默认设备**

员工没有默认设备时，选择最早注册的有效设备并保存，不因重连或新增设备而重算。员工可以改为本人的其他有效设备；选择离线设备时提示离线，仍允许保存。默认设备被吊销时提示重新选择，不自动切换。

**R-06｜设备能力**

设备上报 Agent 类型、版本、模型和操作能力，以及 Project Runtime、目录、代码仓库和本机命令权限。设备详情分别管理订阅与 API 连接。API 连接保存名称、协议、Base URL 和模型 ID，可在同一设备保存多条；密钥仅保存在目标设备，桌面客户端可通过本机桥接填写，其他设备使用本地 CLI 输入。Project 选择模型来源和模型；订阅可由已登录的设备承接，API 连接绑定所属设备，设备离线时等待。保存配置只说明本地已保存，缺少密钥时显示 Key needed。删除连接时列出引用它的 Project。设备上可用 `batond login <provider>` 登录订阅，用 `batond subscriptions` 查看状态；ChatGPT 和 xAI 支持设备码登录，Claude 使用终端登录。状态查询不发模型请求。

### Thread

**R-07｜新建 Thread**

新建 Thread 需要设备、工作目录、Agent 类型和第一条消息，可以指定模型；设备未指定时用默认设备，模型未指定时用这个 Agent 在该设备上的默认模型。工作目录必须位于该设备登记的目录内并且已经存在。员工在网页上新建的 Thread 不属于 Project；属于 Project 的 Thread 由 Project Agent 新建（Project Agent PA-18）。请求带客户端生成的标识，用同一标识重发相同内容时返回原 Thread，内容不同时返回冲突。

模型可从设备上报的目录选择，也可手填模型 ID；目录用于发现与补全，显式 ID 由原生 Agent 判定是否可用。执行模式可选设备报告支持的上游 `RuntimeMode`，省略时使用上游 `DEFAULT_RUNTIME_MODE`，当前为 `full-access`；模式在创建时保存，规则见 R-21。

设备按模型报告原生 Agent 提供的思考强度及默认值。新建对话和发送下一条消息时可以选择报告中的强度；选择默认值时由 Agent 使用自己的默认设置。插话沿用当前回复的设置。模型不报告选项时，界面说明该模型没有提供思考强度选项。

中心保存 Thread 后返回 Thread ID；设备离线时 Thread 处于「等待设备」，设备上线并同步后开始。条件不满足（目录不存在、Agent 不可用等）时，Thread 进入「已停止」并显示原因，不改派到其他设备。

**R-08｜发消息**

员工可以向自己的 Thread 发消息。Agent 空闲时，消息开启新的一轮。Agent 正在处理时，发送方选择一种方式：

| 方式 | 行为 | 支持范围 |
|---|---|---|
| 排队（queue，默认） | 这一轮结束后，作为下一轮的第一条消息发出。排队的消息按发送顺序处理，在发出前可以撤回 | 所有 Agent。由设备上的 Worker 保存，这一轮结束后发出 |
| 插入（steer） | 加入当前这一轮，Agent 在下一个可以接收输入的时机读到它 | 只在 Agent 原生支持时提供，由设备能力上报（R-06） |

开启新一轮的消息可以换模型，从这一轮起使用新模型；插入的消息沿用当前这一轮的模型。Agent 不支持换模型时，整个 Thread 使用新建时的模型，换模型的请求在执行前返回原因。

Agent 不支持插入时只能排队；需要立即改变方向时，先停止这一轮再发消息。每条消息带客户端生成的标识，确认丢失后用同一标识查询或重发，不会被 Agent 收到两次。设备离线时消息等待设备，界面显示等待。

**R-09｜回复与 Turn**

Agent 在一轮里的每条回复按顺序记录。适配器报告 Agent 已停下来等待输入时，这一轮结束；到达执行时限或被停止时，这一轮也结束，并记录原因。中心保存每条回复的有界正文和附件引用，以及这一轮的过程记录，设备离线时仍可查看（R-15）。Baton 不要求 Agent 交回固定结构，也不判断这一轮是成功还是失败，结论由读回复的人或 Project Agent 判断。

过程记录按 Agent 报告的顺序列出这一轮的步骤：命令及其输出和退出码、文件修改、工具调用的输入与结果、文件与网页搜索、子 Agent、错误、上下文压缩，以及 Agent 提供的推理文本。内容以 Agent 实际提供的为准，不提供的部分不补造。Agent 上报的步骤全部显示，不按工具来源过滤；工具调用显示 Agent 给的标题和原生工具标识，输入和结果分别标明，Agent 没提供的一项不显示。步骤结束后才进入过程记录；进行中的步骤按 Agent 报告的顺序排在已结束步骤之后，实时显示标题、状态和 Agent 已提供的内容，不持久化（R-16）。Baton 不把步骤归入阶段，Agent 不上报阶段。设备离线期间结束的步骤在重新连接后补报，不重复、不遗漏，并且都排在这一轮结束之前。这一轮的结束记录同时保存所用模型和 Agent 报告的 token 用量。

单个步骤在中心最多保存约 192 KiB，超出时保存开头和结尾，并记录原始大小；全文留在设备，网页可以逐段继续读取或下载当前片段。网页保留全部步骤和已保存的片段，在被截断的步骤旁标明缺口和原始大小。

回复正文超过 32 KiB 时，中心保存开头和结尾，网页在回复旁标明已截断和原始大小，暂不提供读取全文的入口；未超限的回复不显示全文相关内容。设备保存被截断回复的全文、被截断步骤的全文与 shell 原始输出。完整内容默认保留 30 天，设备可配置保留天数；读取步骤全文或 shell 输出时，设备离线、内容过期或已删除的，网页显示具体原因，中心保存的片段仍可查看。

**R-10｜Thread 状态**

| 状态 | 含义 |
|---|---|
| 等待设备 | 已保存，设备离线或尚未同步 |
| 执行中 | Agent 正在处理一轮 |
| 空闲 | 这一轮已结束，可以发下一条消息 |
| 已停止 | Agent 进程已退出或无法启动，附原因；能力允许时可以恢复（R-12） |
| 状态未知 | 无法确认 Agent 是否还在运行，或无法确认最后一条消息是否被收到（R-13） |
| 已归档 | 员工归档，不再接收消息 |

界面同时显示设备连接状态和最后一次报告的时间，不把过去的执行中当成当前事实。执行中显示这一轮已经过的时间。

**R-11｜停止与归档**

员工可以停止 Thread 当前的一轮，排队中尚未提交 intent 的消息一起撤回。界面显示停止请求已发送及确认情况；设备中断执行，在默认 1 分钟预算内等待终态或尝试回收，并核实执行实例及所属进程均已停止，随后才报告 Thread 已停止。无法确认回收或输入结果时保留状态未知。下一条消息或显式恢复请求按 R-12 恢复原会话。停止不回滚已经发生的文件修改、命令或设备动作。员工可以归档 Thread，归档前先停止正在进行的一轮。设备已确认停止且没有活动回合或待发输入时，历史中的不确定消息随 Thread 一起保留，允许归档；归档不会重发这些消息。

**R-12｜恢复**

Agent 进程退出后，如果设备和 Agent 支持恢复、本地历史仍在，员工发消息时 Baton 恢复原会话，Thread ID 不变。恢复不重放历史里的工具调用。设备在创建会话前因 Agent 不可用或目录授权问题明确拒绝打开，且持久记录证明没有输入派发时，员工可以在原 Thread 中重试打开；失败记录和原文保留，原消息由员工再次发送。已经接收打开请求或启动结果不明时，继续按原会话的恢复证据处理。无法恢复时返回原因；员工可以新开一个 Thread，不伪装成原会话已恢复。

**R-13｜不确定的情况**

设备断线、Worker 崩溃、回执丢失可能让 Baton 无法确认一条消息是否被 Agent 收到，或 Agent 是否还在运行。存活 Worker 通过原 IPC 重新连接；Worker 崩溃后先回收旧进程，为已发送且未结束的回合补结束记录，再按排队消息或显式请求决定是否恢复原会话。发送结果不确定时只读核对既有接受证据，无法确认则标为状态未知，不自动重发。shell 根据完成记录恢复结果，缺少证据时不重新执行。员工看过情况后可以继续发消息。设备历史丢失时，中心依据持久投递记录区分输入：确定从未派发的输入撤回并保留原文，员工可再次提交；尝试派发过或已被设备接收的输入保留不确定状态。

**R-14｜期限**

等待设备没有期限，设备上线后再开始。每一轮有执行时限，默认 2 小时。API 可以在创建 Thread 时设置或修改已有 Thread 的时限，包括延长正在进行的一轮，接受 1～2,147,483,647 秒的整数。时限是每轮的总时长，从该轮开始计算；修改不会重置开始时间。设备收到设置后应用于当前和后续各轮，离线时先保存并等待设备上线。到达时限时，Baton 停止这一轮并记录原因，员工仍可以随时显式停止。

### 数据与界面

**R-15｜数据位置**

| 数据 | 保存位置 |
|---|---|
| 账号、设备、Thread 记录、每条消息与回复的有界正文、附件引用、Thread 状态变化 | 中心 |
| 每一轮的过程记录（每个步骤的有界内容）、所用模型与 token 用量 | 中心 |
| Project、主对话、输入队列、项目记忆、Project Agent 的运行记录 | 中心 |
| 完整回复、shell 原始输出与超出中心上限的步骤全文，以及 Agent 原生会话 | 设备 |
| 模型订阅凭据、设备上的密码 | 设备 |

网页按时间线分页读取中心保存的输入、回复、过程记录和事件，设备离线时仍可查看。中心的过程记录随 Thread 保留。shell 原始输出和被截断步骤的全文按权限从设备补读；设备离线、内容过期或本地数据已删除时显示具体原因，中心记录继续保留。原生会话历史由设备上的 Agent 管理。执行 Agent 不能读取 Project Agent 的主对话或项目记忆。

**R-16｜实时输出**

员工可以看 Thread 的实时输出和进行中的步骤。流断开时显示中断，重连后从设备补取；无法补齐时标出缺口。进行中的步骤只显示设备当前的最新状态，步骤结束后由过程记录中的同一步骤取代，同一步骤不会出现两次。中心只为传输使用有界缓存，不把流经的输出持久化。一台设备输出过多时，其他设备的消息、停止和状态确认不受影响；输出超限可以丢弃并标出缺口，控制消息不能丢失。

**R-17｜网页**

网页按设备和 Project 列出 Thread，显示状态、设备、目录、Agent 和最后活动时间。浏览期间列表在状态分组内保持顺序，本页面发送消息或新建 Thread 时将该 Thread 前移；状态变化仍使 Thread 进入对应分组，重新进入页面按最近活动排序。创建 Project 和修改 Project 设置时可以选择一个 emoji 作为项目图标，图标保存在中心并在网页的项目入口显示。Thread 列表上方是新建 Thread 的输入区：设备和目录分别选择，切换设备时预填该设备最近使用的目录，目录列表支持搜索；模型预填这个位置上次用的 Agent 和模型，执行权限列出该 Agent 支持的模式，输入第一条消息发出即新建。Thread 页面显示消息、回复、附件和实时输出，提供发消息、换模型、撤回排队消息、停止和归档。实时回复保留到对应持久回复出现；中心确认这一轮已结束且没有保存该回复时，显示中断提示。过程记录位于该轮回复之前，运行中默认展开，这一轮结束后自动收起；用户在运行中动过开关时保留其选择。工具步骤只显示标题，输入和结果默认收起，可逐条展开。后台刷新失败时保留已有内容并提供重试，权限失效或记录删除时显示对应状态。操作失败时显示原因，不以按钮点击成功代替设备上的操作成功。本期只针对桌面浏览器，不发推送通知。

**R-18｜附件与文件浏览**

附件引用包含所在设备或存储位置、路径或资源标识和访问状态，不能只是一条无法判断属于哪台设备的本地路径。代码提交作为附件时写仓库地址和完整 commit SHA，之后工作区的修改不影响它。

员工在网页上新建对话选位置时添加目录：选目录弹窗保留设备切换和已添加目录的目录树，找不到时直接输入设备路径，设备检查通过后添加并选中该目录作为新对话位置。设备本机也可添加目录。设备详情不默认列出目录，移除目录从详情里的「Folders…」次要入口进入。界面不向用户区分授权根目录和工作目录。远程设置要求设备属于本人、在线且已同步，并等待设备确认保存；同一路径重复添加返回已有目录。网页只浏览授权目录中的内容，分页读取完整授权目录清单和目录内容，读取不完整时保留已取得条目并提供重新读取。文本预览每片最多 64 KiB，可继续读取后文；文件变化时要求重新打开，避免拼接不同版本。符号链接和 Windows 目录联接解析后仍必须位于允许范围内。越界、未授权或设备离线时拒绝并说明原因。附件指向登记目录中的文件时，可以直接打开预览；设备离线时显示暂不可查看，不显示过期内容。

文件内容通过有界文本分片按需读取；二进制文件和完整日志不作为单条控制消息传输。

### 可靠性与安全

**R-19｜中心重启与不可用**

中心重启会断开设备连接。batond 自动重连并同步，同步完成前设备不显示为可用。设备上正在进行的一轮继续执行，未送达的回复和状态保存在设备本地，恢复后补报；同一条回复在中心只保存一份。中心无法保存时不接受新 Thread 和新消息。Project Agent 的每一步都要先保存到中心，中心不可用时它在本地期限到达前停止，已开的 Thread 不受影响。

**R-20｜batond 重启**

batond 重启后保留设备身份和本地历史，尝试确认原 Agent 是否仍在运行：仍在时继续跟踪，不能确认时标为状态未知。历史文件损坏或被删除时明确显示原因。

**R-21｜授权边界**

Baton 强制执行员工隔离、设备归属和 Thread 初始工作目录范围。执行模式直接采用上游 `RuntimeMode` 及 `DEFAULT_RUNTIME_MODE`，当前默认 Full access；各 Agent 的审批、沙箱、网络与自动审查按上游 adapter 的实际映射执行。模式在新建时确定，之后详情可查看，本期不提供修改入口。具体选项、接口和待审批请求行为见 [Agent 适配 R-11](../agent-adapters/PRODUCT.md#r-11本机权限与后台运行)。

Full access 可按设备用户权限访问工作目录之外的文件和网络；其他模式的审批能力与系统隔离分别呈现，Pi、Kiro 的审批模式不构成系统沙箱。文件浏览继续遵守 R-18 的目录边界。设备上的「允许 Project Agent 执行命令」只管 `nodes.exec`，不影响执行 Agent Thread；开关默认关闭，打开前说明命令以设备用户身份直接运行、可以访问目录之外的文件。

**R-22｜敏感数据**

设备密码和模型订阅凭据留在设备，不发给中心，也不放进消息。设备令牌、注册凭据不进入日志或遥测。中心不持久化实时输出和 Agent 原生会话。过程记录按原文保存，可能包含命令输出里的密钥；它只对 Thread 所属员工和该 Thread 所在 Project 的 Project Agent 可见，Project Agent 读取时不脱敏。中心启用 OTLP 遥测导出时，默认上报完整 Agent 活动（提示词、思考、回复与工具调用输入输出）供自托管观测平台分析 harness；未配置导出地址时不向外发送任何数据。

**R-23｜可追溯性**

设备、Thread、Project 和 Project Agent 的每次运行都有可关联的标识。Thread 由谁新建、每条消息由员工还是 Project Agent 发出、停止、归档、默认设备变更、凭据吊销都记录操作者和时间。中心提供在线设备、连接、收发量、队列占用和 Thread 状态分布等诊断信息，不附带完整会话内容或秘密。

内部首版的诊断与遥测须能关联中心和设备的发布版本、系统、Agent/provider/model、操作与运行标识，记录等待原因、错误码、重试、停止与恢复结果，并按 OpenTelemetry GenAI 语义约定默认记录完整 Agent 活动（系统指令、输入与输出消息、思考过程、工具名称及输入输出），单字段有界截断。长期记忆的整理积压、检索降级、token 用量与耗时按 [记忆规格](../project-memory/PRODUCT.md) 记录。模型未提供用量时标为未知。凭据、口令与网页未捕获异常的原始堆栈不进入遥测；发布后的观测与员工反馈用于持续迭代，遥测不可用时业务仍可运行。

一条消息从网页发出、在设备上执行，到回复回到中心，整个过程能作为一条记录查到；Project Agent 的一次运行也一样。遥测地址和凭据只在中心配置，设备和网页的遥测都经中心转发；安装包和网页里不带遥测地址，中心不配置时不会有数据发往外部。单台设备可以在本机另配地址直接导出，用于排查。网页出错时可以复制一份诊断信息交给开发者，里面有时间、版本、相关标识和错误码，不含正文。网页的操作回放默认关闭，部署者开启后也会遮住全部文字和输入。

**R-24｜容量**

按约 110 名员工、约 220 台设备规划。第一版之后的压测场景为：500 台在线设备、100 个同时执行的 Thread、每秒 100 个网页请求、每秒 200 条设备消息，持续 24 小时，并注入中心重启、设备掉线和数据库暂时不可用。R-16 与 R-24 的负载合格阈值在第一版之后确定；当前只记录实际观测结果。

**R-25｜协议扩展与发布兼容**

协议接收方忽略不认识的字段，消息携带协议版本，新增能力通过可选字段声明。首次内部发布前，实验数据可以按当前结构重建，不维护更早开发版本的兼容分支。

首个供员工保存真实工作的内部版本即为发布基线。从该版本起，后端与 daemon 升级保留已保存数据、设备身份、输入与执行证据，结构变化使用版本化增量迁移。协议与可选能力独立于产品版本判断，发布说明包含数据格式、失败恢复和验证范围。具体行为与验收见 [发布行为规格](../release/PRODUCT.md)。

## 验收

| 场景 | 条件与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| 三类 PC 接入 | 在 Windows、macOS、Linux 上注册与重连 | 设备身份稳定、能力准确，虚拟机可独立显示 | R-02、R-03、R-06 |
| 多轮 Thread | 在一台设备上新建 Codex Thread；Agent 执行中先插入一条消息，再排队一条消息 | 插入的消息在当前这一轮被读到；排队的消息在这一轮结束后开启下一轮；同一个原生会话；中心保存每条回复 | R-07～R-10 |
| 换模型 | 新建 Codex Thread 时指定模型，下一条消息换成另一个模型；对不支持换模型的 Agent 发同样的请求 | 两轮分别使用指定的模型，仍是同一个原生会话；不支持时在执行前返回原因，消息不发出 | R-06～R-08 |
| 排队可靠性 | Kiro 执行中排队两条消息，然后重启 Worker | 两条消息在这一轮结束后按顺序各发一次，没有丢失或重复 | R-08、R-13 |
| 离线等待 | 设备离线时新建 Thread 并发消息，之后设备上线 | 上线前显示等待设备；上线后开始，消息只被收到一次 | R-07、R-08 |
| 重复提交 | 用同一标识重复新建 Thread、重复发消息 | 只有一个 Thread，Agent 只收到一次消息；内容不同时返回冲突 | R-07、R-08 |
| 回执丢失 | 消息发出后断开连接，使 Baton 无法确认 Agent 是否收到 | 查询原会话；仍不能确认时标为状态未知，没有自动重发 | R-13 |
| 停止竞态 | 分别在一轮开始前、执行中、刚结束时停止 | 状态符合设备确认，界面不宣称已回滚 | R-11 |
| 恢复 | Agent 进程退出后发消息 | 支持恢复时继续原会话，Thread ID 不变；不支持时返回原因 | R-12 |
| 中心故障 | 执行中重启中心，短时停止数据库 | 设备重连，同步前不可用；这一轮继续，回复补报且不重复 | R-19 |
| 吊销竞争 | 吊销与认证、重连同时发生，随后重启中心 | 已吊销凭据不能继续操作；新连接不被旧连接的断开事件标为离线 | R-03、R-04 |
| 输出洪泛 | 设备 A 持续大量输出，设备 B 同时收消息和停止；浏览器慢读 | B 的操作持续得到处理，缓冲有界，输出缺口可见 | R-16 |
| 数据位置 | 一轮结束后让设备离线 | 中心仍能显示输入、回复、过程记录和附件引用；设备保存的完整输出显示暂不可取回 | R-15 |
| 过程记录 | Codex、Cursor、Pi、Kiro 和 shell 各跑一轮，其中有命令、文件修改和工具调用，一条命令输出超过 192 KiB；执行中途让设备断线再重连 | 每一轮的步骤按顺序完整出现，没有重复，都排在这一轮结束之前；超长输出标明截断和原始大小；结束记录带模型和 token 用量 | R-09、R-15 |
| 附件 | 回复带一个日志文件和一个 commit；之后设备离线 | 设备在线时可预览日志；离线时显示暂不可查看；commit 始终显示仓库和 SHA | R-18 |
| 越权与越界 | 请求其他员工的 Thread；访问登记目录外的文件 | 都被拒绝，没有返回内容 | R-01、R-18 |
| 协议扩展 | 当前消息带接收方不认识的可选字段；缺省未声明的可选能力 | 已知字段与核心行为保持正确；未知能力不启用 | R-25 |
| 凭据闲置过期 | 注册后仅心跳、重连、探测、轮询与后台整理；分别在 30 天前后尝试业务 | 到期前可用，到期后需要重新认证；连接关闭，业务不派发；旧执行中状态不延长期限 | R-02 |
