# Agent 适配与扩展行为规格

Status: draft
Owner: 待指定
Basis: 已确认的 Agent 接入范围、t3code 复用讨论及规格审查；Baton `c064efa`；配套 [技术设计](TECH.md)。本文描述拟议行为，批准并实施后同步主规格。

## 概述与范围

员工和 Project Agent 通过现有 Thread 功能使用 Pi、Codex、Kiro、Cursor、Grok 和 Antigravity。适配器沿用各 Agent 的原生会话、认证和模型，提供新建、排队、停止、恢复及历史读取；插入和换模型按实际能力提供。

| Agent | 本期工作 |
|---|---|
| Pi、Codex | 参考 t3code 核查并补强输入、停止和恢复边界，保持现有会话归属 |
| Kiro | 在复用 ACP 基础实现时保持现有功能与原生会话恢复 |
| Cursor | 新增接入，运行依赖随设备安装包分发 |
| Grok、Antigravity | 新增接入，使用设备上已经安装、配置并完成认证的原生程序 |

Claude、OpenCode、Muse、通用 ACP Agent 目录接入均不在本期。既有 shell Thread 继续用于 Project Agent 命令执行。原生 fork、rollback、计划卡片、独立子 Agent 界面、自动续跑、多账号选择，以及 Agent 安装更新和登录托管均不在本期。

本文补充 [Baton 行为规格](../baton/PRODUCT.md) R-06 至 R-16、R-25 和 D1。Thread 状态、员工隔离、设备目录限制、归档和附件约定继续适用。本期同时统一六种 Agent 的设备端历史消息格式，补齐不可用原因到网页和 Project Agent 的传递，并将设备接收命令与 Agent 启动、输入准备及发送分开确认。

## 行为

### R-01｜接入与可用性

设备分别报告六种 Agent 的版本、模型、可用状态、操作能力及诊断原因。网页与 Project Agent 读取中心保存的同一份设备报告；原因在节点上报、中心保存和查询中保留，缺少程序、运行依赖、认证或配置时显示具体缺项。只有状态为可用且明确支持新建的 Agent 才能选择创建，未验证也属于不可创建状态。

版本未知、协议不满足要求，或该系统组合尚未通过交付验证时，报告为未验证。诊断原因变化后，消费端能读取到更新后的原因。原因只包含有限长度的脱敏摘要，不携带凭据或原始诊断输出。创建前再次检查执行条件；检查失败时返回原因，不切换 Agent、账号或设备。新接入 Agent 的交付验证必须覆盖发送、停止、原生历史核查及恢复，单次对话成功不能代替这些验证。

### R-02｜探测与准备

后台版本和可用性检查不发送模型推理请求，不打开登录浏览器，不执行项目或用户级 hooks、扩展，也不启动 MCP 服务。能够静态查询的直接查询；必须建立会话才能读取认证或模型元数据的，允许使用已验证无上述副作用的隔离探测会话。探测只访问所选认证上下文和临时工作目录，不连接员工正在执行的会话，也不发送 prompt。

没有安全静态查询或隔离探测方式时，报告未验证并说明缺项。认证状态未知时拒绝创建，正常创建不能作为跳过探测的入口。认证与模型目录分别判断：缓存目录或公开模型列表不能证明账号有效；认证已确认但模型目录读取失败时，允许使用原生默认模型，并显示目录缺失原因。

员工修复本机安装、认证或配置后，重启 batond 会重新探测。探测建立的进程、会话临时数据和后台任务有明确期限并被回收；探测失败不影响既有 Thread 的执行。

Cursor 缺少随设备分发的运行依赖时显示安装不完整；设备使用时不临时联网安装依赖。Grok、Antigravity 缺少原生运行环境时提供本机配置指引。

### R-03｜认证与会话归属

每台设备上的每种 Agent 使用一份本机认证上下文。本期不提供网页多账号切换。Thread 记录所用 Agent、原生会话和认证配置位置的关联；恢复只能使用这份关联。

执行 Agent 的凭据与 Project Agent 模型订阅分别管理。`batond login openai-codex|xai` 的成功不代表 Codex 或 Grok Thread 已可用。凭据不进入中心、消息正文、原生历史的展示内容或诊断日志。

认证失效、配置位置变化或账号不能访问原会话时，停止创建或恢复并说明原因，不能新建空会话来冒充恢复。

### R-04｜新建与恢复

设备持久接收新建或恢复命令后及时返回接收确认，原生 Agent 的慢启动异步完成。已接收命令不表示 Agent 已就绪；只有完成原生会话建立和归属保存后，才显示 Thread 已打开或恢复成功。恢复进行中的状态保持到实际成功、失败或取消，接收确认不会清除它；期间重复恢复请求复用同一操作。启动失败通过后续状态报告显示原因，接收确认丢失后用同一命令标识重试，不重复创建或恢复。

首次启动完成前收到停止时，取消该次打开并清理迟到创建的运行实例，不再报告打开成功；若打开成功已确认，则按已打开会话停止。最终结果在进程重启后保持一致，不能重新执行已经取消的打开。

首次创建 Thread 时，原生会话归属必须先保存，再发送第一条消息。恢复时核对原生会话与工作目录，Thread ID 保持不变，历史中的工具调用不再次执行。

原生会话或本地映射缺失、历史不匹配时，返回历史缺失或不可用原因。网页仍能查看中心已经保存的回复；员工可以自行新建 Thread。

### R-05｜输入与重复确认

设备将消息持久保存到队列后返回接收确认，不等待原生历史查询或 Agent 接收。排队由 Baton 保存；Agent 结束当前一轮后才发送下一条。只有取得原生接收证据后才显示已发送，本地队列已保存与原生已接收分别表示。

发送前的历史基准一次采集，并绑定到该输入的持久发送意图；发送不重新选择比较起点。Agent 启动、历史准备和提交期间，停止请求及状态查询仍能被处理。

消息发送过程中断线、超时或进程退出后，先核查原生历史。能确认输入存在时继续记录已发送；不能确认时显示状态未知。同一个客户端消息标识不自动再次提交给 Agent。原生 SDK 的重试也必须满足这项约定。

### R-06｜插入

插入只加入当前这一轮，不改变模型。Pi 和 Codex 保留原生插入能力；Kiro、Cursor、Grok、Antigravity 本期按不支持插入交付，执行中只提供排队。需要改变方向时，员工先停止当前一轮再发送新消息。

插入与回合结束同时发生时，必须核对原生接收结果；不能把它悄悄改成下一轮输入，也不能通过“中断后重开一轮”表示插入成功。无法确认归属的输入显示状态未知。

### R-07｜模型

模型列表和标识来自实际 Agent。未指定模型时使用该认证上下文的默认模型；界面里的“默认”不能作为虚构模型标识发送。

开启新一轮前才允许切换模型。模型不支持、配置未就绪或切换被拒绝时，若能确认消息尚未提交，就撤回该条消息并显示原因，继续处理后续排队消息；不能确认是否已提交时按 R-05 处理。没有实际切换能力时隐藏换模型操作，整个 Thread 使用创建时的模型。

### R-08｜停止

停止覆盖当前一轮及其在本机启动、由该会话拥有的工具和后台任务，并撤回尚未发送的排队消息。取消请求的响应只表示请求已处理；只有原生终止状态或进程树回收证据才能表示已停止。

发送后立即停止、长工具运行中停止和子任务运行中停止都必须生效。原生取消未在一分钟内完成时，结束该 Thread 的 Agent 进程树；不能误杀其他 Thread。无法确认回收结果时显示状态未知。停止不撤销已经发生的文件修改或其他动作。

### R-09｜回复与回合归属

只把当前 Thread、本轮执行的回复写入其时间线，按接收顺序保存。子任务的结束不能提前结束父回合，恢复过程重放的旧消息不能当作新回复再次上报。

一轮结束前保存已经收到的回复。当前一轮有可观察的后台执行尚未结束时，不显示空闲；可用性验证必须确认后台工作能被归属和停止。迟到的旧回合事件不能混入下一轮。本期不启用会在没有 Baton 输入时自动启动新一轮的原生功能。

### R-10｜历史与实时输出

六种 Agent 提供同一格式的 user / assistant 消息历史和实时输出入口。原生消息解析、当前分支选择及流式分块合并由设备完成，再按逻辑消息分页。浏览器不解释各 Agent 的原始协议；同一条回复拆成大量 token 分块，也只算一条消息。

历史消息具有稳定标识和顺序。缺少原生时间戳时保留消息并显示时间未知，不伪造时间，也不因此丢弃正文。与中心保存记录的匹配不依赖两端时钟或时间戳齐全；匹配不唯一、正文截断或消息边界无法确定时显示缺口，不静默隐藏可能重复的内容。

历史读取不依赖执行进程存活，不发送 prompt，不改变执行中会话的状态。一次历史读取的后续翻页复用有界的只读快照或原生分页状态，不逐页重启 Agent 重放全量历史；快照构建期间可显示读取中。快照是捕获时的一致视图，后续追加在刷新后读取。快照过期、已知会话分支切换或已读内容改写时明确要求重新读取，不拼接不同版本的历史；缺少变更检测能力时明确保留快照有效期限制。

正文、容量和分页预算沿用主规格 R-15、R-16。本机历史不可读取时返回明确原因，不用中心保存的回复代替完整原生历史。实时输出发生截断或丢失时标记缺口。工具过程留在设备上。

### R-11｜本机权限与后台运行

沿用各原生 Agent 的权限和执行边界，不新增逐条审批界面。具体启动策略见技术设计；每种 Agent 必须能在无交互终端的 Worker 中结束权限请求，不能无限等待本机确认窗口。

自动权限响应只适用于当前 Thread 正在执行的一次请求，不写入项目或账号的永久授权。停止后和历史读取过程中的权限请求一律取消。原生权限或隔离要求不能满足时，显示不支持的原因，不自动切换成更宽权限继续执行。

### R-12｜交付与升级

按操作系统公布已验证的 Agent、版本和能力组合。既有 Pi、Codex、Kiro 的最低版本策略继续适用；新增 Agent 的最低版本以实际录制与验证结果确定，未确定前不声明可用。

设备安装包、Node 运行依赖和原生 Agent 程序分别报告缺项。更新后使用当前安装版本重新检查；历史映射不匹配时明确失败。实验室阶段沿用主规格 R-25，不维护旧开发版本的数据读取分支。

## 验收

| 编号 | 场景 | 可观察结果 | 验证状态 |
|---|---|---|---|
| A-01 | 缺少程序、依赖或认证；版本未知或协议不兼容 | 不可用或未验证，显示具体原因，创建前拒绝 | planned |
| A-02 | 静态查询与隔离会话探测，环境带全局 hooks、扩展、MCP 和登录缺项 | 无项目或用户级动作、无推理或交互登录，探测结束后清理进程和临时会话数据 | planned |
| A-03 | 六种 Agent 分别新建并完成两轮对话 | 同一原生会话、回复和模型正确，排队顺序正确 | planned |
| A-04 | 已接收输入但确认丢失；发送中断并重启 Worker | 查历史确认或显示未知，相同输入不重发 | planned |
| A-05 | 发送后立即停止、工具及子任务运行中停止 | 等待真实停止证据，必要时回收整棵进程树，不影响另一 Thread | planned |
| A-06 | Pi、Codex 插入与回合结束竞态；向其余 Agent 插入 | 前者归属明确或未知，后者执行前拒绝，无隐含新一轮 | planned |
| A-07 | 默认模型、有效模型、被拒绝模型及模型切换失败 | 默认可用；失败未提交时撤回，否则未知；原模型和队列符合 R-07 | planned |
| A-08 | batond、Worker、Cursor 运行依赖或原生进程退出后恢复 | 归属不变，无历史工具重执行；缺失历史明确失败 | planned |
| A-09 | 子任务晚结束、旧事件迟到、历史加载重放 | 不提前结束父回合，不串入下一轮，不重复新增回复 | planned |
| A-10 | Worker 已退出后翻页；历史重排、截断或超大内容 | 原生分页有效，变化和缺口明确，不执行项目动作 | planned |
| A-11 | 两个 Thread 并行，其中一个停止或认证失败 | 各自原生会话、输入、回复和进程互不混用 | planned |
| A-12 | 从真实安装包运行，移走 Cursor 运行依赖或切换账号配置 | 缺项、权限或归属错误可见，无临时下载或替代账号 | planned |
| A-13 | 原因跨节点上报、中心保存、网页和 devices.list；只修改原因；状态为 unverified 或 create=false | 原因一致且能更新，不可创建的 Agent 在两类消费端均不可选，中心仍拒绝执行 | planned |
| A-14 | 六种 Agent 的统一历史；ACP 长回复拆成上万分块、同角色多条消息、缺少时间戳 | 消息合并与边界正确，分页按消息计数，缺失时间仍可显示，不调用前端原生解析 | planned |
| A-15 | 连续翻页、并发读取、快照过期及历史分支变化 | 同次读取不逐页重放，快照有界且归属正确，失效要求重读 | planned |
| A-16 | 原生冷启动超过 3 秒、发送准备超过 5 秒，期间发停止和查询 | 命令落盘后及时确认，无假性打开或已发送，停止和查询不被慢执行阻塞 | planned |
| A-17 | 输入准备后停止、准备过程中重启、准备后历史前缀变化 | 一次准备对应一个输入，发送不重复读取或换基准，无证据时未知且不重发 | planned |
| A-18 | 模型目录可读但认证未知；认证有效但目录失败 | 前者拒绝创建；后者允许默认模型并保留目录诊断 | planned |
| A-19 | 恢复已接收但未完成时再次请求；完成结果早于接收确认；其后重启 | 持续显示恢复中，只执行一次，迟到接收确认不覆盖结果 | planned |
| A-20 | 首次启动成功与停止竞态，返回迟到运行实例，再重启 | 成功先确认则先打开再停止；停止先接收则打开取消、资源回收且不补报成功 | planned |

## 待确认与验证事项

| 项目 | 缺少的证据 | 阻塞范围 |
|---|---|---|
| Cursor 认证 | 初期是否接受员工显式配置原生 API key；本机 CLI 订阅登录能否通过 SDK 公开接口复用尚未验证 | Cursor 认证入口需在实施前确认，不能自动换到另一计费账号 |
| Cursor 运行与历史 | 官方 SDK 的跨进程恢复与只读历史行为，以及各系统的运行要求 | Cursor 标为可用与确定最低版本 |
| Grok | 原生历史能否在独立读取连接中保留输入身份，以及取消后后台任务的状态与清理证据 | Grok 标为可用与确定最低版本 |
| Antigravity | 可供用户独立准备的 ACP 程序和认证流程、恢复及历史读取行为 | Antigravity 的交付入口与可用声明 |
| 新增 Agent 的系统矩阵 | Windows、macOS、Linux 上的原生程序和进程树回收验证 | 相应系统组合的交付声明 |

这些事项在各 Agent 实施验证时记录结果，不能用其他 Agent、其他系统或 t3code 的运行结果代替。
