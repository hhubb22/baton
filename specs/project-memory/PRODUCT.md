# Project 长期记忆行为规格

Status: partially implemented
Owner: Asa
Basis: [Project Agent 行为规格](../project-agent/PRODUCT.md)、[技术设计与资料依据](TECH.md)。

## Summary

Project Agent 从已完成的工作中自动保留有依据的知识，吸收用户纠正，并在后续任务中主动找回相关内容。默认检索在本地完成，不要求 embedding API、额外模型或独立搜索服务。

手动维护、员工 API 与前台记忆工具已实现条目修订、来源证据、事实时间、纠正/替代、停用恢复、操作去重与隔离。Memory 页面支持编辑、按需来源与历史、冲突草稿和「不再使用」分组。自动召回、词法索引、请求快照与后台整理仍为 planned。员工隔离、执行授权、原始历史持久化和 Thread 生命周期继续遵循 Baton 与 Project Agent 的既有规格。

## 范围与概念

一个 Project Agent 拥有一个 Project 范围的记忆空间。运行进程、设备和模型变化不改变记忆归属。本期不增加用户全局记忆、Project 之间自动共享、执行 Agent 直接读取项目记忆、模型训练或自动生成可执行 Skill。

| 概念 | 用户可理解的含义 |
| --- | --- |
| 原始经历 | 已保存的用户消息、执行反馈与操作记录，可作为核验依据 |
| 记忆条目 | 关于偏好、事实、决定或经验的一项可独立修正的知识，包含适用条件与来源 |
| 主题 | 测试、部署、架构决定等知识分组，内容来自其下的有效记忆 |
| 核心记忆 | 每轮都需要遵守的少量稳定要求，保留重要否定、例外与条件 |
| 后台整理 | 从新增经历提取候选知识，去重、纠错和更新主题的过程 |
| 停用 | 停止将一条知识作为有效记忆使用；原始对话和变更历史仍保留 |

本期提供停用和显式恢复，不提供彻底删除原始对话及全部派生副本的功能。界面和工具必须使用与保留范围相符的表述。

## Behavior

### 形成与来源

- PM-01：用户访问、搜索或修改记忆时，只能作用于自己的指定 Project。用户可以查看主题、当前条目、来源与变更历史；任何记忆内容都不能授予设备目录、命令执行或额外工具权限。
- PM-02：一批输入得到最终回复后，系统自动登记对该批新增经历的整理工作。整理尚未完成、没有可运行设备或模型暂时不可用时，原始内容保持保存，前台对话可以继续。失败和等待原因记入诊断，不把未整理表现成没有值得保存的信息。
- PM-03：用户直接编辑条目或明确要求记住时，可以立即保存相应知识。用户在对话中纠正旧认识后，Agent 应优先处理纠正，再决定相关后续操作；有歧义时只采用已明确的范围。“这次用 Python”不能自动变成“所有工作都用 Python”。
- PM-04：自动形成的记忆必须能够追到支持其结论的原始内容，区分用户明确表达、执行观察与 Agent 推断。用户引用的文章、第三方指令和执行 Agent 的猜测不能仅凭出现在对话里就变成用户要求。没有独立执行证据时，“Agent 报告测试通过”不能写成已核验的通过事实。
- PM-05：同一知识重复出现时，合并条目并保留独立证据。召回次数、对旧回答的复述和压缩摘要不增加可信程度。重复投递、进程恢复和后台重试不能重复产生相同修改。决定保留理由，经验保留适用条件和验证结果。

### 更新与停用

- PM-06：新信息到达时，系统区分事实变化、旧记忆错误和适用范围不同。事实变化保留过去的有效区间；原来记错则撤回错误断言；不同条件可以并存。无法判定的实质矛盾显示争议与来源，不把任一方当作确定结论。
- PM-07：用户与后台同时修改同一条目时，不静默覆盖。保存冲突返回当前内容，用户草稿继续保留；后台依据新内容重新整理。一次直接修改或明确纠正即可生效，不要求用户重复表达来提高记忆权重。
- PM-08：用户停用一条记忆后，后续自动上下文、主题和普通搜索不再将它作为有效知识提供。后台重试、重建和旧来源再次被处理时，不能恢复该条记忆。原始历史仍可显式读取；历史结果标明该条知识已停用。恢复使用须由用户明确发起。
- PM-09：稳定偏好、明确约束和过去发生的决定不会仅因时间流逝而被自动删除。临时环境观察可降低检索优先级；实际操作前核对当前设备和执行状态。保存顺序与事实的有效时间分别呈现；无法确定发生时间时保留未知或范围。

### 召回与执行

- PM-10：每批主动输入开始处理前，自动提供适用的核心记忆和与当前任务相关的有效知识。无需用户提醒检索，也不依赖是否已经发生过对话压缩。输入“继续上次那个”时，结合最近目标与相关对象查找，不能只搜索这几个字。
- PM-11：默认检索支持中文、英文、技术标识符、实体别名与部分措辞变化，按相关性返回片段和来源。检索本身不要求模型或外部 API；后台生成检索辅助词、Agent 按需改写查询仍计入模型使用成本。条目停用、撤回或替代已经生效后，即使索引尚未刷新也不能作为当前知识返回。
- PM-12：查询当前事实时使用当前有效结论；查询过去时使用所问时间的有效区间。精确 ID、路径和命令按原文保留。关键词未命中时，Agent 可以改写查询、读取相邻原文或沿主题继续查；不足以支持答案时说明缺少什么，不能把没有搜到解释为从未发生。
- PM-13：用户重要要求进入核心记忆后，保留否定、例外和适用条件，在后续请求及压缩后重新提供。容量不足时显示原因并保留已保存内容，不静默裁剪这些要求。推断出的偏好不能覆盖用户明确要求。
- PM-14：任务是否完成、Thread 是否仍在执行、事项是否处理以及设备是否可用，以当前业务记录为准。记忆和摘要里的状态只代表过去的观察。有关任务的回复要区分已确认结果、对方报告与尚未核验的判断。
- PM-15：压缩和恢复保持来源、当前有效性与重要要求。用户纠正或停用后，旧检索快照、工具结果、主题或摘要不能被重新包装成当前有效记忆。在已知记忆更新与工具执行竞争时，尚未提交的相关操作先刷新依据；已持久提交的操作继续查询原结果，不因刷新记忆重复执行。

### 可见性与运行控制

- PM-16：Memory 标签只列当前有效条目的正文，条目多时按主题分组；列表不显示版本、来源、时间和类型标签。用户可以新建、编辑和停用条目，编辑时不区分纠正还是事实变化。来源对话和修改历史在条目里按需打开。停用的条目收进列表末尾的「不再使用」分组，可以显式恢复。主题只显示底层有效内容，不另存一份可与条目冲突的人工正文。提取、整理、有效期和修订由系统处理，不需要用户参与。
- PM-17：后台整理的等待、处理中、已处理和失败状态，以及处理到哪批经历和原因，只记入内部诊断，主对话不插整理提示。界面只在保存失败、编辑冲突和需要用户处理的持续故障（例如需要登录）时提示。没有设备或需要登录时保留工作；登录恢复后继续。后台模型请求和失败不计入前台对话的失败次数，不为每次暂时失败创建 Inbox 事项。
- PM-18：Project 暂停后停止自动整理，未完成工作保留，用户仍可手动维护记忆；恢复后继续。归档后记忆只读，后台提交被拒绝。停止一次前台运行不撤回已完成轮次登记的整理工作。后台工作不创建、发送或执行 Thread，不处理 Inbox，不执行本机命令。
- PM-19：前台有工作时优先获得设备与模型容量。后台不能耗尽前台运行名额；必要时中断后台模型请求，已保存的整理进度保留。搜索或整理降级时显示实际状态，不能把失败结果或半条结论写成有效记忆。
- PM-20：记忆效果分别评估形成、找回和实际使用。必须检查用户纠正后的下一次行为、失效知识误用、来源支持程度及额外成本。固定离线用例验证流程；真实模型的语言理解与提取效果通过单独、显式的质量评估验证，不能用替身结果宣称真实模型已达到某个准确率。

## 验收

| 编号 | 场景 | 必须观察到的结果 | 关联需求 |
| --- | --- | --- | --- |
| PM-A01 | 保存最终回复后立刻结束进程，再恢复；重复投递同一批工作 | 原始经历和整理工作均在；相同提取与修改只生效一次 | PM-02、05 |
| PM-A02 | 用户只说一次正确测试入口；整理后更换 Runtime，开始另一项需测试的工作 | 自动提供该约定；质量评估观察 Agent 实际选择正确入口 | PM-03、10、20 |
| PM-A03 | 同一项目先后两次迁移技术，另登记一项未来生效的变化；分别查询当前和过去状态 | 回答对应时间的结论与依据；未来变化在生效前不移除现行值，生效后切换 | PM-06、09、12 |
| PM-A04 | 用户说明旧记忆从一开始就错了，随后重放积压的旧来源；另一场景只给本次任务一个例外 | 错误断言撤回，旧证据不能以新 ID 恢复它；临时例外保留原有通用范围 | PM-03、06 |
| PM-A05 | 后台读取旧值后，用户先保存新内容；后台随后提交 | 用户修改保留；后台冲突并重新整理；用户草稿不丢失 | PM-07 |
| PM-A06 | 停用后普通编辑、重放工作、重建索引/主题、恢复旧运行；再尝试显式恢复 | 普通编辑保持停用；旧来源不复活；历史标明停用；互斥现行后继存在时恢复返回冲突，不能暗中覆盖 | PM-08、15 |
| PM-A07 | 多次召回同一事实，再把召回内容及摘要交给整理 | 不增加独立证据，不因重复回流产生条目或可信度提升 | PM-04、05 |
| PM-A08 | 对话中出现外部文章的命令、用户对文章的引用和执行 Agent 的未验证总结 | 保存正确的来源身份；外部内容不晋升为用户要求，不获得执行权限 | PM-01、04 |
| PM-A09 | 使用中文同义表达、中英混合、camelCase/snake_case 查询；同时含相关已失效条目 | 找到可核查的有效候选；无外部检索调用；对未命中与截断如实标识 | PM-11、12 |
| PM-A10 | 重要要求含否定和条件，另有未来生效的要求；多次压缩后继续，并尝试超额加入核心内容 | 要求完整提供；新要求生效时刷新上下文；超额操作返回原因，不静默丢失已保存要求 | PM-13、15 |
| PM-A11 | 旧摘要说 Thread 已完成，当前记录显示失败或仍在执行 | 使用真实状态；将摘要标作历史观察 | PM-14 |
| PM-A12 | 请求中途更新记忆；另在 nodes.exec 已创建 Thread、尚无工具结果时更新并恢复 | 未提交调用刷新后再决定；已有 pending 执行继续原等待，无第二个 Thread 或重复命令 | PM-15 |
| PM-A13 | 后台等待模型时前台新输入到达，分别使用 1、2 个运行名额；再暂停、恢复和归档 | 后台阻挡前台时均被抢占；回收前不虚报名额；暂停保留工作、恢复继续、归档拒绝迟到提交 | PM-18、19 |
| PM-A14 | 所有设备离线、认证需要登录、后台模型失败，随后恢复条件 | 前台对话不受后台状态影响；工作保留；原因记入诊断，只有需要登录时提示一次，无重复 Inbox 提示 | PM-02、17、19 |
| PM-A15 | 其他员工或其他 Project 查询条目、来源、主题和工作状态 | 返回不可访问，不泄露对象内容或驱动其他设备 | PM-01 |
| PM-A16 | 无法回答的问题、仅部分相关证据、错误证据和正确证据混合 | 质量评估检查继续查询或说明缺口；记录无依据断言和过时知识误用 | PM-12、20 |
| PM-A17 | 用户查看一条记忆，打开来源与历史，编辑后停用并显式恢复 | 列表只显示当前正文；来源、条件与时间可按需追溯；停用条目进入「不再使用」并可恢复；修订不进入普通列表 | PM-16 |

自动化使用本地模型替身、固定录制和人工定义的正确事实，验证持久性、隔离、排序与恢复。PM-A02、09、16 中真实模型是否正确理解和使用知识，单独记录质量评估结果。未完成的验收均为 planned。
