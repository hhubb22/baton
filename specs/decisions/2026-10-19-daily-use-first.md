# 先做出能完整运行的第一个版本：2026-10-19 评审结论

Status: accepted（2026-10-19）
Date: 2026-10-19
Related: [Baton 行为规格](../baton/PRODUCT.md)、[Project Agent 行为规格](../project-agent/PRODUCT.md)、[Agent Inbox 行为规格](../agent-inbox/PRODUCT.md)

## 背景

2026-10-19 收到一份外部产品与架构评审，基线 `hhubb22/baton@a26cb31`。评审从十五位作者的公开观点出发，提出八项方向和对现有规格的七处修订。用户逐条讨论后，只保留收益明确大于成本的部分，并按 Mitchell Hashimoto 和 Linus Torvalds 的观点补充了几项决定。

当时的状态：项目从 2026-10-17 开始，`main` 上约 3.9 万行非测试代码、130 个需求编号、30 个迁移文件，还没有一条能完整运行的使用流程。Web 只有「节点 / Session / 任务」三个页面，Project Agent 和 Inbox 还没有界面。Agent Inbox 规格 2026-10-18 批准，尚未实现。

## 决定

1. **第一个版本之前不提前优化，不做超出当前需要的工程。** 判断一项工作要不要现在做，看第一个里程碑缺了它能不能走通。性能、容量、通用扩展点、多版本兼容的完整机制和更多 Agent 适配，等第一个版本跑起来、遇到具体问题再做。例外是改起来便宜、拖到以后会弄坏已有数据的事，例如消息字段的含义。
2. **第一个里程碑是一件真实工作走通全程。** 用户从 Project 发起一件自己会反复做的跨设备工作；Project Agent 派到另一台设备，结果带证据回来；需要判断时进入 Inbox，用户隔一段时间回来处理。过程中至少经历一次 Project Runtime 换实例，以及执行设备在交付结果后离线。里程碑同时包含上下文压缩（PA-15、PA-16）、Project Agent 执行命令（PA-22），以及里程碑实际用到的设备上的安装验收：持续使用时，这三项缺一项就要绕开 Baton 手动处理（2026-10-20 修订）。验收使用真实订阅，替身测试不能代替。PA-W08（PS-160）承担这项验收。
3. **里程碑完成前少加计划。** 新的计划类需求只在真实使用遇到问题时加入。规格按契约和计划分类、逐条标注，留到第一个版本之后。
4. **删除浏览器推送通知。** Agent Inbox 由用户自己来看，Baton 不主动打断用户。IB-28～IB-32、IB-A14、IB-A15 删除，PS-168 取消。
5. **Baton 在两种确定的条件下创建事项。** Project Agent 达到重试上限、Project 的任务进入待核实时，由 Baton 直接创建事项，不依赖模型调用 `inbox.ask`（Agent Inbox IB-33～IB-35）。
6. **引用固定到结果版本。** 事项和对话里的任务结果引用指向创建时的结果版本；代码变更以 commit SHA 作为产物。中心暂不保存产物文件，执行节点离线时文件预览仍显示暂不可查看。
7. **用户可以绕过 Project Agent 直接控制任务。** 用户在 Project 里可以自己派发任务、处理 Project Agent 派出的任务、暂停 Project 后自己操作（Project Agent PA-23～PA-25）。Project Agent 的自主协调能力保留。
8. **每个任务写明怎样验证完成。** Project Agent 派发任务时在 `expected_outputs` 里写明验证方式；用户派发时可以填写。这条靠系统提示词约束，Baton 不检查内容。
9. **消息只做增量变化。** Coordinator、batond 和 Project Runtime 之间新增字段不改旧字段含义，接收方忽略不认识的字段（Baton R-41）。版本上报和拒绝旧版本留到第一个版本之后。
10. **核心数据结构画在一页上。** Baton TECH 增加一节，列出核心表和它们的关系；以后增加对象时先更新这一节。
11. **手机不适配。** 等产品成型后再考虑。

## 第一个版本之前暂缓的工作

按决定 1，以下已批准的工作推迟到第一个版本之后，规格中对应条目标注「推迟到第一个版本之后」：

| 工作 | 规格条目 | 工单 | 第一个版本的做法 |
|---|---|---|---|
| OpenUI 展示内容与组件库 | IB-14～IB-19 的 OpenUI 部分 | PS-165 | 展示内容用 Markdown |
| 浏览器实时通道 | IB-08 的实现方式 | PS-166 | 页面定时查询 |
| Cursor 适配 | — | PS-121 | 使用 Codex、Pi、Kiro |
| 凭据轮换、保留与空间不足 | — | PS-133 | 不处理 |
| 容量基线、长稳与交付审查 | R-39 | PS-138～PS-141 | 不做 |
| 各平台安装与网络验收 | — | PS-134～PS-137 | 里程碑用到的设备在 PS-160 里验收，其余推迟 |

## 没有采纳的建议

- **明确操作由后端直接执行。** 任务详情页已经提供取消、人工核实和重新执行，在 Inbox 里重复一套收益小。Plane 审批门槛需要时再单独设计。
- **执行 Agent 中途提问提前到第二个里程碑。** 先从真实录制里统计权限请求和提问的频率，再排优先级。
- **中心保存正式成果和证据。** 等第一个里程碑真的因为执行设备离线受阻，再设计存储位置和大小上限。
- **全局导航改版。** Project 和 Inbox 界面按原计划实现，节点和 Session 页面保留。
- **用对比实验决定 Project Agent 的自主程度。** 用户认为 Project Agent 有价值，改为同时提供用户直接控制的界面（决定 7）。
- **主规格去掉员工、北京、PC 与 Ubuntu 的说法。** 方向认可，全文改写留到第一个版本之后，避免现在的文字和代码频繁变动。
