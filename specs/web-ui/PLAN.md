# Web UI 实施计划

## 目标与范围

Web UI 默认通过 HTTP 客户端连接 Coordinator，覆盖登录、设备、Thread、项目协同、文件与引用、Inbox 和项目维护。模拟客户端用于开发场景和确定性测试，在开发服务器中通过显式的 `?mock=1` 或 `?scenario=<id>` 启用。流程顺序为：公共框架 → 登录导航 → 设备 → Thread → 项目协同 → 查看与引用 → 事项处理 → 项目维护。

范围包含桌面浏览器的英文界面、浅色与深色主题、真实后端接入，以及 Coordinator 嵌入式页面的部署验收。模拟场景可在未启动 Coordinator、batond 和真实 Agent 时开发交互；真实链路与部署验收使用实际服务、设备和 Agent。手机和窄屏布局、浏览器推送不在本计划范围内。

本文件用于安排实现和验收。产品行为以以下规格为准，页面与组件按设计稿实现：

- [Baton 行为规格](../baton/PRODUCT.md)
- [Project Agent 行为规格](../project-agent/PRODUCT.md)
- [Agent Inbox 行为规格](../agent-inbox/PRODUCT.md)
- [界面文案规范](../../web/WRITING.md)

发现设计与规格冲突时，先确认对应行为，再实现。设计中已有入口但缺少完整交互的部分，归入对应流程补足。

## 实施顺序与范围归属

| 顺序 | 流程 | 负责范围 |
|---|---|---|
| 0 | 公共框架 | 视觉基础、共享组件、导航基础、数据接口、HTTP 与模拟客户端、场景切换 |
| 1 | 登录并进入工作区 | 会话恢复、登录、首次改密、侧栏导航、账号入口与退出 |
| 2 | 连接并管理设备 | 接入指引、设备能力、默认设备、命令权限、断开设备 |
| 3 | 直接使用一个 Thread | 新建、列表、详情容器、消息操作、停止、恢复、归档 |
| 4 | 创建项目并交给项目助手推进 | 创建项目、主对话、概览、项目内打开 Thread、助手运行状态 |
| 5 | 查看执行过程、附件与文件 | 历史和实时输出详情、文件浏览预览、内容引用 |
| 6 | 处理需要用户决定的事项 | Inbox、事项卡片、回答与关闭、系统事项、各处状态同步 |
| 7 | 维护、暂停与归档项目 | 项目设置、记忆编辑、暂停恢复、归档与记录查看 |

各流程复用同一套组件和业务对象。Thread 的消息操作由流程 3 实现，流程 4 在项目内复用；过程与文件细节由流程 5 完成；事项的处理行为由流程 6 统一实现。每条流程同时核对 HTTP 契约与页面反馈，模拟场景用于覆盖可重复的状态与异常。

## 0. 公共框架

- 从设计复用语义颜色、字体、间距、图标和主题，建立按钮、字段、菜单、弹窗、卡片、输入区、横幅与状态标签。
- 建立工作区布局、页面导航与弹层行为。浮层层级、主按钮数量和颜色用途遵循设计规则。
- 提供统一的 `BatonClient` 数据访问边界，页面复用查询和操作接口。默认 HTTP 客户端请求同源 `/api/v1`；模拟行为集中在开发与测试模块中。
- 设备、Project、Thread、消息和事项使用稳定 ID 关联，共享业务状态。任一入口的修改应反映到所有相关页面。
- 提供显式启用的开发场景入口，可直接进入和重置空数据、正常运行、离线、等待、异常、冲突等状态。生产构建始终使用 HTTP 客户端。
- 按真实操作状态显示已提交、已保存、等待设备、执行中和已停止，并通过模拟延迟与事件覆盖各阶段。

验收：默认入口使用真实 HTTP 请求；开发时可显式启用 mock 独立启动，切换和重置场景可重复得到相同状态。服务器事件与每 2 秒的轮询触发查询刷新，设备状态变化同时影响 Thread、Project 和文件预览。

## 1. 登录并进入工作区

路径：打开网页 → 恢复会话或登录 → 需要时修改初始口令并重新登录 → 进入工作区 → 切换页面或项目 → 退出登录。

范围：

- 登录表单、提交反馈、账号或口令错误。
- 打开或刷新页面时，通过 `/api/v1/me` 恢复会话与 CSRF token；需要 CSRF 校验的写请求携带 token，token 失效时刷新并重试一次。
- `must_change_password` 对应的首次改密页面、输入校验、失败重试和保存后的重新登录。
- 管理员重置口令后的重新登录提示，以及登录失效时的反馈。
- 侧栏中的 Inbox、Threads、Devices、项目列表和当前账号。
- 页面选中状态、项目切换、侧栏收起与展开。
- 首次进入、没有项目和设备时的入口引导。
- 账号菜单和退出登录。

验收：新用户能找到连接设备、创建项目和新建对话入口；已有数据的用户能在页面之间往返。刷新页面后恢复有效会话与真实记录；要求改密时先完成改密和重新登录，再进入工作区。登录或改密失败保留必要的表单上下文。
## 2. 连接并管理设备

路径：Devices → 连接设备 → 选择系统、获取命令和口令 → 等待接入 → 查看能力 → 配置使用方式。

范围：

- Windows、macOS、Linux 的连接指引，复制命令与口令。凭据通过环境变量或标准输入交给注册命令，不放进命令行参数。
- 等待接入、口令过期、重新获取、连接完成。
- 在线、离线、同步中、最后联系时间。
- Agent、模型、订阅登录情况和缺少的能力。
- 允许访问的目录和发现的仓库；目录配置仍在设备端管理。
- 默认设备设置，包括选择离线设备的提示。
- 项目助手命令执行权限开关，以及执行身份、shell 和无沙箱风险说明。
- 断开设备确认、处理中和完成反馈；默认设备被移除后的提示。

验收：连接或移除设备后，侧栏数量、Thread 位置选择和项目运行条件同步变化；断开设备时明确说明离线设备上的进程可能继续运行，历史记录保留。
## 3. 直接使用一个 Thread

路径：Threads → 选择位置、Agent 和模型 → 发送第一条消息 → 持续对话 → 停止、恢复或归档。

范围：

- 顶部新建输入区，预填默认设备、最近目录和模型。
- 位置菜单、选择其他目录、按 Agent 分组的模型菜单。
- Thread 列表分组，以及设备、项目、归档状态筛选。
- 右侧详情容器；打开详情后列表调整显示列。
- 多轮消息、运行计时、换模型、`Send next`、`Send now`、撤回待发送消息。按 Agent 能力提供操作与不可用原因。
- 停止请求、正在停止、确认停止、超时停止；停止时撤回尚未发出的排队消息。
- 等待设备、执行中设备离线、状态未知。设备离线后保留最后报告的信息，避免将过去的运行状态当成当前事实。
- 支持时恢复原会话；历史丢失时新建对话；目录不存在时重新选择目录。恢复入口保留原设备和可用模型，不向旧对话自动重发。
- 归档确认和归档后的只读状态。已归档、无法恢复或启动失败时隐藏旧对话输入区。

验收：从空列表创建独立对话，完成多轮交互并归档；各异常都有明确反馈或恢复入口。网页新建的 Thread 不属于 Project，设备离线时留在原设备等待，状态未知时不自动重发。回复结束显示空闲，Baton 不判定任务成功或失败。
## 4. 创建项目并交给项目助手推进

路径：新建项目 → 描述目标 → 发起工作 → 助手开 Thread 或执行命令 → 查看进展和回复。

范围：

- 创建弹窗：名称、可选目标、订阅和模型、名称校验。订阅和模型来自设备上报的 Runtime 目录；空目录时显示提示并支持手填 provider ID、model ID，已有未上报的配置保留原值。
- 创建后的空项目和第一条消息引导。
- 主对话中的用户消息、助手回复和处理进度。
- 助手每轮按过程记录、Thread 卡片、正文的顺序呈现内容。
- 概览中的目标、助手运行设备、Threads、待处理事项和最近活动。
- 从主对话卡片或概览打开右侧 Thread，关闭后返回概览；详情打开时保留主对话的状态汇总。
- 在项目内直接向 Thread 发消息，复用流程 3。
- 所有设备离线或没有满足运行条件的设备时保存消息，并显示等待原因。
- 助手切换运行设备的提示；停止当前助手运行，已有 Thread 继续执行。

验收：用模拟场景覆盖“要求两台设备分别执行工作 → 出现两条 Thread → 分别回复 → 项目助手汇报”；真实链路验证消息保存、助手启动、工具调用、实际 Thread 执行及汇报。主对话、概览和 Thread 列表保持一致，用户发起的一轮与项目助手发起的一轮按规格呈现不同的后续通知行为。
## 5. 查看执行过程、附件与文件

路径：打开回复或过程记录 → 查看执行细节 → 打开附件或文件 → 必要时引用内容向项目助手提问。

范围：

- 过程记录展开与收起，命令、工具调用和文件改动。
- 执行中的实时输出；结束后收起为过程记录。
- 输出连接中断、恢复、无法补齐的缺口。
- 完整历史加载、分页，以及设备离线或历史已删除的提示。已保存的回复仍可查看。
- 附件列表、文件预览、代码提交与完整 SHA 的复制。
- 允许目录内的文件浏览、路径导航和文本行号。目录分页读取，受限时保留已取得条目并提示；文本预览每次读取最多 64 KiB，可继续读取后文，文件变化时要求重新打开；二进制内容不提供预览。
- 设备离线、文件不可用、路径越界时的反馈；停止展示不可用文件的旧预览。
- 在有项目上下文的 Thread 回复、文件预览或事项内容中选中文字，带来源预填主对话输入区，补充要求后发送。
- 引用携带对应的 Thread、回复位置、设备、路径、行号或事项标识；超过规格上限时截短并注明来源和原长度。

验收：用户能从回复查看具体过程和文件，再将带来源的片段送回主对话。独立 Thread 没有项目上下文时，不默认选择其他项目作为提问对象。
## 6. 处理需要用户决定的事项

路径：发现待处理数量 → 打开 Inbox 或对话内事项 → 查看上下文 → 回答或关闭 → 项目继续推进。

范围：

- 跨项目 Inbox、最新在前、侧栏及浏览器标签页待处理数量。
- 默认收起的事项说明、受限 Markdown 展示、跳转关联项目或 Thread。
- 选择选项、附加说明、允许时纯文字回答、关闭事项。
- 已回答、已关闭、已撤回、已解决的结果及历史查看入口。
- 同一事项在 Inbox、主对话和 Thread 内同步更新。
- 项目暂停或设备离线时仍可提交回答，输入保存后等待项目助手处理。
- 重复处理或被撤回时，显示已经生效的结果。
- 系统事项：查看原因、前往项目、重试、解决；也可关闭通知。系统事项没有选项或文字回复，不按普通问题处理。

验收：从任意入口处理一次，其他位置同步更新，待处理数量随之变化。普通事项的回答交给项目助手处理，选项不直接执行设备操作；系统事项遵循独立的重试和关闭规则。
## 7. 维护、暂停与归档项目

路径：打开项目设置或记忆 → 修改长期信息 → 暂停与恢复 → 归档 → 查看保留记录。

范围：

- 修改名称、目标、订阅和模型，点 `Save changes` 一次提交；显示未保存、保存中、已保存和失败重试，失败保留输入。未保存的修改留在草稿里，应用内离开再回来仍在，刷新或关闭标签页前由浏览器确认。
- 展示模型修改从下一次运行生效。
- 查看、添加和编辑记忆，显示版本、来源和时间；按真实修订接口分页读取历史，处理保存冲突并保留草稿。
- 暂停项目：主对话新输入等待，Thread 和事项仍可操作。
- 恢复项目：继续处理暂停期间保存的输入。
- 归档确认：停止项目助手和项目中仍在工作的 Thread，撤回未处理事项，保留对话、记忆和 Thread 记录。保存归档期间显示进度，失败时在确认弹窗内重试。归档后按 Thread 实际状态说明：设备确认前显示仍在停止或等待设备连接，停止未生效时提示打开 Thread 再次停止。
- 归档项目的入口、记录查看及只读界面。

验收：修改后的名称和信息在各处一致；停止当前运行、暂停项目、归档项目的影响分别可见。归档 Project 不等于归档其中的 Thread。
## 真实后端接入与部署验收

以下范围与流程 0～7 一起验收。部署结果和实际证据在最终验收时写入仓库外的 handoff 文件。

### 真实客户端与开发环境

- 默认入口使用 `src/data/http`，JSON 请求、Cookie 与 WebSocket 均通过页面同源的 `/api/v1`。开发模式仅在地址中显式带有 `?mock=1` 或 `?scenario=<id>` 时启用 mock 和场景面板；生产构建始终使用真实客户端。
- Vite 可通过 `BATON_DEV_BACKEND` 代理 `/api` 的 HTTP 与 WebSocket 请求，并调整 Origin。后端 TLS 证书持续验证；私有 CA 通过启动 Node.js 前设置 `NODE_EXTRA_CA_CERTS` 加入信任链。
- 页面刷新后通过 `/me` 恢复会话并取得 CSRF token；需要 CSRF 校验的写请求缺少 token 时先获取，遇到 `csrf_rejected` 时刷新并重试一次。验证未登录、会话失效、权限拒绝、首次改密和重新登录的页面行为。
- Project 模型目录来自设备的 `project_runtime.providers[].models`，Thread 模型目录来自对应 Agent 报告。核对 ChatGPT 与 `openai-codex`、xAI 与 `xai`、Claude 与 `anthropic` 的映射，以及未上报目录、手填 provider ID、认证缺失和设备不可用的反馈。Project Runtime 当前注册这三个 provider；设备页按 `login_methods` 显示设备码登录或本地 OAuth/API key 配置入口。
- 核对 Project、Thread、消息、Inbox、文件、执行过程和历史的真实 DTO、错误与分页契约。创建和消息重试沿用同一客户端标识，返回已有记录或实际冲突结果。
- 已登录且有页面订阅时连接 `/api/v1/events`，通过 `thread.changed` 刷新 Thread、消息和操作状态；每 2 秒轮询刷新相关查询，补充其他状态并在事件连接断开后继续更新、尝试重连。
- 已保存的业务数据由 Coordinator 和设备持久化。验证保存后刷新、重新登录、直接打开页面和跨入口读取的一致性。完整历史、执行过程与文件按设备的实际可用性读取；未保存的事项、设置和记忆草稿及引用选择仅留在工作区，离开工作区或刷新后清除。

### 部署验收范围

在实际 Coordinator、batond 与 Agent 环境中执行以下检查，记录实际结果及未覆盖的条件：

- 通过 `node tools/build.mjs` 构建前端并嵌入 Coordinator，由部署后的 HTTPS 地址加载页面、静态资源和同源 API；核对 CSP、页面刷新及项目、Thread、文件和记忆等直接入口。
- 验证真实登录、刷新后会话恢复、CSRF 刷新重试、首次改密、重新登录、退出和会话失效。
- 验证设备接入、能力与模型上报、默认设备、命令权限和设备断开；设备状态变化反映到项目与 Thread。
- 创建 Project 和独立 Thread，发送真实消息并观察设备执行、输出、回复、操作确认及事件更新；核对停止、恢复、归档与设备离线后的反馈。
- 由项目助手创建 Thread 或调用工具，核对主对话、实际执行与 Thread 卡片一致。读取真实历史、执行过程和允许目录中的文件，将带来源的引用发送给项目助手。
- 保存项目设置与记忆，分页读取真实修订历史；处理 Inbox 的回答、关闭和系统事项，验证并发冲突显示已生效的结果。刷新和重新登录后核对已保存内容。
- 验证暂停与恢复、停止当前助手运行、项目归档各自的影响，以及已有 Thread 和保留记录的可用性。
- 断开并恢复事件连接，核对轮询期间状态继续更新、连接可以恢复；验证真实错误、拒绝访问、设备离线和记录不可用时的反馈。

## 设计覆盖

以下交互已有对应设计状态，前端实施时按所属流程验证。

| 所属流程 | 对应交互 |
|---|---|
| 1 | 账号菜单、退出登录、登录失效、首次进入工作区 |
| 2 | 无设备、同步中、能力缺失、默认设备被移除、操作失败 |
| 3 | 选择其他目录、列表空状态、停止与归档确认、能力受限操作 |
| 4 | 空项目的后续交互、无满足条件设备时的具体原因、停止助手运行反馈 |
| 5 | 历史加载与分页、文件不可用、引用预填及长引用处理 |
| 6 | 已处理事项列表、回答表单、处理冲突、处理后的卡片状态 |
| 7 | 记忆编辑与保存冲突、设置保存失败、归档项目入口和只读页面 |

开始对应流程时读取相关画板和组件，通过实际交互验证设计；发现新缺口时先明确交互，再同步设计与实现。补充设计沿用现有组件和文案规则。

## 各流程共同的完成标准

- 正常操作能走到结果，等待和异常有准确反馈；表单错误不清空已填写内容。
- 加载、空数据、提交中、保存失败、重试、复制结果和不可用原因均有对应表现。
- 页面往返、刷新、直接打开及返回位置有明确行为；草稿和筛选状态的保留规则一致。
- 键盘可完成主要操作，焦点可见；菜单和弹窗支持合理的关闭与焦点返回；输入法组合输入不误触发送。
- 常用桌面宽度下检查长名称、长消息、大量列表和滚动。Inbox 在 1024px 宽度下完整显示，无页面横向滚动。
- 浅色与深色主题均按设计检查。涉及安全边界或操作后果的文案完整说明影响。
- 每个关键状态可从模拟场景直接进入并重置；跨页面共享对象同步变化。真实模式的显示内容、模型与结果来自后端和设备报告。
- 交互测试覆盖主要状态转换、错误与冲突，HTTP 契约测试覆盖请求、DTO 映射与分页。浏览器验收覆盖核心使用路径和设计还原；部署验收按真实后端范围执行。

前端验证命令：

```sh
pnpm --dir web format:check
pnpm --dir web lint
pnpm --dir web typecheck
pnpm --dir web test
pnpm --dir web build
```

每条流程交付时说明实现范围、实际执行的验证和仍未覆盖的部分。已有代码按这些标准检查后复用，不能仅因存在页面就视为流程完成。真实链路与部署验收需核对事件顺序、延迟、数据量、权限拒绝和持久化，实际证据写入仓库外的 handoff 文件。
