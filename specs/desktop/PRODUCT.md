# 桌面客户端行为规格

Status: implemented
Owner: Asa
Basis: 桌面端与本机控制通道简化对齐；[设备接入行为规格](../device-setup/PRODUCT.md) DS-08～DS-17；[发布行为规格](../release/PRODUCT.md)。

## Summary

桌面客户端加载已保存中心的网页，网页能做的事在客户端里都能做。在此基础上，客户端通过本地控制通道与本机 `batond` 协作，提供浏览器做不到的本机能力：一键发起本机设备码绑定、窗口隐藏时弹出系统通知、托盘显示运行与待回复工作、在本机文件管理器或编辑器中打开工作目录、通过原生对话框选择本机目录，以及查看和复制本机 `batond` 诊断摘要。首次配置、常驻、登录自启和退出规则见 [设备接入行为规格](../device-setup/PRODUCT.md)。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 中心网页 | 客户端窗口加载的已保存中心的页面，随中心发布，不打进客户端安装包 |
| 桌面能力 | 客户端向已保存中心网页声明开放的一项本机功能，带名称和版本；网页按声明决定是否显示入口 |
| 本机设备 | 与客户端共用默认数据目录、经本地控制通道连接的 `batond` 所绑定的设备（含客户端按需拉起或系统用户服务托管两种运行方式） |

本期支持 macOS arm64 与 Windows x64，安装包不签名、不公证。不在本期范围：应用内自动热更新与跨版本在线迁移、macOS 静默替换应用、把网页打进安装包、离线查看、Linux 桌面客户端、同时连接多个中心、手机。

## Behavior

### 桌面能力与安全边界

- DC-01：客户端向中心网页声明它支持的桌面能力及版本。网页只为已声明的能力显示入口；在普通浏览器中或客户端未声明某项能力时，对应入口不出现，网页其他功能照常可用。网页遇到不认识的能力声明时忽略。
- DC-02：只有来自已保存中心地址的主框架页面可以调用桌面能力。其他站点、页面内嵌子框架和本地接入说明页调用时一律拒绝，客户端不执行任何动作。
- DC-03：每项桌面能力只执行单一具体动作（例如发起本机设备码绑定、打开指定 Thread 的工作目录）。客户端不向网页提供执行任意命令、读写任意文件或遍历任意目录的能力；网页传入的参数仅指明业务对象，真实归属与本机路径由客户端经中心登录会话和本机 `batond` 控制通道核实后取得。

### 版本兼容与替换升级

- DC-04：本机 `batond` 因协议版本不兼容被中心拒绝连接时，托盘与本机设备详情页明确显示不兼容原因，并提供打开中心下载页获取新版客户端安装包的入口。员工安装新版客户端替换旧版后，继续沿用原有的中心配置、设备身份和数据目录。

### 系统通知

- DC-05：客户端运行期间（包括窗口隐藏在托盘时），员工的 Thread 或 Project 出现以下情况会弹出系统通知：Agent 提出问题或请求确认、Turn 结束、Turn 失败或异常停止、本机设备被拒绝连接。通知标题显示 Thread 或 Project 名称，正文说明发生的事件。
- DC-06：员工正在已聚焦的客户端窗口中查看某个 Thread 时，该 Thread 的事件不弹系统通知。同一事件只通知一次；网页重连或重新加载后，不为已通知过的事件重复弹窗。
- DC-07：点击通知后显示并聚焦客户端窗口，打开对应的 Thread 或 Project；目标对象已删除或已归档时，打开列表并说明原因。
- DC-08：托盘菜单提供「通知」开关，默认开启，选择保存在本机。操作系统禁用了客户端的通知权限时，开关旁说明通知已被系统关闭，并提供打开系统通知设置的入口。

### 托盘运行状态

- DC-09：托盘在 [DS-16](../device-setup/PRODUCT.md) 的设备连接状态之外，显示员工当前正在运行的 Thread 数量，以及等待员工回复（问题和确认请求）的数量；统计范围涵盖该员工在所有设备上的 Thread。等待回复数量大于 0 时，托盘图标显示醒目提示标记。
- DC-10：托盘菜单列出等待回复的 Thread（最多 5 个），点击后显示窗口并打开对应 Thread。

### 本机打开与目录选择

- DC-11：Thread 运行在本机设备上时，网页在设备·目录行末尾提供本机打开入口，可选择「在访达中显示」（Windows 为「在资源管理器中显示」）或「用编辑器打开」；Project 页中的本机 Thread 行提供同样入口。客户端只接收 Thread ID 与打开方式，通过本地控制通道由本机 `batond` 核实并返回可信工作目录；目录已不存在时提示原因且不自动创建目录。编辑器可在客户端设置中指定，未指定时使用系统默认关联程序。
- DC-12：运行在其他设备上的 Thread 不显示本机打开入口。Project 保持跨设备调度，不绑定单一设备或工作目录，不为 Project 本身提供本机目录入口。
- DC-13：新建 Thread 选择工作目录且目标设备为本机设备时，网页提供「选择本机目录」入口，调用系统原生目录选择框；取消选择不改变当前输入。选出的路径仍按设备可浏览目录规则经中心与本机 `batond` 校验登记，无效路径显示原因并拒绝。新建 Project 不提供本机目录选择入口。

### 本机诊断

- DC-14：在客户端中打开本机设备的详情页时，通过本地控制通道额外展示 `batond` 运行状态、是否由系统用户服务托管、当前客户端与 `batond` 版本、最近一次异常退出或连接拒绝的时间与原因，并提供「重启 batond」（非系统服务托管时）和「打开日志目录」入口。
- DC-15：员工可从本机设备详情页将脱敏诊断摘要复制到系统剪贴板，内容包含客户端与 `batond` 版本、平台、守护进程与连接状态、最近错误原因及日志末尾最多 200 行。摘要不含连接凭据、设备码、会话令牌或模型密钥，原始日志正文不直接暴露给网页脚本。

## 验收

| 场景 | 设置与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| 能力声明 | 同一中心网页分别在普通浏览器、当前客户端和缺少某项能力的客户端中打开 | 浏览器不显示桌面专属入口；缺少某能力的客户端仅隐藏对应入口，其余功能正常 | DC-01 |
| 调用来源隔离 | 外部站点页面、中心页面内的子框架、本地接入说明页分别尝试调用桌面桥接能力 | 调用全部被拒绝，本机不发生任何文件、进程或剪贴板动作 | DC-02、DC-03 |
| 版本不兼容与覆盖升级 | 中心升级到不兼容协议版本后打开旧版客户端；随后覆盖安装匹配的新版客户端 | 旧版托盘与详情页提示协议不兼容并引导前往下载页；覆盖安装后直接复用原设备身份上线 | DC-04 |
| 通知与去重 | 窗口隐藏时 Agent 提问；窗口聚焦查看某 Thread 时 Turn 结束；刷新网页 | 隐藏时弹通知且点击跳转目标 Thread；聚焦查看时不弹；刷新页面不重复弹历史通知 | DC-05～DC-07 |
| 通知权限与开关 | 在托盘关闭通知；在系统设置中禁用客户端通知权限 | 关闭开关后不再弹出；系统禁用时托盘说明原因并提供系统通知设置入口 | DC-08 |
| 托盘运行摘要 | 员工名下有 2 个运行中 Thread、1 个待回答问题的 Thread | 托盘显示 2 个运行、1 个待回复并带标记；点击菜单项直接打开该待回复 Thread | DC-09、DC-10 |
| 本机打开工作目录 | 分别查看本机 Thread、其他设备 Thread 和 Project；删除本机工作目录后点击打开 | 仅本机 Thread 显示文件管理器与编辑器入口；目录缺失时提示原因且不自动创建目录 | DC-11、DC-12 |
| 本机目录选择 | 新建本机 Thread 时通过原生选择框选目录和取消选择；打开新建 Project 弹窗 | 有效目录被选中并登记，取消不改原值；新建 Project 无目录选择入口 | DC-13 |
| 本机诊断与脱敏 | 模拟连接拒绝或进程异常后查看本机详情页并复制诊断摘要；在已安装用户服务时查看详情页 | 准确显示错误原因与版本；剪贴板摘要已剥离敏感凭据；用户服务托管时说明托管方式 | DC-14、DC-15 |

自动化验收使用本地中心与本地控制通道替身验证能力协商、来源校验、路径核实、通知去重和诊断脱敏；原生窗口、托盘、系统通知与文件管理器交互在 macOS arm64 与 Windows x64 真机手动验证。网页界面改动遵循 [Web UI 设计系统](../web-ui/DESIGN.md)。
