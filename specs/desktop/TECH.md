# 桌面客户端技术设计

Status: in progress
Basis: [桌面客户端行为规格](PRODUCT.md) DC-01～DC-10；[发布设计](../release/TECH.md)；[设备接入规格](../device-setup/PRODUCT.md)。

## 更新来源与信任边界

客户端 main 只向已保存的 HTTPS 中心请求 `GET /api/v1/release`、`GET /api/v1/downloads` 和 `/downloads/<文件名>`。中心继续使用现有下载目录、版本筛选、SHA-256 校验和公开发布信息，不新增数据库表。安装包必须属于当前中心版本、当前平台和架构；版本按字符串精确比较，不以语义版本大小决定是否更新。查询在启动及每 6 小时执行，版本拒绝时立即重新查询。没有对应安装包时显示中心版本及缺包原因，保留重试入口。

HTTPS 使用部署配置保存的 CA 或系统信任，不跟随重定向，不接受中心返回的任意 URL。文件名限定为目标版本和平台的标准安装包名。下载写入 userData 下私有更新目录的临时文件，大小与 SHA-256 均核对后原子改名；每次交给安装程序前重新校验，不符时删除并提供重试。

桌面更新由原生窗口菜单、托盘和原生进度对话框提供。版本不兼容时显示原始公开拒绝原因和更新操作，无需修改中心网页。preload 声明带版本的 `update` 能力，只为保存中心的主 frame 暴露查询和具体更新动作；main 每次校验窗口、frame 与源，网页不能指定路径、命令或下载地址。

## 升级准备与目标绑定

设备执行暂停、进程核查、备份、迁移和完成确认沿用 batond 的 `upgrade.json` 与 `draining → ready → migrating → syncing → completed`。取消继续使用 `cancelled`，迁移失败继续使用 `failed`。客户端只保存下载信息和上次成功运行的客户端版本，不建立另一份设备升级阶段。

桌面安装包替换之前尚无可执行的目标安装目录，因此扩展原 `upgrade prepare`，允许按当前中心发布版本发起准备。此时记录目标版本但不声称已经核验目标二进制。新程序首次启动时，将同一操作绑定到自身 `resources/batond`，核对实际程序、发布清单、版本及本地格式后再迁移。传统 `--package` 入口继续使用完整预检。目标版本或构建身份冲突时拒绝继续，不覆盖既有操作。

客户端发现上次成功运行版本不同，或已有设备身份但没有成功版本记录时，先暂停普通监管，由新 batond 自己发起准备。这也覆盖未经过旧版本准备便直接替换的情况。准备必须先持久保存暂停，再允许任何 daemon 业务启动；仍存活的独立 Worker、Runtime、登记后代或未确认清理事实阻挡 ready。没有 daemon 时在原有数据目录锁保护下检查和推进准备，绝不把 daemon 退出当作全部进程退出。外部服务仍占锁时显示等待原因，不停止或接管外部进程。

## 客户端监管与安装

| batond 阶段 | 客户端监管与员工操作 |
|---|---|
| 无升级 / completed / cancelled | 正常监管；保留上次完成信息。版本不一致时提供中心版本更新入口 |
| draining | 已在运行的 daemon 继续处理原准备流程；首次启动直接替换时不启动普通业务。显示工作、PID、清理原因与待补报数；可取消或显式停止对应 Thread，停止沿用原命令语义 |
| ready | 停止并等待本客户端持有的 daemon 真正退出，关闭自动重启；外部 daemon 须由其管理者退出。下载、校验并交给平台安装入口 |
| migrating / failed | 不启动或重启 daemon；运行目标 `upgrade migrate`，失败保持暂停，显示阶段与原因，提供重试和打开日志目录 |
| syncing | 恢复目标 daemon 的监管，但业务仍由原升级门禁暂停；完成认证、同步、结果补报及中心完成回执后才继续原队列 |

Windows 运行已经校验的按用户 NSIS 安装包，以静默更新参数安装并重新启动。旧客户端先完成退出与监管停止，不在旧应用仍占用文件时自行覆盖。安装未完成时 ready 状态保持有效，再次启动可重试同一安装；新客户端绑定目标后继续迁移。

macOS 不使用需要 Developer ID 的静默替换。客户端打开已校验 DMG，明确提示把 Baton 拖到「应用程序」替换并退出旧版本。旧客户端退出时只停止自己持有的 daemon，设备保持 ready；员工打开新副本后绑定新目标并迁移。旧副本再次启动仍显示 ready 和安装提示，不解除暂停。

## 中断恢复与持久不变量

| 中断位置 | 重启后的依据和处理 |
|---|---|
| 查询或准备 | 重新查询中心；已有操作按 operation ID 和目标版本复用。读取状态失败时保持暂停并报错 |
| 等待工作结束 | 查询原 `upgrade status`，重查锁、工作和登记进程，不强杀、不超时判定就绪 |
| 下载 | 删除不完整临时文件，重试下载；完整文件重新核对大小和校验值 |
| 安装替换 | ready 保留；旧副本提供重试，新副本绑定自身目标。配置、身份和设备目录保持原位置 |
| 迁移 | 目标 `migrate` 复用原备份，依据库内格式继续；不恢复旧备份、不重建数据 |
| 同步 | 原 daemon 重报并补交相同报告身份，取得中心完成回执后恢复队列；不调用会撤回排队输入的 resume |

迁移子进程使用独立于注册操作的长时等待，不因普通 CLI 的 40 秒超时被结束。客户端退出时不杀迁移进程；再次启动先检查原锁与持久阶段，等待或重试。日志写入设备日志目录，错误包含阶段和固定错误码，不含凭据。

## 验证

离线测试以依赖注入的进程、下载与安装替身验证准备、取消、ready、替换、首次迁移、syncing 与 completed；保留原排队输入身份，不重复派发。batond 测试验证直接替换时仍存活的 Worker 阻挡迁移、目标绑定、锁与失败重跑。下载测试覆盖离源重定向、错误版本、路径、大小、校验值及损坏缓存。macOS arm64 使用两个实际打包版本和本机中心验证替换与迁移；Windows 真机安装结果单独记录，未运行时标为未测。
