## Summary

用户为一件长期的事创建 Project，例如「Baton 开发」。每个 Project 有一个 Project Agent，负责和用户对话、记住项目里的决定、把具体工作派给某台设备上的执行 Agent，并处理返回的结果。Project Agent 在用户自己的设备上运行，使用设备上已登录的模型订阅；对话、记忆和待处理的消息都存在 Coordinator，所以它可以这次在 Mac 上运行，下次换到 Windows 上接着处理。

例如：用户在浏览器里发消息「在 Windows 上跑一遍兼容性测试」。Coordinator 在用户的 Mac 上拉起 Project Agent，它把测试任务派给 Windows，回复用户后退出。半小时后测试结果返回，Mac 已经关机，Coordinator 改在 Linux 主机上拉起 Project Agent，它读到之前的对话和这条结果，向用户汇报。

Project Agent 请用户做决定的事项（Agent Inbox）和可操作的任务成果，见 [Agent Inbox 行为规格](../agent-inbox/PRODUCT.md)。

本期不包括：外部工单事件（Linear、Plane）触发 Project Agent、定时触发、一个 Project 内多个常驻角色、更换 Runtime 后的会话迁移、运行中进程的跨设备迁移。

## Behavior

### 身份与边界

- PA-01：用户创建 Project 时只需提供标题，可补充目标说明。Project 可以长期存在，可以暂停或归档，没有删除流程。Project 不绑定代码仓库，它的数据里没有设备、工作目录或仓库与设备的对应关系。项目记忆里可以有「Baton 仓库在 Mac 上的路径是 ~/src/baton」这样的普通事实，但它不构成授权或配置。
- PA-02：创建 Project 时同时创建它唯一的 Project Agent 和一个主对话，三者各有稳定 ID。修改标题、换设备运行都不改变这些 ID。
- PA-03：Project Agent 负责协调和管理环境。它可以对话、检索和修改项目记忆、查询历史、查询设备能力、派发和查询任务、请求取消任务、创建和撤回请用户处理的事项（Agent Inbox IB-01、IB-23），并在用户开启了命令执行的设备上执行命令（PA-22，推迟到第一个版本之后），例如创建 worktree、检查仓库状态。开发工作优先交给执行 Agent；必要时 Project Agent 可以自己修改配置、运行脚本。这是写在系统提示词里的分工，Baton 不检查命令内容，也不拦截写文件。它不能通过任务结果、记忆内容或模型输出获得额外的工具。工具集合由 Baton 固定，每次调用都由后端检查权限。
- PA-04：Project Agent 使用设备上已登录的模型订阅推理，不要求用户提供 API key。Coordinator 不做模型推理，不保存订阅凭据。用户为每个 Project Agent 选择使用哪个订阅和模型，可以随时修改，修改从下一次运行起生效。

### 输入与运行

- PA-05：本期的输入有两类。会触发运行的是用户消息、Project Agent 自己派发的任务的结果，以及用户对事项的回答或关闭（Agent Inbox IB-12）。只做通知的是用户在界面上对项目记忆、Project 标题或目标的修改（PA-17），以及用户在 Project 里直接派发的任务的结果（PA-23，2026-10-19 修订）。输入先在 Coordinator 的输入队列里持久保存，再触发运行。用户消息带客户端生成的消息 ID，重发同一 ID 和相同内容时返回原记录，内容不同时返回冲突；同一任务的同一结果版本只形成一条输入。单条用户消息不超过 64 KiB；任务结果进入队列时，文本超过 32 KiB 的部分保留开头和结尾，Project Agent 可以用任务查询读取全文。
- PA-06：有待处理的输入时，Coordinator 从用户的设备中选择一台运行 Project Agent。设备需要同时满足：在线、已同步、装有 Project Agent Runtime、所需模型订阅可用。用户默认设备满足条件时优先选它，否则选其他满足条件的设备，并记录选择原因，不修改默认设备设置。
- PA-07：没有满足条件的设备时，Project Agent 不运行，输入在 Coordinator 里等待，不会过期。界面显示等待原因，例如所有设备离线、订阅需要重新登录。有设备满足条件后，Coordinator 再次尝试。
- PA-08：同一个 Project Agent 同一时刻最多只有一个有效运行实例。实例失去资格后（例如网络断开导致租约过期），它发出的写入全部被拒绝。界面区分「实例已失去资格」和「进程已确认退出」。
- PA-09：只有通知类输入时，Coordinator 不启动 Project Agent。Project Agent 一次运行会处理完当前所有待处理输入。处理完后，如果在 180 秒内有新输入到达，就接着处理；否则退出。单次运行有时长上限，到达上限时处理完当前这一轮再退出，剩余输入由下一次运行处理。Project Agent 退出不影响它已派出的任务。
- PA-10：Project Agent 每开始一轮，就把此刻的待处理输入按到达顺序一起交给模型。例如 5 个子任务的结果同时返回，它们在同一轮里处理。一轮最多 20 条，总量也有上限，超出的按顺序放到下一轮。一轮进行中到达的新输入，放到下一轮。

### 持久保存与恢复

- PA-11：对话中的每条内容都自动保存到 Coordinator，包括用户输入、模型回复、工具调用和工具结果。一条内容保存成功后，Project Agent 才继续下一步。保存的内容只追加、不修改、不删除。所有设备都离线时，用户仍可以在界面上查看完整对话。
- PA-12：运行中途崩溃或失去资格时，下一次运行从最后一条已保存的内容接着处理。已经执行过的工具调用不会再执行一次，例如任务不会被派发两次。崩溃前还没保存的模型输出会被丢弃，模型可能重新生成一次，这只会多消耗一次推理。
- PA-13：模型请求失败、设备断线等暂时性错误自动重试，有次数上限。超过上限后，主对话标记为「需要处理」并暂停，界面显示原因，Agent Inbox 出现一个系统事项（IB-33，2026-10-19 修订）；之后到达的输入继续保存。用户确认重试后，从原位置继续。其他 Project 不受影响。

### 上下文与记忆

- PA-14：发给模型的上下文按以下顺序组织：系统提示词、工具定义、压缩摘要（如果有）、此后的对话原文。当前设备、当前时间、队列长度这类每次都会变的信息不放进系统提示词，需要时由工具返回，或者附在新输入里。同一个主对话在不同设备上恢复时，发给模型的内容和上次一致，以便命中模型厂商的 prompt cache。缓存是否命中不影响正确性。
- PA-15（推迟到第一个版本之后，2026-10-19）：第一个版本不压缩；上下文超过模型上限时模型请求失败，按 PA-13 处理。实现后的行为：上下文用量超过阈值时才压缩，优先在运行结束前进行。压缩先清掉较早的工具输出；用量仍然过高时，再把最早的一段对话换成摘要。摘要前面有一行由程序生成的说明，写明它替换了哪些内容、原文可以怎样查看。压缩只改变发给模型的内容，Coordinator 里的原始对话保持完整。
- PA-16（推迟到第一个版本之后，2026-10-19）：Project Agent 可以按关键字搜索、按位置读取主对话的原始内容，包括已经被压缩的部分。
- PA-17：Project Agent 通过工具检索和修改项目记忆，每次修改保留版本、来源和时间。用户可以在界面上查看和修改记忆。用户的修改形成一条通知，写明是哪条记忆、新版本号，在 Project Agent 处理下一条用户消息或任务结果时一起交给它；同一条记忆连续改了几次，只通知最新版本。Project Agent 自己的修改不再通知。用户修改 Project 标题或目标时同样形成通知。

### 工具与任务

- PA-18：每个工具的输出都能通过某个只读工具重新拿到。例如派发任务返回的任务 ID，可以通过「列出本 Project 的任务」再次查到。因此清掉较早的工具输出不会让 Project Agent 失去找回信息的途径。
- PA-19：Project Agent 派发任务时，自己决定目标设备、执行 Agent 和工作目录。依据是设备上报的能力（允许的目录、发现的仓库、已安装的 Agent）和项目记忆。工作目录必须已经存在；第一个版本由用户预先创建需要的目录；PA-22 实现后，Project Agent 可以用命令执行创建它（2026-10-19 修订）。任务被接受后参数固定，沿用 Baton R-06。目录不存在或条件不满足时任务明确失败；Project Agent 要换设备或换目录，需要重新派发一个新任务，并和原任务建立关联。同一次工具调用最多产生一个任务。派发时 Project Agent 在 `expected_outputs` 里写明怎样验证完成，例如要运行的测试和必须观察到的结果；找不到验证方式时写明原因。这条写在系统提示词里，Baton 不检查内容（2026-10-19 修订）。
- PA-20：Project Agent 派发的任务结束时，它的结果作为一条输入进入 Project Agent 的待处理队列。结果被人工修正后形成新的结果版本，作为一条新输入。执行 Agent 再派生的子任务按原有父子关系把结果交给父任务，不再单独通知 Project Agent。
- PA-22（推迟到第一个版本之后，2026-10-19）：用户可以在每台设备上单独开启「允许 Project Agent 执行命令」，默认关闭。开启后，Project Agent 可以在这台设备的已登记目录下执行任意命令，命令以设备上的用户身份运行，使用设备上报的 shell（例如 bash、zsh、PowerShell）。每次执行时，Project Agent 指定最多等待多久。命令在等待时间内结束，输出直接返回；没有结束时，Project Agent 先得到「仍在执行」和任务 ID，命令继续执行，结束后的结果作为一条输入送回（PA-20）。等待结束不会终止命令。命令的执行时限单独设置，默认 2 小时。同一次工具调用最多执行一次命令；无法确认命令是否执行过时，结果标为待核实，不会自动重试。命令和输出完整记录在对话里，输出超过 32 KiB 时保留开头和结尾。Baton 不为这些命令提供沙箱，开启前界面要说明这一点。

### 界面

- PA-21：用户可以在桌面浏览器里查看 Project 列表、主对话、项目记忆、等待原因、当前运行实例所在的设备，以及 Project Agent 派出的任务和结果。Project Agent 执行的命令显示在主对话和 Project 的任务里，全局任务列表默认不显示，可以用筛选条件查看。所有设备离线时仍可发送消息，界面显示消息正在等待设备，不显示 Project Agent 正在运行。Project Agent 运行时，用户可以在界面上停止这次运行；已派出的任务不受影响。Project 的任务列表标明每个任务由 Project Agent 还是用户派发（2026-10-19 修订）。手机和窄屏布局暂不支持。

### 用户直接控制（2026-10-19 新增）

- PA-23：用户可以在 Project 里直接派发任务，不经过 Project Agent。用户可以指定目标设备、执行 Agent 和工作目录，也可以只写任务说明，按 Baton R-06 发往默认设备；界面提供填写验证方式的位置（`expected_outputs`），可以留空。这个任务属于该 Project，显示在 Project 的任务列表里；Project Agent 没有运行或 Project 暂停时同样可以派发。任务结束后，结果作为一条通知类输入交给 Project Agent（PA-05），不触发运行。用户想让 Project Agent 接着处理时，可以用「问 Project Agent」引用这个结果发消息（Agent Inbox IB-21）。
- PA-24：对 Project Agent 派出的任务，用户可以直接取消、人工核实或发起新执行，规则与 Baton R-20、R-21 相同。结果按 PA-20 进入 Project Agent 的输入队列，并写明操作人和操作。系统提示词要求 Project Agent 不撤销用户的操作，例如不重新派发用户取消的任务，除非用户在对话里要求；Baton 不在后端拦截这类派发。
- PA-25：用户暂停 Project 后，Project Agent 不再启动，已派出的任务继续执行。暂停期间用户仍可以按 PA-23、PA-24 派发和处理任务，期间产生的输入全部保存。用户恢复 Project 后，Project Agent 按 PA-10 处理这些输入。

## 验收

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| PA-A01 | 浏览器发消息；Project Agent 在设备 A 运行，保存一条记忆，把任务派给设备 B 后退出；B 的结果返回时 A 已离线 | 设备 C 上的新实例读到之前的对话和记忆，处理这条结果；这次派发只有一个 Task 和一个 Execution；全程使用设备上已登录的订阅，没有 API key |
| PA-A02 | 所有设备离线时发送消息，并有任务结果返回 | 没有运行实例；设备上线后处理同一批输入，不产生重复记录 |
| PA-A03 | 默认设备不满足条件 | 在另一台设备运行，默认设备设置不变；Project 数据里没有设备或目录字段 |
| PA-A04 | 同时到达多个输入；运行中断网使租约过期，网络恢复 | 只有一个有效实例；旧实例恢复连接后的写入全部被拒绝 |
| PA-A05 | 分别在模型回复保存前后、任务接受前后、工具结果返回前后杀掉 Runtime 进程 | 恢复后任务数、记忆版本数不重复；对话里没有重复的工具结果 |
| PA-A06 | 同一主对话先后在两台不同系统的设备上运行 | 第二台设备发给模型的系统提示词、工具定义和历史消息与第一台的最后一次请求一致 |
| PA-A07 | 对话很长，超过压缩阈值 | 运行结束前完成压缩；摘要带有程序生成的范围说明；Project Agent 能用历史工具读到被压缩的原文 |
| PA-A08 | 对未开启命令执行的设备调用 `nodes.exec`；模型要求使用工具列表之外的工具 | 两者都被后端拒绝 |
| PA-A09 | 派发到一个不存在的目录 | 任务明确失败；Project Agent 换设备重新派发时产生新任务，并和原任务关联 |
| PA-A10 | 模型请求持续失败 | 达到重试上限后主对话暂停并显示原因；新消息继续保存；用户确认重试后从原位置继续 |
| PA-A11 | 在开启了命令执行的设备上，对一个大仓库执行 `git worktree add`，等待时间设得比命令实际耗时短 | 先返回「仍在执行」；命令不被中断；完成后结果作为输入送回；随后派发到新 worktree 的任务正常执行 |
| PA-A12 | 命令执行中杀掉 Runtime 进程，再杀掉目标节点的 Worker | 恢复后命令没有被执行第二次；Worker 被杀的情况下结果标为待核实 |
| PA-A13 | 20 个任务同时结束，每个结果都很长；其中一个结果的摘要有 300 KiB | 结果分几轮全部处理，没有丢失；进入对话的那条结果被截短并注明全文的读取方式，Project Agent 能读到全文 |
| PA-A14 | Project Agent 没有运行时，用户连续修改同一条记忆 3 次，然后发一条消息 | 修改记忆时没有启动运行；处理这条消息时 Project Agent 收到一条通知，版本号是最新的 |

| PA-A15 | Project Agent 没有运行时，用户在 Project 里直接把任务派到指定设备；任务完成后用户发一条消息 | 任务执行期间和完成时都没有启动 Project Agent；处理这条消息时 Project Agent 收到这个任务结果的通知；任务列表显示由用户派发 |
| PA-A16 | 用户取消 Project Agent 派出的一个运行中任务 | 取消按 Baton R-21 生效；Project Agent 收到的结果写明由用户取消 |
| PA-A17 | Project 暂停期间，用户直接派发一个任务并人工核实另一个任务，然后恢复 Project | 暂停期间没有运行实例；恢复后 Project Agent 收到期间的全部输入，没有重复 |

PA-A07、PA-A11、PA-A12 和 PA-A08 中的命令执行部分，随压缩和命令执行推迟到第一个版本之后。PA-A01 和 PA-A06 必须使用真实 Runtime 和真实订阅；其他场景可以用测试用的模型替身。
