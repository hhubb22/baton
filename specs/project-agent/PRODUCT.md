# Project Agent 行为规格

Status: approved
Owner: Asa
Basis: 《Baton Project Agent 需求说明》及其后续讨论；[Baton 行为规格](../baton/PRODUCT.md)。

## Summary

用户为一件长期的事创建 Project，例如「Baton 开发」。Project 里有两种对话：

- 主对话：用户和 Project Agent 的对话。Project Agent 记住项目里的决定，替用户在各台设备上开 Thread、发消息、读回复，再向用户汇报。
- Thread：某台设备上某个目录里的一个执行 Agent 会话，例如 Windows 台式机上 `D:\src\baton` 里的一个 Codex 会话。用户可以自己开，也可以由 Project Agent 开。Thread 的行为见 Baton 行为规格「Thread」一节。

Project Agent 是用户的代理人：用户能对 Thread 做的操作，它都能做。它在用户自己的设备上运行，使用设备上已登录的模型订阅；对话、记忆和待处理的输入都存在 Coordinator，所以它可以这次在 Mac 上运行，下次换到 Windows 上接着处理。

例如：用户在主对话里说「在 Windows 上跑一遍重连测试」。Coordinator 在用户的 Mac 上拉起 Project Agent，它在 Windows 台式机上开一个 Codex Thread，发出测试要求，回复用户后退出。半小时后 Codex 这一轮结束，Mac 已经关机，Coordinator 改在 Linux 主机上拉起 Project Agent，它读到之前的对话和 Codex 的回复，向用户汇报。

Project Agent 请用户做决定的事项见 [Agent Inbox 行为规格](../agent-inbox/PRODUCT.md)。

本期不包括：外部工单事件（Linear、Plane）和定时触发 Project Agent、一个 Project 内多个常驻角色、更换 Runtime 后的会话迁移、运行中进程的跨设备迁移、执行 Agent 之间直接委托（执行 Agent 需要别的设备配合时，在回复里说明，由 Project Agent 协调）。

## Behavior

### 身份与边界

- PA-01：用户创建 Project 时只需提供标题，可补充目标说明。Project 可以长期存在，可以暂停或归档，没有删除流程。Project 不绑定代码仓库或设备。项目记忆里可以有「Baton 仓库在 Mac 上的路径是 ~/src/baton」这样的普通事实，但它不构成授权或配置。
- PA-02：创建 Project 时同时创建它唯一的 Project Agent 和一个主对话，三者各有稳定 ID。修改标题、换设备运行都不改变这些 ID。
- PA-03：Project Agent 的工具由 Baton 固定：对话历史、项目记忆、设备能力、本 Project 的 Thread 操作（新建、发消息、停止、归档、读取）、事项（Agent Inbox）、在用户开启了命令执行的设备上执行命令（PA-21）。每次调用都由后端检查权限。它不能通过 Thread 回复、记忆内容或模型输出获得额外的工具。开发工作优先交给 Thread 里的执行 Agent；必要时 Project Agent 可以自己执行命令。这是写在系统提示词里的分工，Baton 不检查命令内容。
- PA-04：Project Agent 使用设备上已登录的模型订阅推理，不要求用户提供 API key。Coordinator 不做模型推理，不保存订阅凭据。用户为每个 Project Agent 选择订阅和模型，修改从下一次运行起生效。

### 输入与运行

- PA-05：输入先在 Coordinator 的输入队列里持久保存，再交给 Project Agent。输入分两类：

  | 类型 | 内容 | 是否触发运行 |
  |---|---|---|
  | 主动 | 用户在主对话里的消息；Project Agent 发起的那一轮 Turn 结束（PA-13）；用户对事项的处理（Agent Inbox） | 是 |
  | 被动 | Project Agent 发起的那一轮里 Agent 的中间回复；用户对项目记忆、Project 标题或目标的修改 | 否，随下一次主动输入一起交给 Project Agent |

  用户消息带客户端生成的消息 ID，重发同一 ID 和相同内容时返回原记录，内容不同时返回冲突。单条用户消息不超过 64 KiB；Thread 回复进入队列时，超过 32 KiB 的部分保留开头和结尾，Project Agent 可以读取全文。
- PA-06：有主动输入时，Coordinator 从用户的设备中选择一台运行 Project Agent。设备需要同时满足：在线、已同步、装有 Project Agent Runtime、已声明所需 provider，认证状态为可用或未知。认证未知时允许启动并由 provider 检查；明确需要登录或凭据权限、属主、路径错误时显示具体原因并拦截。默认设备满足条件时优先选它，否则选其他满足条件的设备，并记录原因，不修改默认设备设置。
- PA-07：没有满足条件的设备时，Project Agent 不运行，输入在 Coordinator 里等待，不会过期。界面显示等待原因，例如所有设备离线、订阅需要重新登录。有设备满足条件后再次尝试。
- PA-08：同一个 Project Agent 同一时刻最多只有一个有效运行实例。实例失去资格后（例如网络断开导致租约过期），它发出的写入全部被拒绝。
- PA-09：Project Agent 一次运行会处理完当前所有待处理输入。处理完后，如果 180 秒内有新的主动输入，就接着处理；否则退出。单次运行有时长上限，到达上限时处理完当前这一轮再退出。Project Agent 退出不影响它开的 Thread。
- PA-10：Project Agent 每开始一轮，把此刻的待处理输入按到达顺序一起交给模型。一轮最多 20 条，总量也有上限，超出的放到下一轮。一轮进行中到达的输入放到下一轮。

### 持久保存与恢复

- PA-11：主对话中的每条内容都自动保存到 Coordinator，包括用户输入、模型回复、工具调用和工具结果。一条内容保存成功后，Project Agent 才继续下一步。保存的内容只追加、不修改、不删除。所有设备都离线时，用户仍可以查看完整对话。
- PA-12：运行中途崩溃或失去资格时，下一次运行从最后一条已保存的内容接着处理。已经执行过的工具调用不会再执行一次，例如同一条消息不会发进 Thread 两次。崩溃前还没保存的模型输出会被丢弃，模型可能重新生成一次。
- PA-13：模型请求失败时自动重试；本次运行重试耗尽后结束运行，并依次退避 1、5、15 分钟，后续失败继续使用 15 分钟间隔。连续失败三次起，界面显示最后的错误，Agent Inbox 出现一个系统事项，退避到期仍自动尝试。新的用户消息可立即触发一次尝试，同一消息 ID 的重发不改变退避。用户也可显式重试；任一模型回复保存成功后清除失败计数与系统事项。租约、工具去重及执行结果不确定时的保护继续生效。其他 Project 不受影响。

### 上下文与记忆

- PA-14：发给模型的上下文按以下顺序组织：系统提示词、工具定义、压缩摘要（如果有）、此后的对话原文。当前设备、当前时间这类每次都会变的信息不放进系统提示词。同一个主对话在不同设备上恢复时，发给模型的内容和上次一致，以便命中模型厂商的 prompt cache。
- PA-15：上下文用量超过阈值时才压缩。压缩先清掉较早、已被分析过的大工具输出，用量仍然过高时，再把最早的一段对话换成摘要，保留最近的原文。工具调用与结果始终成对。摘要保留用户要求、Thread ID、设备、状态、决定和未完成事项。摘要为空、没有缩短上下文或生成期间历史变化时，不用它替换原文。压缩只改变发给模型的内容，Coordinator 里的原始对话保持完整。
- PA-16：Project Agent 可以按关键字搜索、按位置读取主对话的原始内容，包括已经被压缩的部分。每个工具的输出都能通过某个只读工具重新拿到，例如新建 Thread 返回的 Thread ID 可以从 Thread 列表再次查到。
- PA-17：Project Agent 通过工具检索和修改项目记忆，每次修改保留版本、来源和时间。用户可以在界面上查看和修改记忆。用户的修改形成一条被动输入，写明是哪条记忆和新版本号；同一条记忆连续改了几次，只交给 Project Agent 最新版本。

### Thread

- PA-18：Project Agent 新建 Thread 时自己选择设备、工作目录、Agent 类型和模型，依据是设备上报的能力（登记的目录、发现的仓库、已安装的 Agent 及其模型）、用户在主对话里的要求和项目记忆。工作目录必须已经存在；需要新目录时，Project Agent 先用 PA-21 的命令执行创建它。条件不满足时新建失败并返回原因。同一次工具调用最多新建一个 Thread。
- PA-19：Project Agent 可以向本 Project 的任何 Thread 发消息；Agent 正在处理时，它和用户一样选择排队或插入（Baton R-08）。一轮 Turn 属于发出第一条消息的一方：Project Agent 开启的，Agent 的每条回复都进入它的输入队列（PA-05），用户中途补充消息或停止这一轮，回复和结束仍然交给 Project Agent；用户开启的，不通知 Project Agent。用户想让 Project Agent 接着处理时，直接在主对话里说，Project Agent 可以读取本 Project 的所有 Thread。
- PA-20：Project Agent 可以停止 Thread 当前的一轮、归档 Thread，规则与用户的操作相同。

### 命令执行

- PA-21：用户可以在每台设备上单独开启「允许 Project Agent 执行命令」，默认关闭。开启后，Project Agent 可以在这台设备的已登记目录下执行任意命令，命令以设备上的用户身份运行，使用设备上报的 shell。每次执行时，Project Agent 指定最多等待多久：命令在等待时间内结束，输出直接返回；没有结束时，先返回「仍在执行」和命令 ID，命令继续执行，结束后的输出作为一条主动输入送回。命令的执行时限默认 2 小时。同一次工具调用最多执行一次命令；无法确认命令是否执行过时标为状态未知，不会自动重试。命令和输出记录在主对话里，输出超过 32 KiB 时保留开头和结尾。Baton 不为这些命令提供沙箱，开启前界面要说明这一点。

### 界面与暂停

- PA-22：用户可以在桌面浏览器里查看 Project 列表、主对话、Thread 列表和每个 Thread、项目记忆、等待原因和当前运行实例所在的设备。主对话里，Project Agent 开 Thread、执行命令各显示为一行，点开查看。所有设备离线时仍可发送消息，界面显示消息正在等待设备。Project Agent 运行时，用户可以停止这次运行，它开的 Thread 不受影响。手机和窄屏布局暂不支持。
- PA-23：用户暂停 Project 后，Project Agent 不再启动，Thread 照常可用。期间产生的输入全部保存。用户恢复 Project 后，Project Agent 按 PA-10 处理这些输入。

## 验收

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| PA-A01 | 浏览器发消息；Project Agent 在设备 A 运行，保存一条记忆，在设备 B 上开一个 Thread 后退出；B 上这一轮结束时 A 已离线 | 设备 C 上的新实例读到之前的对话和记忆，处理这轮回复；只开了一个 Thread；模型调用由设备上的本地替身提供，中心不接触凭据 |
| PA-A02 | 所有设备离线时发送消息，同时有 Thread 的一轮结束 | 没有运行实例；设备上线后处理同一批输入，不产生重复记录 |
| PA-A03 | 默认设备不满足运行条件 | 在另一台设备运行，默认设备设置不变 |
| PA-A04 | 同时到达多个输入；运行中断网使租约过期，网络恢复 | 只有一个有效实例；旧实例恢复连接后的写入全部被拒绝 |
| PA-A05 | 分别在模型回复保存前后、新建 Thread 前后、发消息前后杀掉 Runtime 进程 | 恢复后 Thread 数、发出的消息数、记忆版本数都不重复 |
| PA-A06 | 同一主对话先后在两台不同系统的设备上运行 | 第二台设备发给模型的系统提示词、工具定义和历史消息与第一台的最后一次请求一致 |
| PA-A07 | 对话很长，超过压缩阈值 | 完成压缩；Project Agent 能读到被压缩的原文 |
| PA-A08 | 对未开启命令执行的设备执行命令；模型要求使用工具列表之外的工具 | 两者都被后端拒绝 |
| PA-A09 | 在不存在的目录新建 Thread | 新建失败并返回原因；Project Agent 换目录重试时只产生一个新 Thread |
| PA-A10 | 模型请求持续失败 | 本次重试耗尽后按 1、5、15 分钟退避，三次起显示系统事项；后续仍自动尝试，新消息或显式重试可立即继续，原有输入保留 |
| PA-A11 | 在开启了命令执行的设备上执行 `git worktree add`，等待时间比命令实际耗时短 | 先返回「仍在执行」；命令不被中断；完成后输出作为输入送回 |
| PA-A12 | 命令执行中杀掉 Runtime；分别在 Worker 执行中、完成记录保存后且尚未交付时杀掉 Worker | 命令没有执行第二次；有完成记录时补回原输出，否则标为状态未知 |
| PA-A13 | Project Agent 开了 20 个 Thread，它们的一轮同时结束，每个回复都很长 | 回复分几轮全部处理，没有丢失；超长回复被截短并注明读取方式 |
| PA-A14 | Project Agent 发起的一轮里，执行 Agent 先后回复 3 条，最后一条结束这一轮 | 前 2 条回复没有触发运行；这一轮结束时 Project Agent 被启动，按顺序收到全部 3 条 |
| PA-A15 | Project Agent 开的一轮进行中，用户补充一条消息，再停止这一轮；之后用户在同一个 Thread 里开启新的一轮 | 前一轮的回复和停止都交给 Project Agent；用户开启的新一轮没有启动 Project Agent，输入队列里没有它的回复 |
| PA-A16 | 用户在 Project Agent 开的 Thread 里开启一轮，结束后 Project Agent 在同一个 Thread 发消息 | 用户那一轮的回复不进入输入队列；Project Agent 开启的这一轮的回复进入输入队列 |
| PA-A17 | Project 暂停期间，用户在 Thread 里发消息，再在主对话发消息，然后恢复 | 暂停期间 Thread 正常回复，没有 Project Agent 运行实例；恢复后 Project Agent 收到主对话里的消息，没有重复 |

PA-A01 和 PA-A06 使用真实 Runtime 进程与本地模型替身，记录请求并验证跨设备恢复；其他场景使用离线回放或本地替身。真实订阅登录与模型调用为可选的手动冒烟检查，不作为功能开放或发布前提。
