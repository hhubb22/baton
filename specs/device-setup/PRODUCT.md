# 设备接入行为规格

Status: draft
Owner: Asa
Basis: 2026-10-27 设备接入简化讨论；[Baton R-01、R-02、R-13](../baton/PRODUCT.md)；[发布行为规格](../release/PRODUCT.md)。

## Summary

员工接入设备时，需要自己下载安装包、导入中心的私有 CA、复制注册凭据，再让 `batond up` 一直在前台运行，任何一步出错设备都连不上。本规格让中心托管安装包：个人电脑安装桌面客户端，登录后点一下即可接入；Linux 与远程机器下载由中心写好部署配置的 CLI 安装包，注册后安装为用户服务。

例：员工在 Mac 上打开中心网页，下载客户端并安装，回到网页点「在客户端中打开」，在客户端里登录后点「接入这台电脑」，设备出现在 Devices 页面并保持在线；重启电脑后自动重连。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 部署配置 | 中心对外地址和中心 TLS 证书的 CA，均为公开信息，不含账号、凭据或员工数据 |
| 通用安装包 | 构建产出的安装包，不含任何中心的部署配置 |
| CLI 安装包 | 中心在下载时加入部署配置的 batond 安装包，适用于 macOS 与 Linux 终端用户和远程机器 |
| 桌面客户端 | 内含 batond 的个人电脑应用，加载中心网页并管理本机 batond；安装包为通用包 |
| 接入链接 | 中心网页生成的 `baton://` 链接，向桌面客户端传递部署配置 |
| 用户服务 | 以当前系统用户身份、在用户登录后运行的后台服务，无需管理员权限 |

桌面客户端支持 macOS arm64 与 Windows x64，只连接一个中心；客户端更新和签名限制见 [桌面客户端行为规格](../desktop/PRODUCT.md)。CLI 的用户服务支持 macOS 与 Linux；Windows 个人电脑可使用桌面客户端。系统级服务、需要管理员权限的安装、包管理器分发和 Linux 桌面客户端不在本期范围。

## Behavior

### 中心托管下载

- DS-01：管理员为中心配置安装包目录和 CA 后，网页对员工显示下载入口，列出 macOS 与 Linux 的 CLI 安装包和桌面客户端，以及各自的文件大小、版本和 SHA-256；Windows 只提供桌面客户端。下载无需登录。未配置时不显示入口，注册流程与现状相同。
- DS-02：中心原样提供已发布的 CLI 归档，网页显示的 SHA-256 与实际下载内容一致；中心地址和 CA 通过接入链接或显式参数单独传递。
- DS-03：安装包目录中只有版本被当前中心接受的安装包会出现在下载入口；不被接受、文件不全或校验值不符的安装包不提供下载，并在中心日志中说明原因。
- DS-04：桌面客户端以通用安装包原样提供，中心不修改其内容。

### CLI 安装包与 batond

- DS-05：首次注册时，未显式传入中心地址和 CA 的 `batond up` 与 `batond register` 使用安装目录中的部署配置。显式参数优先于部署配置。两者都没有时，与现状相同，要求提供中心地址。
- DS-06：注册或重新认证成功后，设备把本次使用的 CA 保存在私有数据目录。之后 `up`、`run`、`reauth` 和设备更新使用保存的 CA；注册或重新认证显式传入新 CA 并成功后替换。未使用 CA 的设备继续按系统信任连接。
- DS-07：已有设备身份时，中心地址与 CA 以设备已保存的为准；换用另一个安装包、或安装包的部署配置与已保存值不同，都不改变已注册设备连接的中心。
- DS-08：`batond service install` 在 macOS 安装 launchd 用户代理，在 Linux 安装 systemd 用户单元。服务使用当前安装路径和数据目录运行 batond，在用户登录后启动，异常退出后自动重启，标准输出与错误写入数据目录下的日志文件。设备尚未注册时拒绝安装并提示先注册。
- DS-09：服务使用固定启动入口；设备更新通过版本指针切换程序。`service uninstall` 停止并移除服务，保留数据目录。`service status` 显示服务是否安装、是否运行、程序路径与日志位置。
- DS-10：Linux 用户会话不可用、systemd 用户实例不存在或系统不受支持时，`service install` 失败并说明原因，不留下半写入的服务定义。Windows 上提示使用桌面客户端。服务安装后若用户退出登录时服务随之停止，`service status` 说明需要管理员为该用户开启 linger。
- DS-11：服务已在运行时，在同一数据目录再执行 `batond up` 或 `run`，按现有数据目录锁拒绝启动第二个 daemon，提示服务正在运行。

### 网页

- DS-12：在普通浏览器中打开注册对话框时，选择 macOS 或 Linux 后，对话框给出对应平台 CLI 安装包的下载链接与 SHA-256，以及解压后依次执行的注册与服务安装命令。命令中不包含中心地址和 CA，注册凭据仍通过隐藏输入交给 batond，不出现在命令参数和 shell 历史里。选择 Windows 时引导下载桌面客户端。
- DS-13：中心配置了下载时，普通浏览器中的网页提供「在客户端中打开」，打开接入链接。
- DS-14：网页在桌面客户端中打开时，注册对话框不显示命令。本机尚未接入时，Devices 页面显示「接入这台电脑」；本机设备闲置过期时显示「重新认证这台电脑」。

### 桌面客户端

- DS-15：客户端首次启动且没有部署配置时，显示说明页：先在浏览器打开中心网页，点击「在客户端中打开」。客户端收到接入链接后显示中心地址和 CA 指纹，员工确认后才保存并打开中心登录页；取消则不保存任何内容。
- DS-16：已保存部署配置后收到指向其他中心的接入链接时，本机未接入则经确认后替换；本机已有设备身份则拒绝替换，并说明本机已接入的中心。接入链接内容不完整或证书无法解析时，显示错误，原配置不变。
- DS-17：客户端只对已保存的中心地址使用保存的 CA，其他站点按系统信任处理。中心网页中指向其他站点的链接在系统浏览器打开。只有来自已保存中心地址的页面能请求接入或重新认证本机。
- DS-18：员工点击「接入这台电脑」后，网页以当前员工身份领取注册凭据交给客户端，客户端用内置 batond 完成注册并启动 daemon；凭据不在页面显示，也不写入日志。显示名默认使用主机名，可在接入前修改。注册失败时显示原因，可以重试；凭据过期时重新领取。重新认证使用同样流程，保留原设备与 Thread。
- DS-19：本机已有同一中心的设备身份时（例如曾用 CLI 注册），客户端直接沿用并启动 batond，不产生第二台设备。身份属于其他中心时，客户端不覆盖，并说明冲突。本机已有 daemon 在使用该数据目录（例如 CLI 用户服务）时，客户端不再启动 daemon，并显示设备由外部服务运行。
- DS-20：客户端运行期间保持 batond 运行；batond 异常退出后自动重启，连续失败时停止重启并显示最后的错误。关闭窗口时客户端留在托盘，设备保持在线；选择退出时正常停止 batond 后退出，设备随后显示离线。
- DS-21：客户端默认在用户登录后自动启动并隐藏窗口，托盘菜单可以关闭或重新开启此行为。
- DS-22：托盘显示设备状态，包括未接入、连接中、在线、已拒绝（附原因，例如版本不兼容或凭据过期）；托盘菜单提供打开窗口、重启 batond、打开日志目录和退出。
- DS-23：员工下载新版本客户端替换旧版本后，客户端沿用原部署配置、设备身份和数据目录。中心以版本不兼容拒绝连接时，托盘与窗口提示从中心下载新版客户端。客户端的更新与数据迁移见 [桌面客户端行为规格](../desktop/PRODUCT.md#更新与数据迁移)。

## 验收

| 场景 | 设置与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| CLI 首次接入 | 中心配置下载；在未信任中心 CA 的 Linux 机器上，按注册对话框下载、解压、注册、安装服务 | 不传中心地址和 `--ca-file` 即注册成功；设备在线；注销重新登录或重启后自动重连 | DS-02、DS-05、DS-06、DS-08、DS-12 |
| 下载一致性 | 同一版本连续下载两次；替换目录中某个安装包使其校验值不符 | 两次文件字节相同且与网页 SHA-256 一致；不符的安装包不出现在下载入口 | DS-02、DS-03 |
| CA 保存与替换 | 注册后不带 `--ca-file` 运行；再带另一张有效 CA 重新认证 | 第一次使用保存的 CA 连接；重新认证成功后保存的 CA 被替换 | DS-06 |
| 已有身份不被改写 | 已注册设备换用部署配置不同的 CLI 安装包启动 | 仍连接原中心，原身份与保存的 CA 不变 | DS-07 |
| 服务切换与失败 | 更新后使用固定服务入口；在无 systemd 用户实例的 Linux 上安装服务 | 固定入口启动目标版本；失败时说明原因且没有残留服务定义 | DS-09、DS-10 |
| 重复 daemon | 服务运行中再执行 `batond up` | 拒绝启动并提示服务正在运行 | DS-11 |
| 客户端接入 | macOS arm64 与 Windows x64 全新环境：安装客户端，经接入链接确认中心，登录后点「接入这台电脑」 | 无需终端和系统证书导入即在线；页面与日志中没有注册凭据 | DS-13～DS-18 |
| 接入链接安全 | 取消确认；本机已接入后打开其他中心的链接；其他站点页面尝试请求接入 | 取消不保存；已接入时拒绝替换；非中心页面无法触发接入 | DS-15～DS-17 |
| 沿用 CLI 身份 | 先用 CLI 注册并运行服务，再安装客户端 | 客户端显示设备由外部服务运行，不启动第二个 daemon，不新增设备 | DS-19 |
| 常驻与退出 | 关闭窗口；结束 batond 进程；托盘退出；重启系统 | 关窗后保持在线；batond 自动重启；退出后显示离线；登录后自动启动并重连 | DS-20、DS-21 |
| 版本拒绝提示 | 中心升级后用旧版客户端连接 | 托盘显示版本不兼容并提示下载新版 | DS-22、DS-23 |

自动化验收使用本地中心、本地 CA 与进程替身，不访问外部服务。launchd、systemd 用户实例与桌面客户端的系统集成在对应系统上手动验证，未测的平台如实记录。

## Open questions

- 远程 Linux 机器在用户未登录时是否需要保持在线。需要的话，要由管理员开启 linger 或安装系统级服务，后者超出本期范围。不阻塞本规格。
