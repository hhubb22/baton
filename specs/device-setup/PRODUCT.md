# 设备接入行为规格

Status: partially implemented
Owner: Asa
Basis: 设备连接与本机控制面简化对齐；[Baton R-01～R-04](../baton/PRODUCT.md)；[发布行为规格](../release/PRODUCT.md)。

设备码认证、长效可吊销凭据、CLI 本地控制通道与按需拉起、网页确认页和用户服务接管已实现。桌面客户端仍使用现有接入桥接与进程监管，尚未迁移至本地控制通道；Thread 和 Execution 继续使用独立 Worker。原生 launchd、systemd 用户会话、Windows 命名管道及桌面接入需在目标系统验证。

## Summary

员工通过统一的设备码登录（Device Code Flow）将个人电脑或远程 Linux 机器绑定到自己的 Baton 账号：在终端运行一条登录命令，或在桌面客户端点击「连接这台电脑」，随后在已登录的浏览器中点击确认即可上线，全程无需导入私有证书、复制一次性口令或手动协调多个守护进程。

每台设备在同一数据目录下只运行一个后台 `batond` 守护进程，对外暴露受保护的本地控制通道；CLI 与桌面客户端均作为该通道的客户端，并在守护进程未运行时按需在后台拉起它。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 中心地址 | 中心公开的标准 HTTPS 地址，使用操作系统根证书库信任的 TLS 证书 |
| 设备码登录 | 设备向中心申请短期登录会话，展示验证网址与短验证码；已登录员工在网页确认后，设备换取长效连接凭据 |
| 本机守护进程 | 单一数据目录下唯一运行的后台 `batond` 进程，负责维持中心连接、管理本机状态与调度 Agent 执行 |
| 本地控制通道 | `batond` 对本机当前系统用户暴露的受保护 IPC 通道；CLI 与桌面客户端均通过它查询状态与发起控制操作 |
| 按需拉起 | CLI 或桌面客户端连接本地控制通道发现 `batond` 未运行时，自动在后台启动 `batond`，再作为客户端与之通信 |
| 用户服务 | 以当前系统用户身份、在用户登录后自动运行的后台服务（macOS launchd / Linux systemd 用户单元），无需管理员权限 |
| 桌面客户端 | 内含 `batond` 的 macOS arm64 与 Windows x64 应用，加载已保存中心的网页并通过本地控制通道协作 |
| 接入链接 | 中心网页生成的 `baton://connect?url=<HTTPS 源>` 链接，仅用于向桌面客户端传递中心地址，不含证书或秘密 |

桌面客户端支持 macOS arm64 与 Windows x64，同一时刻只连接一个中心。CLI 用户服务支持 macOS 与 Linux；Windows 使用桌面客户端或按需后台守护进程。应用层私有 CA 分发、一次性环境变量注册口令、系统级 root 服务、包管理器分发、应用内自动热更新和 Linux 桌面客户端不在本期范围。

## Behavior

### 中心安装包下载

- DS-01：管理员为中心配置安装包目录后，中心网页与匿名下载清单列出可用的 macOS / Linux CLI 安装包和 macOS / Windows 桌面客户端安装包，展示各自版本、大小和 SHA-256；Windows 仅展示桌面客户端。未配置目录时不展示下载入口。
- DS-02：中心原样提供与当前中心版本一致且 SHA-256 校验通过的安装包；版本不符、文件缺失或摘要不一致的安装包不进入清单，并在中心日志记录原因。
- DS-03：中心启用安装包下载时，普通浏览器中的网页提供「在客户端中打开」入口，通过 `baton://connect?url=<中心 HTTPS 源>` 向桌面客户端传递当前中心地址。

### 设备码登录与身份绑定

- DS-04：员工在未绑定的设备上执行 `batond login --coordinator <中心 HTTPS 地址>`（或在桌面客户端点击「连接这台电脑」），本机守护进程向中心发起设备码登录会话，返回并展示验证网址、短验证码与剩余有效期；具备图形环境时自动打开系统浏览器。设备显示名默认取主机名，支持在发起时指定。
- DS-05：已登录员工在浏览器打开验证页面，核对短验证码、设备显示名与系统类型后点击确认；中心创建设备记录并绑定当前员工，本机守护进程轮询换取长效可吊销的连接凭据，持久保存中心地址与设备身份并立即连接上线。设备码会话默认 10 分钟有效且单次消费；过期、拒绝或取消后不可换取凭据，员工可重新发起。
- DS-06：本机已保存同一中心的有效设备身份时，再次执行 `batond login` 或点击连接直接复用原身份并确保守护进程在线，不重复注册新设备。本机已有其他中心的绑定身份，或当前凭据已被中心吊销时，拒绝静默覆盖并提示先执行 `batond logout`（或在客户端解除本机绑定）清除旧身份后再重新登录。
- DS-07：中心与设备的所有 HTTPS / WSS 通信均使用系统根证书库验证 TLS 证书，不读取或保存自定义私有 CA。

### 本机守护进程、本地控制通道与用户服务

- DS-08：每个数据目录同时最多运行一个 `batond` 守护进程，并监听仅当前系统用户可访问的本地控制通道。CLI 命令与桌面客户端统一通过该通道查询状态、发起登录/登出、重启或停止守护进程；检测到守护进程未运行时自动在后台拉起，不产生双主管锁竞争。
- DS-09：`batond status` 与桌面客户端通过本地控制通道实时获取守护进程状态与中心连接状态（未绑定、等待网页确认、连接中、同步中、在线、已拒绝）及具体原因。中心以「协议版本不兼容」或「凭据已吊销」拒绝连接时，守护进程停止自动重连并保留拒绝原因，提示员工更新安装包或重新绑定。
- DS-10：`batond service install` 在 macOS 安装 launchd 用户代理，在 Linux 安装 systemd 用户单元，使 `batond` 在用户登录后自启、异常退出后自动重启。`service uninstall` 停止服务并移除服务定义，保留数据目录中的身份与本地数据；`service status` 显示服务安装状态、运行状态、程序路径与日志路径。
- DS-11：Linux 用户会话缺少可用的 `systemd --user` 实例时，`service install` 失败并说明原因，不留下半写入的服务定义；未开启 `linger` 时，`service status` 说明用户注销后后台服务会随之停止。Windows 执行 `service` 子命令时明确提示改用桌面客户端。

### 网页与桌面客户端接入

- DS-12：普通浏览器的添加设备弹窗按所选系统展示对应安装包下载链接与 SHA-256，以及简洁的终端登录与服务安装命令（`batond login --coordinator <中心地址>` 与 `batond service install`），不生成或展示任何注册口令；选择 Windows 时引导下载桌面客户端。
- DS-13：桌面客户端首次启动且尚未配置中心地址时，显示本地接入说明页：支持直接输入中心 HTTPS 地址，或通过浏览器的「在客户端中打开」接入链接传入地址并经员工确认后保存；非 HTTPS 地址或格式无效时拒绝保存并提示原因。
- DS-14：桌面客户端已保存中心地址后收到指向另一中心的接入链接时：若本机尚未绑定设备，经员工确认后替换中心地址；若本机已绑定原中心设备，拒绝替换并说明已绑定的中心。中心网页内指向其他站点的链接一律在系统默认浏览器中打开。
- DS-15：桌面客户端加载已保存中心的网页，并通过本地控制通道连接（未运行时自动拉起）本机 `batond`。本机尚未绑定时，Devices 页面显示「连接这台电脑」；点击后客户端经本地控制通道发起设备码登录，并在窗口内打开确认流程，员工点击确认即完成绑定上线，页面与日志中不暴露任何连接秘密。
- DS-16：桌面客户端关闭窗口时隐藏到系统托盘，保持本机在线；默认开启系统登录后自动启动并隐藏窗口，可在托盘菜单切换。托盘显示本机连接状态及拒绝原因，菜单提供打开窗口、重启 `batond`、打开日志目录和退出。
- DS-17：员工从托盘选择「退出」时：若本机未安装 CLI 用户服务，客户端经本地控制通道通知 `batond` 正常停止后再退出，设备随之显示离线；若本机已安装用户服务，客户端仅退出自身窗口与托盘，后台服务保持在线。覆盖安装新版桌面客户端后，原中心地址、设备身份和数据目录继续保留。

## 验收

| 场景 | 设置与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| CLI 设备码接入 | 全新 Linux / macOS 环境下载 CLI 包，执行 `batond login --coordinator <地址>`，在已登录浏览器中确认短码，再执行 `batond service install` | 无需复制口令或配置证书即绑定上线；注销重登或重启系统后自动重连且设备 ID 不变 | DS-01、DS-04、DS-05、DS-07、DS-10、DS-12 |
| 过期与重复绑定保护 | 设备码放任过期后尝试确认；已在中心 A 绑定的设备直接对中心 B 执行 `batond login` | 过期会话被拒绝且可重新发起；跨中心登录被拒绝并提示先 `batond logout`，原身份不被覆盖 | DS-05、DS-06 |
| 按需拉起与单一守护进程 | 停止后台 `batond` 后分别执行 `batond status` 和打开桌面客户端；同时使用 CLI 与桌面客户端查看状态 | 首次访问自动拉起唯一的后台 `batond`；两边看到一致的实时状态，无锁冲突报错 | DS-08、DS-09 |
| 桌面客户端一键接入 | 全新 macOS arm64 / Windows x64 安装客户端，输入中心地址或点击「在客户端中打开」，登录后点「连接这台电脑」并确认 | 无需打开终端即完成绑定上线；外部域名链接在系统浏览器打开 | DS-03、DS-13～DS-15 |
| 常驻、服务协同与退出 | 关闭客户端窗口；分别在未安装和已安装 CLI 用户服务时从托盘点击「退出」 | 关窗后保持在线；未装服务时退出客户端使 `batond` 正常停止并离线；已装服务时退出客户端后设备仍保持在线 | DS-10、DS-16、DS-17 |
| 终止类拒绝停止重连 | 员工在网页吊销本机设备，或中心升级到不兼容协议版本 | `batond` 停止重连循环，CLI `status`、托盘与网页准确显示已吊销或版本不兼容原因及恢复指引 | DS-09、DS-16、DS-17 |

自动化验收使用本地中心与受控本地传输，不依赖外部在线服务。launchd、systemd 用户实例与桌面客户端的原生托盘、自启及协议唤起在目标操作系统上手动验证并如实记录未测平台。
