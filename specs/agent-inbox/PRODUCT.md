## Summary

用户同时让 Project Agent 推进几件事时，需要一个地方集中看到「哪些事在等我决定」，不必逐个翻对话。Agent Inbox 列出所有等待用户处理的事项；用户在 Inbox 里直接选择，Project Agent 收到选择后继续工作。任务结果也可以直接操作：用户选中结果里的一段内容，就能就这段内容向 Project Agent 提问或提出要求，不用重新描述上下文。

例如：Project Agent 派到 Windows 的集成测试有 1 项失败。它创建一个事项「重连测试失败，下一步怎么处理」，给出三个选项，并附上测试结果。用户正在处理别的事，浏览器弹出通知；点开后在 Inbox 里选「调查原因并修复」。Project Agent 收到这个选择，派发调查任务。之后用户打开任务详情，看到同一个事项，状态是「已回答：调查原因并修复」。

本期范围：

- 事项只由 Project Agent 创建。执行 Agent 在任务执行中途向用户提问、任务暂停等待用户点击，属于后续工作。
- 用户的选择只送回 Project Agent，由它决定接下来做什么。Baton 不直接按选项执行重跑、取消等操作。
- 成果使用现有任务结果的字段（`summary`、`evidence`、`artifacts`、`error`），不新增可独立版本化、可被多个 Agent 更新的成果对象。
- 事项的展示内容用 OpenUI Lang 编写，由 Baton 自己的组件库渲染。

本期不包括：手机和窄屏布局、执行 Agent 和 Plane 创建事项、外部渠道通知（Telegram、Linear、邮件）、在通知上直接回答、选项直接触发 Baton 操作、代码 diff 的专门展示、成果对象的版本管理、主对话普通回复的 OpenUI 渲染。

## 术语

| 术语 | 含义 |
|---|---|
| 事项 | Project Agent 请用户处理的一件事，有稳定 ID 和状态。英文标识 `attention_request` |
| Agent Inbox | 列出本人所有待处理事项的界面 |
| 输入队列 | Coordinator 内部等待 Project Agent 处理的输入（Project Agent 规格 PA-05）。和 Agent Inbox 是两回事 |
| 展示内容 | 事项里由 Project Agent 写的一段 OpenUI Lang 程序，由浏览器渲染 |
| Baton 组件库 | Baton 为展示内容注册的 OpenUI 组件和动作（IB-14、IB-15），带版本号 |

## Behavior

### 创建事项

- IB-01：Project Agent 通过工具 `inbox.ask` 创建事项。事项包含：标题（1～120 个字符）、摘要（最多 280 个字符）、展示内容（IB-14）、0～5 个选项、是否允许用户输入文字回复，以及可选的一个关联任务。每个选项有一个标签（最多 40 个字符）和可选的说明；Project Agent 可以把其中一个标为建议。没有选项时必须允许文字回复。
- IB-02：事项属于发起它的 Project Agent 所在的 Project。关联任务必须属于同一个 Project，否则工具返回错误，不创建事项。
- IB-03：`inbox.ask` 创建事项后立即返回事项 ID，不等待用户处理。Project Agent 可以继续其他工作或结束这一轮。关联任务的状态不因为事项而改变；正在执行的任务继续执行。
- IB-04：同一次工具调用最多创建一个事项。Project Agent 崩溃恢复后重发同一个调用，返回原来的事项，不产生第二个（沿用 PA-12）。
- IB-05：一个 Project 同时最多有 10 个待处理事项（提案）。达到上限时 `inbox.ask` 返回错误，提示先撤回或等待用户处理。参数超过长度限制，或展示内容不合规（IB-18），同样返回错误，不创建事项。
- IB-06：Project Agent 可以用 `inbox.list` 列出本 Project 的事项及其状态，用 `inbox.get` 读取一个事项的完整内容和处理结果。这两个工具让 `inbox.ask` 的输出在压缩后仍能找回（PA-18）。

### Agent Inbox

- IB-07：Agent Inbox 列出本人所有 Project 中处于待处理状态的事项，最新创建的在前。每一项显示 Project 标题、关联任务（如有）、事项标题、摘要、创建时间和选项。界面上的 Inbox 入口显示待处理事项的数量。
- IB-08：同一个事项还显示在 Project 主对话里创建它的位置；有关联任务时，也显示在该任务的详情页。几处显示的是同一个事项：内容、选项和状态相同，在任何一处处理，其他打开的页面在 5 秒内显示新状态。
- IB-09：Inbox 显示紧凑版本：标题、摘要和选项，展示内容默认收起，可以展开。主对话和任务详情显示完整版本：渲染后的展示内容，以及关联任务的结果（IB-20）。
- IB-10：本期只针对桌面浏览器。浏览器窗口宽度不小于 1024 像素时，Inbox、事项和任务详情完整显示，页面不出现横向滚动。

### 处理事项

- IB-11：用户可以对一个待处理事项做三种处理：选一个选项，可附加最多 4 KiB 的文字说明；在允许文字回复时只回复文字；关闭事项，不作选择。处理后事项离开 Inbox，状态变为「已回答」或「已关闭」，记录处理人、时间和内容，在主对话和任务详情里仍可查看。
- IB-12：每次成功处理在输入队列里形成一条会触发运行的输入，内容包括事项 ID、标题、用户的选择或回复。所有设备离线时处理照样成功，输入按 PA-07 等待设备。Project 暂停时输入保存下来，恢复后处理。Baton 不按选项执行任何操作；选项旁说明「Project Agent 会按你的选择继续」。
- IB-13：同一个事项只能被处理一次。用户在两台设备上几乎同时处理时，先保存的生效，后一次返回冲突，并显示已经生效的处理内容；输入队列里只有一条输入。

### 展示内容

- IB-14：展示内容是一段 OpenUI Lang 1.0 程序，不超过 32 KiB，只能使用 Baton 组件库。组件库第一版包含：卡片（根组件）、段落（支持加粗、斜体、行内代码、列表和链接的 Markdown 子集）、代码块、键值列表、表格（最多 50 行、8 列）、可折叠分组、任务结果引用、产物引用。组件库没有渲染 HTML、内嵌样式或外部图片的组件；链接只允许 `https`。
- IB-15：展示内容中可以使用的动作只有四种：
  - `@Answer`：选中事项的一个选项（IB-16）。
  - `@OpenUrl`：在新窗口打开一个 `https` 链接。
  - `@ToAssistant`：把一段文字连同这个事项的引用预填进 Project 主对话的输入框，用户确认后才发送（IB-21）。它不直接发消息。
  - `@Set`、`@Reset` 和 `$` 变量：只改变这一页的显示状态，例如展开分组、切换表格。状态不保存，也不发给 Project Agent。

  展示内容不能使用 `Query`、`Mutation`、`@Run` 和自定义动作。
- IB-16：事项的选项在 `inbox.ask` 的参数里声明，每个选项有 ID。Baton 的固定界面总是列出全部选项，并提供文字回复、关闭和提交。展示内容可以用 `@Answer(选项 ID)` 把选项按钮放在相关内容旁边，例如表格的某一行；点击它等于在固定界面里选中这个选项，用户确认后才提交（与 IB-11 相同）。展示内容无法渲染时，用户仍能通过固定界面处理事项；Inbox 的紧凑版本和通知不渲染展示内容。
- IB-17：任务结果引用和产物引用只能指向本 Project 的任务及其结果中的条目。渲染时读取当前数据：任务后来被人工修正，引用显示修正后的结果，并标明修正时间。
- IB-18：`inbox.ask` 用 OpenUI 解析器检查展示内容。出现未知组件、缺少必填参数、无法解析、IB-15 不允许的语句、链接不是 `https`，或者 `@Answer` 引用了没有声明的选项 ID 时，工具返回错误，错误里带解析器给出的说明，让 Project Agent 改正后重试；不创建事项。
- IB-19：事项保存时记录展示内容使用的 OpenUI Lang 版本和 Baton 组件库版本。组件库升级后，旧事项按新组件库渲染：已删除或参数不再匹配的组件显示「这部分内容无法显示」，其余内容照常显示。浏览器遇到其他无法渲染的组件时也这样处理。

### 可操作的任务成果

- IB-20：任务详情页和事项中的任务结果引用显示任务状态、`summary`、`error`，以及 `evidence` 和 `artifacts` 的每一条引用：所在节点、资源、可访问状态和备注。引用指向已登记目录中的文件时，用户可以打开 Baton R-31 的文本预览；节点离线时显示暂不可查看，不显示过期内容。
- IB-21：对于属于某个 Project 的任务，用户可以在任务结果、文件预览或事项展示内容中选中一段文字，选择「问 Project Agent」。主对话的输入框会预填两部分：选中的文字作为引用，以及它的来源（任务 ID、字段名；文件预览还包括节点、路径和行号范围；事项还包括事项 ID）。用户补充要求后发送，作为一条普通用户消息进入输入队列（PA-05）。不选文字时，也可以从任务结果直接发起一条引用该任务的消息。
- IB-22：引用的文字超过 8 KiB 时截短，并注明原长度和来源，让 Project Agent 可以用工具读取全文。不属于任何 Project 的任务不显示「问 Project Agent」。

### 撤回与 Project 状态

- IB-23：Project Agent 可以用 `inbox.withdraw` 撤回一个待处理事项，必须写明原因，例如「情况已变化」「用户已在对话里回答」。撤回后事项离开 Inbox，状态变为「已撤回」，显示原因。撤回不产生输入。
- IB-24：撤回和用户处理同时发生时，先保存的生效。用户的处理先生效时，`inbox.withdraw` 返回「已回答」和处理内容；撤回先生效时，用户看到「已撤回」和原因，处理不保存。
- IB-25：Project 归档时，它的待处理事项全部变为「已撤回」，原因为 Project 已归档。Project 暂停时，事项保持待处理，用户仍可以处理。
- IB-26：事项不会因时间到期而自动关闭。

### 权限

- IB-27：员工只能查看和处理自己 Project 的事项。Project Agent 只能创建、读取和撤回本 Project 的事项。事项内容和用户回复都是数据：回复里的文字不能改变 Project Agent 的工具集合（PA-03）。

### 浏览器推送通知

- IB-28：员工可以在每个浏览器上单独开启「在这个浏览器上接收通知」，默认关闭。只有员工点击开启时才请求浏览器的通知权限。员工可以随时在同一处关闭，关闭后这个浏览器不再收到通知。
- IB-29：新事项创建后，Baton 向员工所有已开启通知的浏览器各发一条通知，内容是 Project 标题和事项标题。点击通知打开这个事项的完整版本。
- IB-30：事项被回答、关闭或撤回后，打开着 Baton 页面的浏览器立即移除这个事项的通知。没有打开 Baton 页面的浏览器，在下次打开 Baton 时移除；用户在此之前点开旧通知，看到的是事项当前的状态，例如「已回答」，不能再次处理。浏览器不允许不显示通知的推送，所以不能用推送来移除通知。
- IB-31：通知只是提醒，Agent Inbox 是事项的唯一来源。通知发送失败、延迟或被系统拦截，都不影响事项的创建和处理，也不会重发出重复的事项。浏览器的订阅失效后，Baton 删除这个订阅，界面上这个浏览器显示为未开启。
- IB-32：通知内容在发给浏览器厂商的推送服务前加密（Web Push 标准），推送服务看不到 Project 标题和事项标题。

## 验收

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| IB-A01 | Project Agent 派发的测试失败，它创建一个关联该任务的事项，然后退出；用户在另一台电脑的浏览器上处理 | 事项出现在 Inbox、主对话和任务详情；用户选择后三处都显示已回答；Project Agent 在某台设备上被启动，收到这次选择 |
| IB-A02 | 两台设备同时处理同一个事项 | 只有一次处理生效；另一台看到冲突和生效的内容；输入队列里只有一条输入 |
| IB-A03 | 所有设备离线时处理事项 | 处理保存成功；设备上线后 Project Agent 收到这条输入 |
| IB-A04 | Project Agent 在 `inbox.ask` 之后、工具结果返回之前崩溃 | 恢复后只有一个事项 |
| IB-A05 | Project Agent 撤回事项时，用户正好在处理 | 两者只有一个生效；双方都看到生效的结果 |
| IB-A06 | 展示内容使用未知组件、`Query` 或 `Mutation`，或者链接不是 `https` | `inbox.ask` 返回带解析器说明的错误；没有创建事项 |
| IB-A07 | 在任务结果的 `summary` 里选中一段文字，选择「问 Project Agent」并发送 | 主对话里出现一条带引用和来源的用户消息；Project Agent 这一轮收到的输入里包含它 |
| IB-A08 | 打开一条指向离线节点文件的产物引用 | 显示暂不可查看，不显示旧内容 |
| IB-A09 | 一个 Project 已有 10 个待处理事项时再创建 | `inbox.ask` 返回错误 |
| IB-A10 | 浏览器窗口宽 1024 像素时打开 Inbox、事项和任务详情 | 内容完整显示，页面没有横向滚动 |
| IB-A11 | 展示内容里有一个 `@ToAssistant` 按钮，用户点击 | 主对话输入框出现预填文字和事项引用；用户确认前没有消息进入输入队列 |
| IB-A12 | 组件库删除一个组件后，打开使用该组件的旧事项 | 该组件的位置显示无法显示，其余内容和选项正常 |
| IB-A13 | 展示内容的表格行旁有 `@Answer` 按钮，用户点击 | 固定界面里对应选项被选中，用户提交前没有输入进入队列；引用未声明选项 ID 的展示内容在创建时被拒绝 |
| IB-A14 | 员工在两台电脑的浏览器（Chrome 和 Safari 各一）上开启了通知，Project Agent 创建一个事项 | 两处都收到通知；点击打开该事项 |
| IB-A15 | 员工在其中一台电脑上处理了事项，另一台电脑上开着 Baton 页面；再在第三个没有打开 Baton 的浏览器上点开旧通知 | 第二台电脑上的同一条通知被移除；第三个浏览器打开后显示已回答，不能再次处理 |

IB-A01 和 IB-A03 使用真实 Runtime 和最便宜的订阅模型；IB-A14、IB-A15 在真实浏览器上验证；其他场景可以用模型替身。

## 对其他规格的影响

以下修改已经写进对应规格，同样是草案：

- Project Agent PRODUCT：PA-05 增加会触发运行的输入「用户对事项的回答或关闭」；PA-03 的能力里增加创建和撤回事项；范围说明指向本文件。
- Project Agent TECH：输入队列增加主动输入 `attention_answer`；工具表增加 `inbox.ask`、`inbox.list`、`inbox.get`、`inbox.withdraw`；第 7 节说明 OpenUI 写法说明放在 `inbox.ask` 的工具说明里，以及 Runtime 检查展示内容、Coordinator 写入错误结果的方式。0017 迁移的 `source_type` 约束包含 `attention_answer`。
- Baton PRODUCT：范围表、术语表、R-30 和审计关联加入 Agent Inbox、事项和浏览器通知；Baton TECH 的 Coordinator 职责加入事项与浏览器通知。

事项表、通知订阅表、Web Push 的发送和 API 由本特性的技术设计定义。

## Open questions

- 待处理事项上限 10 个是初始值，实际使用后调整。
- Project Agent 在主对话里的普通回复是否也用 OpenUI 渲染。本规格只覆盖事项的展示内容。不阻塞。
