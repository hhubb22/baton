# Agent Inbox 行为规格

Status: approved
Owner: Asa
Basis: [Project Agent 行为规格](../project-agent/PRODUCT.md)；[Baton 行为规格](../baton/PRODUCT.md)。

## Summary

用户同时让 Project Agent 推进几件事时，需要一个地方集中看到「哪些事在等我决定」，不必逐个翻对话。Agent Inbox 列出所有等待用户处理的事项；用户直接选择，Project Agent 收到选择后继续工作。

例如：Project Agent 在 Windows 上开的 Codex Thread 报告重连测试有 1 项没通过。它创建一个事项「1 项测试没通过，下一步怎么做？」，给出三个选项。用户打开 Inbox，选「找出原因并修好」。Project Agent 收到这个选择，在同一个 Thread 里让 Codex 继续排查。

本期范围：

- 事项由 Project Agent 创建，或由 Baton 在确定的系统条件下创建（IB-18）。
- 用户的选择只送回 Project Agent，由它决定接下来做什么。Baton 不按选项执行任何操作。
- Baton 不主动推送通知，用户自己打开 Inbox 查看。

本期不包括：手机和窄屏布局、执行 Agent 和 Plane 创建事项、浏览器推送和外部渠道通知、选项直接触发 Baton 操作、用组件语言渲染展示内容。

## Behavior

### 创建事项

- IB-01：Project Agent 通过工具 `inbox.ask` 创建事项。事项包含：标题（1～120 个字符）、展示内容（IB-07）、0～50 个选项（推荐不超过 5 个，选项 JSON 总计不超过 16 KiB）、是否允许文字回复，以及可选的一个关联 Thread。每个选项有一个标签（最多 40 个字符）；Project Agent 可以把其中一个标为建议。没有选项时必须允许文字回复。
- IB-02：事项属于发起它的 Project Agent 所在的 Project。关联 Thread 必须属于同一个 Project，否则工具返回错误，不创建事项。
- IB-03：`inbox.ask` 创建后立即返回事项 ID，不等待用户处理，也不改变关联 Thread 的状态。同一次工具调用最多创建一个事项；Project Agent 崩溃恢复后重发同一个调用，返回原来的事项。
- IB-04：同一个 Project 达到 10 个由 Project Agent 创建的待处理事项时，界面提示整理已有问题，仍允许创建。标题、正文、选项、文字回复设置与关联 Thread 均相同的未处理事项复用已有记录；已处理事项不参与内容去重。参数超长或展示内容不合规时，`inbox.ask` 返回错误，不创建事项。
- IB-05：Project Agent 可以用 `inbox.list` 列出本 Project 的事项及其状态，用 `inbox.get` 读取一个事项的完整内容和处理结果。

### 显示

- IB-06：Agent Inbox 列出本人所有 Project 中待处理的事项，最新的在前。每一项显示 Project、标题和选项；系统事项标明由 Baton 创建。Inbox 入口和浏览器标签页标题显示待处理数量。
- IB-07：展示内容是一段 Markdown，不超过 32 KiB，支持加粗、斜体、行内代码、代码块、列表、表格和 `http`、`https`、`mailto` 链接，不渲染 HTML 和图片，也不自动加载外部资源。危险协议链接被拒绝，普通链接由用户主动点击打开。选项默认显示前 5 个，其余可展开。展示内容在各处默认收起，可以展开。
- IB-08：同一个事项还显示在主对话里创建它的位置；有关联 Thread 时，也显示在该 Thread 里。几处显示的是同一个事项：标题、选项和状态相同，在任何一处处理，其他打开的页面在 5 秒内显示新状态。
- IB-09：本期只针对桌面浏览器。窗口宽度不小于 1024 像素时，Inbox 和事项完整显示，页面不出现横向滚动。

### 处理事项

- IB-10：用户可以对一个待处理事项做三种处理：选一个选项，可附加最多 4 KiB 的文字；在允许文字回复时只回复文字；关闭事项。处理后事项离开 Inbox，状态变为「已回答」或「已关闭」，记录处理人、时间和内容。
- IB-11：每次处理在输入队列里形成一条主动输入，内容包括事项 ID、标题、用户的选择或回复。所有设备离线或 Project 暂停时处理照样成功，输入保存到 Project Agent 下次运行。
- IB-12：同一个事项只能被处理一次。两台设备几乎同时处理时，先保存的生效，后一次返回冲突并显示已生效的内容；输入队列里只有一条输入。

### 问 Project Agent

- IB-13：用户可以在 Thread 回复、文件预览或事项展示内容中选中一段文字，选择「问 Project Agent」。主对话输入框预填选中的文字和来源（Thread ID 和回复位置；文件预览还包括设备、路径和行号范围；事项还包括事项 ID）。用户补充要求后发送，作为一条普通用户消息。引用超过 8 KiB 时截短，并注明原长度和来源。

### 撤回与 Project 状态

- IB-14：Project Agent 可以用 `inbox.withdraw` 撤回一个待处理事项，必须写明原因。撤回后事项离开 Inbox，状态变为「已撤回」，显示原因。撤回不产生输入。
- IB-15：撤回和用户处理同时发生时，先保存的生效，双方都看到生效的结果。
- IB-16：Project 归档时，它的待处理事项全部变为「已撤回」。Project 暂停时，事项保持待处理，用户仍可以处理。事项不会因时间到期而自动关闭。

### 权限

- IB-17：员工只能查看和处理自己 Project 的事项。Project Agent 只能创建、读取和撤回本 Project 的事项；它可以读取系统事项，不能撤回。用户回复里的文字不能改变 Project Agent 的工具集合。

### 系统事项

- IB-18：Project Agent 普通模型请求连续失败第 3 次时（PA-13），Baton 直接创建一个系统提示，不经过 Project Agent。主对话保持 active，自动尝试的间隔降为 15 分钟。新的用户消息立即清除退避，同一消息的幂等重发保留退避。系统提示包含标题、原因和打开 Project 的链接，没有选项，也不接受文字回复。
- IB-19：同一个 Project 最多有一个待处理的系统提示。保存助手回复成功或用户显式 Retry 后，失败计数清零，并将尚未关闭的提示标为「已解决」。用户关闭提示后，同一轮持续失败不重新创建；计数清零后下一轮再次到第 3 次失败才创建新提示。
- IB-20：系统事项的创建、解决和关闭不进入 Project Agent 的输入队列，也不依赖模型调用成功。

## 验收

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| IB-A01 | Project Agent 创建一个关联 Thread 的事项后退出；用户在另一台电脑的浏览器上处理 | 事项出现在 Inbox、主对话和 Thread；处理后三处都显示已回答；Project Agent 被启动，收到这次选择 |
| IB-A02 | 两台设备同时处理同一个事项 | 只有一次处理生效；另一台看到冲突和生效的内容；输入队列里只有一条输入 |
| IB-A03 | 所有设备离线时处理事项 | 处理保存成功；设备上线后 Project Agent 收到这条输入 |
| IB-A04 | Project Agent 在 `inbox.ask` 之后、工具结果返回之前崩溃 | 恢复后只有一个事项 |
| IB-A05 | Project Agent 撤回事项时，用户正好在处理 | 两者只有一个生效；双方都看到生效的结果 |
| IB-A06 | 展示内容超过 32 KiB，或含 `javascript`、`data`、`vbscript` 等危险协议链接 | `inbox.ask` 返回错误；合法 `http`、`https`、`mailto` 链接可创建且仅在用户点击时打开 |
| IB-A07 | 在 Thread 回复里选中一段文字，选择「问 Project Agent」并发送 | 主对话出现一条带引用和来源的用户消息；Project Agent 这一轮收到它 |
| IB-A08 | 一个 Project 已有 10 个待处理事项时再创建 | 新问题可创建并显示整理提示；相同未处理问题复用已有事项 |
| IB-A09 | 窗口宽 1024 像素时打开 Inbox 和事项 | 内容完整显示，没有横向滚动 |
| IB-A10 | 模型替身连续失败 3 次，之后继续失败；关闭提示，再发一条新消息，随后保存助手回复或显式 Retry | 第 3 次失败出现系统提示，主对话保持 active，按 15 分钟退避；关闭后持续失败不重建；新消息清除退避，幂等重发保留退避；保存回复或 Retry 清零失败计数并解决仍未关闭的提示，下一轮再次到 3 次失败可创建新提示；系统提示不产生输入 |

IB-A01 和 IB-A03 使用真实 Runtime、独立进程和本地模型替身验证，自动化测试无需订阅登录或在线推理。真实订阅检查可作为手动补充，不作为开放或发布前提。
