# 发布与升级行为规格

Status: draft
Owner: Asa
Basis: 内部开发阶段打包发布与去热更新简化对齐；[Baton R-23、R-25](../baton/PRODUCT.md)；[发布技术设计](TECH.md)。

## Summary

Baton 发布产出中心运行包与容器镜像、自带运行时的各平台 `batond` CLI 安装包，以及内置 `batond` 的 macOS / Windows 桌面客户端安装包。各组件携带可查询的构建与协议版本身份；中心与设备按协议版本校验连接兼容性，版本升级通过停机替换安装包完成，不内置在线热更新协调器。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 发布产物 | 中心服务包与容器镜像、CLI 安装包（macOS arm64、Linux x64/arm64、Windows x64）、桌面客户端安装包（macOS arm64、Windows x64） |
| 构建身份 | 编译写入的版本号、源码提交、目标平台与协议版本，由中心、`batond`、Agent 宿主和桌面客户端一致报告 |
| 协议兼容 | 中心与设备建立业务连接时按协议版本与能力声明准入，与展示用产品版本号解耦 |
| 停机替换更新 | 停止旧进程或服务后替换安装包/镜像并重新启动，保留兼容的数据目录与设备身份 |

内部开发阶段不提供在线自更新命令（无后台预下载、双版本启动器指针切换或跨账本自动回滚协调器），也不维护旧实验数据格式的兼容分支；多中心滚动升级、自动数据库降级与 macOS Developer ID 公证不在本期范围。

## Behavior

### 构建身份与安装包质量

- RL-01：每个发布版本具有明确的版本号、源码提交、目标平台和协议版本，随附产物 SHA-256 摘要、验证结果及已知平台限制；同一版本号对应固定源码与构建输入。中心、`batond`、Agent 宿主及桌面客户端均能报告自身实际运行版本。
- RL-02：CLI 安装包携带运行所需的完整运行时与依赖目录，目标机器无需预装 Node 或包管理器；桌面客户端安装包内含同版本的完整 `batond`。发布前的隔离安装包检查在空 PATH 与临时用户目录下核验版本身份、本地控制通道、Agent 宿主模块加载、Project Runtime 与私有文件权限，任一检查失败阻止发布。
- RL-03：Windows 进程树回收边界与特定 Linux 发行版的原生辅助程序限制（如低版本 glibc）按实测如实记录；未知系统或 Agent 版本组合按实际安装和认证结果开放能力，不设静态平台白名单。

### 协议准入与停机替换升级

- RL-04：中心与设备按协议版本判断业务连接准入，接收方忽略未知可选字段，新增能力通过显式字段声明；协议版本相同的不同构建版本可以正常通信。
- RL-05：设备的协议版本不被当前中心接受时，中心拒绝建立业务连接并返回明确的协议不兼容错误码；`batond` 停止自动重连并保留该拒绝原因，CLI `status`、桌面客户端托盘与网页提示员工下载并覆盖安装匹配版本的安装包。
- RL-06：管理员升级中心服务时，先停止旧中心写入、备份数据库与节点签名密钥，运行数据库迁移校验通过后再对外提供服务。中心停服期间，设备上已开始的回合继续按本地时限运行并持久保存结果；中心恢复后设备自动重连同步并按原事件身份补报结果。
- RL-07：升级设备端时，通过替换 CLI 安装程序并重启 `batond`（或重新执行 `batond install` / 重启用户服务），或直接覆盖安装新版桌面客户端完成；默认数据目录中的设备身份、目录授权与模型凭据保持不变。存储遇到未知、损坏或不兼容的数据结构版本时明确报错并拒绝写入，防止静默损坏数据；内部开发阶段结构调整后可按约定清理重建本地实验账本。

### 备份恢复与诊断记录

- RL-08：中心备份须配套保存 PostgreSQL 数据库、节点签名密钥与部署配置。中心从历史备份恢复后，管理员在开服前执行恢复后处理：注销旧浏览器会话、要求核对设备连接、冻结未决下行命令并将缺少完成证据的在途输入与 Project 运行标为未知或暂停，防止恢复后重复触发外部副作用。
- RL-09：中心与节点各组件的结构化日志、诊断摘要和设备端 Agent 运行记录（`transcript.jsonl`）均携带实际运行的发布版本号、源码提交与运行标识，可直接关联等待、失败、停止与恢复过程；不内置外部 OTLP 遥测导出或网页操作回放，凭据与敏感字段隔离遵循 Baton R-22、R-23。

## 验收

| 场景 | 设置与操作 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| 安装包隔离自检 | 将构建产出的安装包搬迁至临时目录，在空 PATH 与临时 HOME 下运行完整性检查 | 版本元数据一致，本地控制通道、Agent 宿主模块、Project Runtime 与权限检查全部通过；缺依赖时明确非零退出 | RL-01、RL-02 |
| 协议兼容与拒绝 | 分别使用同协议不同版本号、以及不兼容协议版本的 `batond` 连接中心 | 同协议正常同步通信；不兼容协议被明确拒绝，`batond` 停止重连并在状态中报告版本不兼容原因 | RL-04、RL-05 |
| 中心停服升级 | 设备正在执行回合时停止中心、执行迁移并重启中心 | 在途回合不中断，中心恢复后设备自动重连，过程记录与回复按序补报且无重复 | RL-06 |
| 设备覆盖更新与格式保护 | 停止 `batond` 或退出桌面客户端，替换同协议新安装包启动；另用不兼容账本版本启动 | 同协议更新后保留原设备身份、目录与凭据直接上线；账本格式不兼容时明确报错且不破坏原文件 | RL-07 |
| 中心备份恢复后处理 | 恢复历史数据库快照与配套签名密钥，执行恢复后处理再开服 | 旧登录会话失效，在途不确定输入标为未知、Project 暂停，未发生历史命令自动重发 | RL-08 |
| 版本化诊断与运行记录 | 运行一次消息回合、一次异常停止与一次 Project 运行，检查诊断输出与本地 `transcript.jsonl` | 日志、诊断摘要与运行记录均准确携带组件发布版本号与提交，运行轨迹完整无损且不含任何凭据秘密 | RL-01、RL-09 |
