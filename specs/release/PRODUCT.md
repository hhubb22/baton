# 发布与升级行为规格

Status: draft
Owner: Asa
Basis: 内部首版发布、凭据闲置过期与简单可靠升级的约定；[Baton R-02、R-23、R-25](../baton/PRODUCT.md)；[发布技术设计](TECH.md)。

## Summary

长期记忆按其规格完成后，Baton 发布供少量员工使用的内部首版，通过遥测和反馈继续迭代。首版确定持久数据基线，后续中心与 daemon 升级保留员工已经保存的工作。

本文定义发布与升级行为。持久存储已有基线版本与迁移摘要检查；构建身份、程序诊断、公开发布信息查询和安装包元数据一致性检查及连接版本核对已实现，中心通过管理员显式运行的恢复后处理注销旧授权并暂停不确定执行，本地升级准备提供 prepare、status、cancel。增量格式升级和安装切换流程尚待实施。现有打包工具、平台证据和已知限制见 TECH；真实模型质量评估按记忆规格单独进行，不新增为内部发布前提。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 发布基线 | 首个供员工保存真实工作的内部版本及其数据格式；此前实验数据可重建 |
| 安装目录 | 某个版本的程序、网页、迁移、依赖与许可，可由另一个完整版本替换 |
| 持久数据 | 数据库、设备身份、命令与报告账本、会话映射、配置、凭据及已保存输出，升级期间保留 |
| 升级准备 | 停止开始新的执行，等待当前工作结束并保存结果，使安装目录和数据可以安全切换 |
| 应用回切 | 恢复使用旧程序；是否可行取决于旧程序能否读取当前数据格式 |

首版提供人工触发、允许短暂停机的升级流程。静默自动升级、运行中进程迁移、多中心滚动升级和自动数据库降级不在本期范围。

## Behavior

### 内部首版

- RL-01：长期记忆按 [PM 验收](../project-memory/PRODUCT.md#验收) 完成，凭据生命周期与本文升级行为通过相应离线验收后，发布内部首版。真实模型评估与少量员工反馈持续进行，不以等待更多 Agent、手机布局或大规模容量结论延后首版。
- RL-02：每个发布版本具有可查询的版本号、源码提交、平台与数据格式说明，发布记录附安装包校验值、实际验证范围和已知限制。同一版本号对应固定源码与产物；修改后的源码使用另一个版本号。中心、daemon 与其子进程能够报告自身实际运行版本。
- RL-03：Windows 的现有进程回收限制继续作为首版边界保留；Cursor helper 的平台依赖失败按实际环境说明。未知的系统或 Agent 组合继续按安装、认证与上游能力报告开放。发布验证分别标明通过、失败、未测和已接受限制；测试失败后产出安装包不等于验证通过。

### 数据与兼容

- RL-04：从发布基线起，升级保留账号、Project、记忆及修订、Inbox、Thread、消息、回复、过程记录、设备身份与默认选择；设备本地保留配置、会话映射、排队输入、intent、命令回执、报告、模型凭据和仍在保留期内的完整输出。升级不能通过清空、重建账本或重新注册设备完成。
- RL-05：每个发布版本声明可共存的中心、daemon 版本，按先中心、后 daemon 的顺序升级。首版只支持本版，按清单明确列出的版本精确匹配，不接入其他发布版。双方协议版本必须一致；任一方为 development 时允许版本号不同，便于本地开发与发布包联调。升级来源与格式迁移链由后续升级实现声明，期间本地数据保留。
- RL-06：支持的版本组合中，核心通信继续工作。中心在验证设备身份后、登记连接和同步前检查版本；不兼容时返回 node_version_incompatible，说明双方版本、原因和升级指引并关闭连接。daemon 停止自动重连，在本地诊断中显示该拒绝；中心 outbox、本地命令、已保存结果与待补报数据保留，拒绝不续期设备凭据。设备升级前的兼容预检由后续升级入口提供。
- RL-07：每个持久存储独立记录结构版本和已执行迁移，升级按序执行所需迁移。重复启动或中途中断后，可以继续或明确报告失败，不重复执行业务。遇到未知、损坏或更新版本的结构时拒绝写入，保留原数据并报告原因。

### 后端升级

- RL-08：管理员使用新版本升级前，先停止旧中心和其他数据写入，取得一致的数据库备份并保存签名密钥及部署配置，再执行迁移。迁移完成后才对员工和设备提供业务服务。迁移失败时保持停服，指出失败位置，原备份继续可用；单个失败迁移不留下半提交。
- RL-09：中心升级期间，设备上的 Thread 继续按原执行时限工作并保存结果。Project Runtime 按既有租约与保存屏障退出。中心恢复后，设备重新连接并同步，闲置过期时先按 Baton R-02 重新认证，以原命令与报告身份补交数据；无法确认的输入维持原恢复规则。

### daemon 升级

- RL-10：用户发起升级准备后，设备停止开始新的 Thread 回合、恢复操作、Project 前台运行与后台记忆整理。当前 Thread 回合可以继续到结束；Project 前台保存当前进度后退出，已领取但未完成的输入按原历史恢复，后台整理停止并保留进度。中心和本地已经保存的排队输入继续保留，下一回合等待升级结束；停止、必要清理与结果补报仍可进行。
- RL-11：升级准备显示正在等待的工作、结果补报与进程清理情况。默认等待当前工作自然结束，用户可以另行显式停止或取消升级准备。没有隐式强杀或把超时视为升级就绪；未知执行与未确认回收必须显示原因。
- RL-12：升级就绪要求独立 Worker、agent-host、watchdog、Project Runtime 及已登记后代均已退出，结果已持久保存，数据库关闭且升级所需独占锁可取得。中心离线时允许结果只保存在设备账本。退出 daemon 本身不能作为所有进程已停止的证据；Windows 无法确认清理时保留未就绪状态。
- RL-13：在独立安装目录解包并预检目标版本，完成升级准备与本地一致备份后，切换启动入口并迁移持久数据。保留原数据目录和凭据目录。新版本完成本地检查、必要迁移及中心同步后，才恢复新执行；恢复沿用原 Thread、命令、输入、报告与存储代次，不重发结果不确定的输入。
- RL-14：准备、停机、目录切换、迁移或首次启动时中断后，升级状态保持可查询，新执行保持暂停。再次运行明确显示可以继续、可以取消还是需要恢复备份。自动恢复只处理已记录的升级步骤，不自动回放历史命令。切换前取消可恢复原版本；迁移开始后按实际格式决定恢复路径。

### 备份、失败恢复与反馈

- RL-15：备份与恢复说明列明中心数据库、签名密钥、部署配置，设备数据、外部会话存储及模型凭据的保存位置和恢复范围。恢复演练使用本地替身，验证账号、设备重连、历史、记忆和未补报结果。中心恢复旧备份后注销原会话并使恢复出的设备凭据失效，员工重新核对并授权；设备单独恢复继续服从现存中心的吊销与版本判定。恢复旧派发进度后先核查执行证据，无法确认的输入标为未知，不自动继续执行。
- RL-16：失败恢复先检查当前数据与旧程序的兼容性，兼容时可以应用回切；不兼容时继续修复迁移，或由管理员显式选择停机恢复备份。恢复会撤销备份之后的数据变化时，先说明受影响范围并取得执行者确认。不得只替换旧程序后让它写入不认识的新结构。
- RL-17：内部部署可以启用既有 OTLP 导出，按发布版本、系统、Agent/provider/model 与操作标识分析等待、失败、停止、恢复、记忆整理及额外成本。缺失数据如实标明；导出不可用不阻塞业务。员工反馈可携带对应操作标识，正文仅由员工主动提供，默认遥测继续遵循 Baton R-22、R-23 的内容限制。

## 验收

RL-A01 的默认开发身份、显式发布身份、中心与各子进程版本和诊断一致、匿名读取及归档拒绝重新贴标已有离线测试；macOS arm64 已验证 SEA 搬迁和最终归档解包，其他平台的本次元数据检查未验证。RL-A03 的同版同步、不同发布版与协议拒绝、development 混用、拒绝前后中心 outbox/凭据和本地命令/结果不变，以及 daemon 退出与诊断已有本地测试。RL-A04 的基线重复运行、迁移摘要篡改和未知或更新版本拒绝已有包内测试，PostgreSQL 另有事务失败回滚测试；RL-A08 使用本地 PostgreSQL 回退旧授权与派发进度，验证历史、记忆、恢复后的重新授权、不确定输入不重发及原结果补报；设备单独恢复的权限拒绝沿用 Baton R-02/R-04 测试。RL-A05、RL-A06 的本地暂停、输入保留、取消恢复、进程阻挡和 ready 拒绝新业务已有包内测试；增量迁移中断、提交后丢失外部进度及其余发布验收仍为 planned。验收使用本地数据库、进程替身与固定录制。平台加载与回收检查在对应系统运行，真实订阅和在线模型不进入自动化验收。首版验收以候选格式和最小增量迁移替身验证升级机制；后续发布使用实际上一发布包与格式，不为此前实验结构新增兼容用例。

| 编号 | 场景 | 必须观察到的结果 | 关联 |
|---|---|---|---|
| RL-A01 | 从最终发布归档解包，查询中心、daemon 与实际子进程版本 | 版本、提交、平台与发布说明一致；校验值可核对，失败与未测项如实呈现 | RL-01～03 |
| RL-A02 | 在支持的上一版中心与设备保存 Project、记忆、Thread、排队输入和未 ACK 报告，再按顺序升级 | 数据与原标识保留；已发送输入不重发，排队消息最终各发一次，报告各保存一次 | RL-04、05、09、13 |
| RL-A03 | 同版、不同发布版、development 混用及协议不符的节点连接中心 | 同版及协议一致的 development 组合正常同步；其他发布组合或协议不符在登记连接与写入前拒绝；中心 outbox、凭据与本地命令/结果保留，daemon 停止重连并说明升级顺序 | RL-05、06 |
| RL-A04 | 对 PostgreSQL 和各类 SQLite 迁移分别重复运行、事务中中断、提交后丢失进度记录；另尝试修改已应用迁移或用旧程序写新结构 | 可按持久迁移事实继续，无半提交与业务重放；篡改或不支持结构被拒绝 | RL-07、08、14、16 |
| RL-A05 | Thread 执行中、Project 前台等待模型、后台整理与 Worker 有排队输入时准备升级；同时由中心和本地提交新执行 | 当前工作按约定结束，后台进度保留；新执行暂停，输入保留；取消后恢复；显式停止沿用既有撤回规则 | RL-10、11 |
| RL-A06 | daemon 退出但 Worker 仍存活、后代回收不明、结果尚未 ACK，或中心离线 | 存活或未确认进程阻止就绪；已完整本地保存的结果允许离线升级，恢复后补报 | RL-11、12 |
| RL-A07 | 在准备、切换和迁移各阶段结束进程，部分数据库已升级后重启 | 升级状态与数据库事实可核对；恢复前不开始业务；兼容时回切，不兼容时拒绝旧写入 | RL-13、14、16 |
| RL-A08 | 从中心与节点的一致备份恢复，另重放含旧凭据或旧派发进度的备份 | 已保存历史和记忆可读；中心恢复后重新授权，节点单独恢复不能复活失效凭据；可能已执行输入不重发，证据不足标未知 | RL-15、16 |
| RL-A09 | 两版程序产生等待、失败、停止、恢复和记忆诊断，再让导出端超时 | 元数据可按实际版本关联，缺失用量标未知，业务继续；正文、路径、查询与凭据标记不外传 | RL-17 |

## 待审阅取舍

闲置活动的具体范围见 Baton R-02。首版中心只支持本版 daemon，development 联调仍要求协议一致。升级准备采用默认等待当前工作结束并保留队列的方案；当前没有阻塞文档编写的外部依赖。
