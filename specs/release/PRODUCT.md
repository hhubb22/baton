# 发布与升级行为规格

Status: partially implemented
Owner: Asa
Basis: 内部首版发布、凭据闲置过期与简单可靠升级的约定；[Baton R-02、R-23、R-25](../baton/PRODUCT.md)；[发布技术设计](TECH.md)。

## Summary

Baton 发布包含可查询的构建身份、签名更新清单和各平台安装包。设备在独立版本目录安装更新，持久数据保留在原目录；CLI、设备网页和桌面客户端共享更新状态。真实平台和故障恢复的验证范围见「验收」。

## 范围与概念

| 概念 | 含义 |
|---|---|
| 发布基线 | 首个供员工保存真实工作的内部版本及其数据格式；此前实验数据可重建 |
| 安装目录 | 某个版本的程序、网页、迁移、依赖与许可，可由另一个完整版本替换 |
| 持久数据 | 数据库、设备身份、命令与报告账本、会话映射、配置、凭据及已保存输出，升级期间保留 |
| 升级准备 | 停止开始新的执行，等待当前工作结束并保存结果，使安装目录和数据可以安全切换 |
| 应用回切 | 恢复使用旧程序；是否可行取决于旧程序能否读取当前数据格式 |

设备可手动更新或选择空闲时自动更新，默认等待运行中的工作结束。运行中进程迁移、多中心滚动升级和自动数据库降级不在本期范围。

## Behavior

### 内部首版

- RL-01：长期记忆按 [PM 验收](../project-memory/PRODUCT.md#验收) 完成，凭据生命周期与本文升级行为通过相应离线验收后，发布内部首版。真实模型评估与少量员工反馈持续进行，不以等待更多 Agent、手机布局或大规模容量结论延后首版。
- RL-02：每个发布版本具有可查询的版本号、源码提交、平台与数据格式说明，发布记录附安装包校验值、实际验证范围和已知限制。同一版本号对应固定源码与产物；修改后的源码使用另一个版本号。中心、daemon 与其子进程能够报告自身实际运行版本。
- RL-03：Windows 的现有进程回收限制继续作为首版边界保留；Cursor helper 的平台依赖失败按实际环境说明。未知的系统或 Agent 组合继续按安装、认证与上游能力报告开放。发布验证分别标明通过、失败、未测和已接受限制；测试失败后产出安装包不等于验证通过。

### 数据与兼容

- RL-04：从发布基线起，升级保留账号、Project、记忆及修订、Thread、消息、回复、过程记录、设备身份与默认选择；设备本地保留配置、会话映射、排队输入、intent、命令回执、报告、模型凭据和仍在保留期内的完整输出。升级不能通过清空、重建账本或重新注册设备完成。
- RL-05：业务通信按协议版本和能力判断，产品版本独立显示；同协议的不同产品版本可以通信。持久格式按各自迁移链检查，不能读取未知或更新格式。
- RL-06：业务协议不兼容时，中心拒绝业务连接，设备保留本地命令与报告，并通过独立认证更新通道接收更新请求。设备页的连接状态只反映业务连接，更新只显示新版本、进行中和失败的状态；缺少管理能力的旧设备提示先在本机安装新入口。
- RL-07：每个持久存储独立记录结构版本和已执行迁移，升级按序执行所需迁移。重复启动或中途中断后，可以继续或明确报告失败，不重复执行业务。遇到未知、损坏或更新版本的结构时拒绝写入，保留原数据并报告原因。

### 后端升级

- RL-08：管理员使用新版本升级前，先停止旧中心和其他数据写入，取得一致的数据库备份并保存签名密钥及部署配置，再执行迁移。迁移完成后才对员工和设备提供业务服务。迁移失败时保持停服，指出失败位置，原备份继续可用；单个失败迁移不留下半提交。
- RL-09：中心升级期间，设备上的 Thread 继续按原执行时限工作并保存结果。Project Runtime 按既有租约与保存屏障退出。中心恢复后，设备重新连接并同步，闲置过期时先按 Baton R-02 重新认证，以原命令与报告身份补交数据；无法确认的输入维持原恢复规则。

### daemon 升级

- RL-10：用户发起升级准备后，设备停止开始新的 Thread 回合、恢复操作、Project 前台运行与后台记忆整理。当前 Thread 回合可以继续到结束；Project 前台保存当前进度后退出，已领取但未完成的输入按原历史恢复，后台整理停止并保留进度。中心和本地已经保存的排队输入继续保留，下一回合等待升级结束；停止、必要清理与结果补报仍可进行。中心确认准备状态后停止向该节点领取新的 Thread 执行、Project 前后台启动和输入唤醒，暂停的输入不阻挡停止与撤回；确认完成或取消后恢复领取。
- RL-11：升级准备显示正在等待的工作、结果补报与进程清理情况。默认等待当前工作自然结束，用户可以另行显式停止或取消升级准备。没有隐式强杀或把超时视为升级就绪；未知执行与未确认回收必须显示原因。设备页根据节点上报显示等待升级或升级暂停，升级目标的本地路径与原始失败诊断保留在设备。
- RL-12：升级就绪要求独立 Worker、agent-host、watchdog、Project Runtime 及已登记后代均已退出，结果已持久保存，数据库关闭且升级所需独占锁可取得。中心离线时允许结果只保存在设备账本。退出 daemon 本身不能作为所有进程已停止的证据；Windows 无法确认清理时保留未就绪状态。
- RL-13：设备通过 `batond update` 或网页请求更新，桌面使用单一「更新并重启」入口。发布清单由受信 Ed25519 公钥验证，设备仅从已配置中心下载清单内声明的同源工件，核对平台、大小、摘要及程序身份。后台可预下载；选择空闲自动更新时，检查后竞争启动的任务仍自然结束。独立更新进程在 ready 后正常停机、备份并逐库迁移，再通过固定启动入口切换版本。目标 daemon 补报原结果并取得中心完成回执后恢复原队列。
- RL-14：准备、停机、切换、迁移或首次启动中断后，状态保持可查询，恢复按持久记录继续。迁移开始前可以取消；恢复业务前发生明确本地失败时，校验一致备份后可回切程序和数据；恢复业务后不自动还原旧数据。网络断开时保持等待，不把断线视为本地健康失败。

### 备份、失败恢复与反馈

- RL-15：备份与恢复说明列明中心数据库、签名密钥、部署配置，设备数据、外部会话存储及模型凭据的保存位置和恢复范围。恢复演练使用本地替身，验证账号、设备重连、历史、记忆和未补报结果。中心恢复旧备份后注销原会话并使恢复出的设备凭据失效，员工重新核对并授权；设备单独恢复继续服从现存中心的吊销与版本判定。恢复旧派发进度后先核查执行证据，无法确认的输入标为未知，不自动继续执行。
- RL-16：业务恢复前的自动回切同时恢复对应一致备份；业务恢复后如需恢复旧快照，管理员先说明备份后数据及外部副作用的影响并取得执行者确认。旧程序不能写入不支持的新结构。
- RL-17：内部部署可以启用既有 OTLP 导出，按发布版本、系统、Agent/provider/model 与操作标识分析等待、失败、停止、恢复、记忆整理、完整 Agent 活动（提示词、思考、工具调用与回复）及额外成本。缺失数据如实标明；导出不可用不阻塞业务。员工反馈可携带对应操作标识，默认遥测继续遵循 Baton R-22、R-23 的凭据与网页回放限制。

## 验收

| 场景 | 必须观察到的结果 | 状态 |
|---|---|---|
| 可信发布 | 签名、目标平台、大小、摘要或归档路径被篡改时拒绝执行；私钥不进入安装包 | 部分离线单测通过；完整安装包待验收 |
| 发布基线升级 | 两个实际构建的版本保留设备身份，签名下载安装后重新上线；Thread 队列与未确认报告继续恢复 | macOS arm64 双 SEA 空闲设备演练通过；原入口查询实际运行版本并重启新 daemon。队列跨更新执行和报告补报分别由独立 Worker、daemon 测试覆盖，尚未合并为真实包全链路 |
| 空闲与离线 | 当前工作自然结束，离线请求保留；业务协议不兼容时更新管理仍可用 | 排队输入在独立 Worker 测试中恢复一次；完整离线及不兼容协议组合待验收 |
| 中断与失败恢复 | 切换、迁移和首次启动中断后可恢复；业务恢复前核验备份后回切，恢复后禁止自动回滚 | 备份校验、回滚日志和完成后拒绝回滚已有单测；跨进程待验收 |
| 平台 | 按目标平台记录实际打包、运行和恢复结果 | macOS arm64 空闲设备双 SEA 更新已测；Linux、Windows 原生更新未测；macOS 桌面自动更新缺 Developer ID 证书 |

闲置活动的具体范围见 Baton R-02。设备更新保持已保存的队列，等待当前工作结束。
