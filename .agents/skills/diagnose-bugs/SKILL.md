# Diagnose Bugs — 缺陷诊断与修复

## Goal

用快速、可重复的反馈回路（Feedback Loop）定位缺陷根因，实施最小修复并补充回归测试。回路构建参考 [feedback-loops.md](references/feedback-loops.md)，通用红线见 [operating-contract.md](references/operating-contract.md)。

## Workflow

1. **建立最小复现回路**：
   - 优先编写或运行能在秒级稳定变红的单元测试/模块测试，断言用户报告的具体症状。
   - 若因环境限制暂时无法本地复现，整理已有日志/堆栈并标明「尚未复现验证」。
2. **提出可证伪假设并定位根因**：
   - 列出候选原因（「若原因为 X，则检查/改变 Y 会观察到 Z」），一次只改一个变量验证。
   - 临时调试日志统一加 `[DBG]` 前缀，定位后清理干净。
3. **最小修复与回归锁定**：
   - 先确认回归测试因该缺陷失败，实施修复后确认测试变绿，再运行相关测试套件确保无回归。

## Guardrails

- 不要凭猜测连续盲改多处代码；没有复现或直接证据前，不得声称已找到根因。
- 不要在生产代码中保留临时调试日志或专用测试环境变量开关。

## Stop Rules

- 完成根因验证、代码修复、回归测试与临时探针清理后，报告根因、修复位置与验证输出并停下。
