# TR1 场景分析说明书：字段指南

标题：`<PICOS XX版本> <IR XX需求> TR1 场景分析说明书`

按下列顺序输出章节。"归属"取 起草 / 起草·需外部资料 / 人填。

## 1. 需求澄清

| 小节 | 归属 | 要点 |
|---|---|---|
| 需求背景澄清 | 人填为主 | 提出人、客户信息与金额、期望时间保留占位符。应用场景、要解决的问题、期望方案可依据需求对齐结果起草，标注"待确认" |
| 需求范围澄清 | 起草 | 满足客户的最小范围：功能、性能、接口范围、IPv4/IPv6；明确不支持的范围；北向接口（CLI/SNMP/OpenConfig YANG）；限制场景。取自对齐结果中的"包含/不包含" |
| 落地产品形态澄清 | 人填 | 型号勾选由用户完成。可附上代码或芯片能力导致的形态限制作为依据 |
| 需求价值澄清 | 人填 | 需求类别、不实现或推迟实现的影响 |
| 需求澄清结论 | 人填 | 落地版本、范围、形态，或不落地、推迟的结论 |

## 2. 产品现状（起草）

现有实现对该需求的支持情况，以及与客户诉求的差距。引用代码路径、现有 CLI 行为和调查时的 commit。

## 3. 友商或竞品分析（起草·需外部资料）

只基于官方文档。每个厂商写明型号、版本和文档链接，最后给出方案优劣对比表。涉及方案选择的需求，至少覆盖主流厂商。截图和测试报告由用户补充。

## 4. 标准遵从（起草）

列出遵从的标准名称和版本（IEEE/IETF/ITU 等）。对不遵从的部分逐条写明：与标准的差异、影响、不遵从的原因，并引用条款号。

## 5. 架构备选思路（可选，起草）

仅在以下情况编写：方案选型影响场景设计；对 PICOS 软件架构变更大（进程定位变化、新增进程）；引入新的开源软件。

- 5.1 / 5.2 备选方案：方案描述、架构变更项、优缺点（功能、性能、可扩展性、复杂度、工作量）。只写真实可行的方案，不凑数。
- 5.3 最终使用方案：写建议方案和理由；专家裁决保留 `【待填：评审裁决】`。

## 6. 约束限制&缺陷汇总（起草）

需求实现后的部署限制和使用场景限制。

## 7. 场景分析

开头给出场景对应的拓扑与部署说明，按网元粒度分析各网元需要具备的能力。每个场景包含"场景分析描述"和"分解 SR"两节。

| 场景 | 是否必选 | 要点 |
|---|---|---|
| 功能场景 | 必选 | 输入、网元行为、输出；网元间配合用拓扑图或时序图。友商互通、默认行为变更单独描述。新增或变更的 CLI 与 show 命令按 SKILL.md 的 CLI 要求写全 |
| 故障场景 | 必选 | 链路 up/down、设备故障与恢复、进程故障与恢复 |
| 性能场景 | 可选 | 容量与时间指标、达成前提（叠加背景、CPU 状况）、时间与空间分析、资源占用、极端场景、技术风险。没有实测数据时写成待确认的预算 |
| 可维护场景 | 必选 | 面向现网的 log、告警、命令行；网元间定界与网元级定位手段 |
| 网管场景 | CLI 有增删改时必选 | 北向接口：NETCONF/RESTCONF、SNMP、gRPC、telemetry，区分 AmpCon 与第三方 |
| 可测试性场景 | 可选 | 能否黑盒测试；不能时提供测试手段，并说明代价（测试仪、人工、无法自动化） |
