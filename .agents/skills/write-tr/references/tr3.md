# TR3 概要设计说明书：字段指南

标题：`<版本> <特性需求> TR3 概要设计说明书`（XX High Level Design Specification）

按下列顺序输出章节。输入为 TR2 快照中的 AR 列表。

## 1. 简介（起草）

- 目的：文档的作用。
- 范围：软件名称与进程名；软件功能列出全部 AR（取自 TR2 快照，不改编号）。

## 2. 概要设计（起草）

### 2.1 第零层设计描述

- 软件系统上下文：组网方式，以及本软件如何与外部实体组成功能实体，配一张上下文图。
- 设计思路（可选）：设计方法、可选方案比较与结论、设计约束（遵循的标准、硬件限制、技术限制）、其他考虑。

### 2.2 第一层设计描述

| 小节 | 每项写明 |
|---|---|
| 模块分解 | 模块名、功能列表、子模块 |
| 数据分解 | 数据名称、变更类型（新增/修改）、数据结构类型、关键字段、目的 |
| 数据依赖关系 | 数据结构之间的关系，配图 |
| 接口描述 | 按模块列出接口：形式（函数签名）、输入、输出、返回值、目的 |

模块、数据和接口以代码为准；新增部分用拟议语气，并引用对应的 AR。

### 2.3 第二层设计描述（可选）

格式同第一层，仅在模块需要继续细分时编写。

### 2.4 功能设计

每条 AR 一节：介绍、输入（收到的报文、消息、接口 up/down 等事件）、处理（模块间如何配合、调用了哪些接口、处理逻辑）、输出（发出的报文、消息等）。

### 2.5 状态机设计（可选）

有状态的模块编写本节：状态定义、事件定义、状态迁移图（Mermaid `stateDiagram-v2`）、状态迁移表（当前状态 | 事件 | 动作 | 下一状态）。迁移表须与迁移图一致。

### 2.6 影响性分析

分析对已有功能的影响：受影响的调用方、共享数据和默认行为，为影响性测试提供范围。依据代码中的调用关系。

## 3. 开发者测试设计（起草）

### 3.1 黑盒测试

以 SR 为单位，每条 SR 至少一个测试例：前置条件、操作步骤、预期结果。需要上机的测试例同时作为实验室需求单的输入。

### 3.2 白盒测试（可选）

覆盖黑盒无法覆盖的时序场景和异常场景。以 AR 为单位，针对接口函数：被测函数、函数入参、预期的出参和返回值。

## 4–6. 收尾章节

| 章节 | 归属 | 要点 |
|---|---|---|
| 评审问题跟踪 | 人填（评审后同步） | TR3 评审问题须全部闭环 |
| 文档基线时间 | 人填 | HLD 基线日期 |
| 基线后变更记录 | 同步生成 | 日期、AR/模块、变更内容、原因 |
