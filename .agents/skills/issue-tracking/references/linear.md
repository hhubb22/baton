# Linear MCP 操作约定

Linear 官方 MCP 使用 `https://mcp.linear.app/mcp`；只读服务为 `https://mcp.linear.app/mcp/readonly`。优先使用宿主已经连接的工具与授权，不在 Skill 中保存 Token。MCP 工具名称、参数和可用范围以当前宿主实际发现结果为准，codemode 等包装层可能改变调用方式。

## 工具选择

| 任务 | 常见 Linear MCP 工具 | 要点 |
|---|---|---|
| 定位目标项目和 Team | `list_projects`、`get_project`、`list_teams` | 以实际返回 ID/归属为准，避免同名项目误写 |
| 获取候选工单 | `list_issues` | 限定 project/team；按需分页、去重 |
| 阅读单个工单和依赖 | `get_issue` | 传入实际 Issue ID/标识；支持时启用 `includeRelations` |
| 查询可用状态 | `list_issue_statuses` | 对目标 Team 查询，使用现有状态名或 ID |
| 获取已有讨论 | `list_comments` | 核对是否已有相同证据或操作结果 |
| 更新或创建工单 | `save_issue` | 更新**必须带 `id`**；新建传所属 Team 和 Title |
| 添加实施/审查证据 | `save_comment` | 新评论应指向准确的 `issueId`，避免错发项目线程 |

`save_issue` 可支持 `blocks`、`blockedBy`、`relatedTo` 等关系，但不同工具版本字段可能变化；操作前检查实际 schema。不要将 `relatedTo` 当成阻塞关系。追加关系或链接前检查是否已经存在。字段 `labels` 等可能是覆盖式更新，优先只修改明确需要的字段；不要重发旧快照的整个对象。

## 常见路径

**只读工单**：由用户标识解析目标 → `get_issue`（含关系）→ 必要时读取阻塞者 → 报告目标、状态、验收标准、依赖和未知项。未请求修改时停在这里。

**开发任务开始**：确认当前任务可执行、获准追踪进度 → 查询目标 Team 的状态 → 更新当前 Issue 为进行中 → 读取确认。已处于目标状态时不重复写入。

**开发完成待审**：先核对实际测试结果和 Git/PR 引用 → 检查现有评论 → 写入一次简洁实施证据 → 将 Issue 改为现有审查状态（若项目有）→ 读取确认。尚缺必须的测试时说明缺口，不标记为已验证。

**验收关闭**：核对独立审查结果、剩余阻塞和用户/项目验收约定 → 由有权限的主 Agent 设置完成状态 → 读取确认。审查只发现问题时写具体发现；不要仅凭实施者声明关闭。

**创建工单**：确认创建权限 → 查询目标 Project/Team 和相似标题或原始编号 → 提供有可观察验收条件的描述及必要依赖 → 创建 → 读取确认并返回新 ID；网络超时或未知结果时先搜索是否已创建，再考虑重试。

## 进度评论示例

```markdown
实施与验证
- 基线：<分支 / Commit / PR 链接，已核实>
- 改动：<实际完成的行为>
- 验证：<实际命令、环境、通过/失败/未运行>
- 审查：<审查者结论及引用，尚未审查则写待审>
- 未完成：<具体阻塞或验证缺口；没有则省略>
```

只填写有证据的字段，避免每次状态变化都复制完整报告。若历史评论已有等价结果，不重复发送。Issue 评论可能对工作区其他成员可见；写入前根据授权及信息分类检查敏感信息。

## 不可用与冲突

- MCP 不存在或认证失败：列出无法同步的操作；已授权的本地工作可继续，但不伪造 Issue 读写记录。
- 工单未找到/多项匹配：核实项目和标识；不要创建一个新任务来替代读取失败。
- 写操作失败或超时：重新读取目标 Issue 与评论；确认未生效才重试，避免重复创建或评论。
- 写前后远端发生变化：根据最新状态只做未冲突的授权修改；涉及优先级、范围或状态冲突时报告并等待决定。
- 子 Agent 只读应使用宿主权限或 Linear 只读 MCP 实际隔离；Skill 文本不提供权限隔离。

文档：https://linear.app/docs/mcp

## 项目启用示例

若项目长期采用 Linear，在 Git 仓库根目录的 `.agents/PROJECT.md` 声明 issue 模式与实际归属。下面的 Baton / Personal 仅是示例，其他项目须重新定位；老项目的用户目录 `PROJECT.md` 在仓库没有配置时仍可兼容读取。

```markdown
## 任务管理
- 模式：issue
- 提供方：Linear MCP
- Team：Personal（PS）
- Project：Baton
- 任务权威来源：Linear Issue
- 当前任务进展同步：在用户已授权的当前任务内更新状态与证据
- 新建或批量变更工单：逐次授权
```

项目配置帮助定位任务与记录已有授权，不能独立授予新的写入权限。issue 模式下 `to-tasks` 应先产出草案，获准后才创建 Issue；`implement-specs` 只同步当前任务的真实进展，`handoff` 优先从 Linear + Git 恢复，不必维护并行的本地 TASKS.md。
