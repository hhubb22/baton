# Align — 需求对齐

## Goal

在进入规格编写或代码实现前，与用户快速对齐目标、不做范围（Non-goals）、补充假设与阻塞问题。通用红线见 [operating-contract.md](references/operating-contract.md)。

## Workflow

1. **先查代码现状**：在向用户提问前，先阅读仓库相关代码、配置与现有文档，自行确认所有可从源码获知的事实。
2. **结构化复述需求**：参考 [ALIGN.template.md](assets/ALIGN.template.md)，简明扼要地列出：
   - **目标与范围**：本次要解决的具体问题与交付物（以及明确不做的部分）。
   - **关键行为与边界**：正常路径、异常情况与兼容约束。
   - **补充假设**：对原需求未明说之处所做的合理工程默认假设。
   - **阻塞问题**：仅保留会实质性改变行为或架构、且只能由用户拍板的问题（每个问题附推荐选项）。

## Guardrails

- 简单任务直接在对话中输出对齐摘要，无需强行生成本地文件；仅在跨会话复杂特性或用户要求时写入 `ALIGN.md`。
- 不得把本可通过阅读仓库代码确认的技术细节抛给用户回答。

## Stop Rules

- 输出对齐结论与待确认问题后**立即停下**，等待用户确认或修正；未获确认前不得开始编写正式规格或修改业务代码。
