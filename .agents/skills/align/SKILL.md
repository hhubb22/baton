# Align

让用户用最少的时间确认 Agent 理解对了，并把 Agent 自己补上的默认值暴露出来。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。复述使用 [模板](assets/ALIGN.template.md)。

## 收集输入

- 输入可以是用户的描述、讨论记录、外部评审文档快照或 issue。用户想先自由描述时，听完再复述。
- 能从代码、文档或标准查到的事实，由 Agent 自己查，查到的结果作为依据写进复述。
- 过程区已有 ALIGN.md 时，在它的基础上更新。

## 复述

按模板写出目标、范围、验收、补充假设和待定问题。

- 每条一句，使用项目已有术语。
- 假设表每条写明依据：用户原话、评审文档、代码，或"推断"。"如果不成立"一列写出后果，让用户一眼判断是否值得纠正。
- 输入是评审文档时，文档没有写到的内容全部进入假设表。
- 验收写成"条件 → 可观察的结果"，能够直接转成测试。

## 提问

只问会阻塞下一份产物的问题。判断标准：不回答它，就写不出行为规格的第一版，或者无法开始实现。

- 每个问题附上建议答案，并写明它阻塞什么。
- 每轮最多 5 个问题，最多 2 轮。
- 不阻塞的问题留在待定问题表，标注"不阻塞"，留给后续阶段。
- 用户回复"其余按建议"时，接受全部建议答案。

两轮之后仍有阻塞问题，说明需求范围过大或可行性未知。此时建议拆小需求，或者先做快速验证。

## 何时等待确认

复述的价值在于让用户有机会纠正。以下情况等用户确认后再进入下一步：存在阻塞问题，或者有假设一旦不成立就会改变目标、范围或重要行为。

当前请求已经授权继续（例如"对齐后直接写规格"），且没有上述问题时，保存复述并继续，在回复中指出关键假设，方便用户事后纠正。

## 完成

把复述保存到过程区的 `ALIGN.md`，记下确认状态和日期。

确认的是复述内容本身；待定问题在被回答之前保持待定。下一步通常是 `write-product-spec`，局部改动可以直接进入实施。
