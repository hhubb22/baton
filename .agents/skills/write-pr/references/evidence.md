# 差异与验证证据

## 差异基线

分支或 PR/MR：记录仓库、目标分支、merge-base 和 head commit，读取相应差异。用户指定提交区间时沿用该区间，说明它的含义。生成前后核对实际提交和覆盖范围。

工作区：分别确认暂存、未暂存和未跟踪文件，保留无关修改。可以用 `git status --short` 定位，再按用户范围读取差异。单一 `git diff` 输出不能代表所有未跟踪内容。涉及新文件时读取其实际内容，二进制文件记录内容摘要和必要的渲染结果。

需要材料跨会话、对外分享或更新时，把所选差异快照放在过程区，记录 SHA-256。快照包含所选已跟踪差异及新增文件的路径、内容摘要和文件类型，必要时包含文件模式或符号链接目标；仅有路径清单不足以识别后续内容变化。两份材料记录同一基线，元数据放在模板允许的位置或独立的过程记录中。

基线发生变化后，重查受影响代码和验证结果，再更新解释和链接。旧基线下的测试结果保留其原基线，不能冒充新结果。

## 验证与审查

每项验证关联实际命令或报告、执行环境、基线、结果和覆盖限制。只读代码推导出的行为写为解释；运行证据写为实测。计划、命令示例和静态结构检查分别说明各自状态。

前后对照优先复用已有失败记录、测试或截图。缺少修改前结果时如实说明；不会为了补齐模板擅自切换或重置用户工作区。需要新的对照实验时在合适的隔离环境中执行。

测试失败、尚未执行和外部环境待验证都明确保留。检查已通过且代码未变化时复用证据；补跑应覆盖当前缺口。调用方兼容性、持久化数据和回退后的状态需要结合实际改动说明。

已有 code-review 报告中的发现注明位置、条件、状态和来源。用户只要求写描述时，不额外启动完整审查；必要的代码核对用于确认解释。潜在问题与已确认发现分开，审阅重点可以是需要人判断的具体取舍。

## 项目模板

从 `PROJECT.md`、用户提供的材料或仓库模板取得正式格式。保留必填字段和顺序，输出语言按项目要求；没有语言约定时沿用用户请求。

公司模板可以通过本地路径或已授权可访问的链接引用。缺少测试报告链接、需求级别、关联编号或远端访问能力时，在对应字段标记待补及原因。格式示例中的数字、结果和编号不能当成任务事实。

发布前核对审核说明链接是否对目标读者可用。上传和分享需要已有授权；使用项目指定的位置，源代码和内部结果按项目的数据规则处理。未知远端操作结果先读取状态确认，避免重复创建或重复上传。
