# Write PR

交付可以直接用于 PR/MR 的正式 message，以及帮助审核者理解复杂改动的说明。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。差异覆盖、验证证据或材料更新需要核对时，读取 [证据规则](references/evidence.md)。生成 HTML 时再读取 [HTML 写法](references/html-writing.md)和 [页面模板](assets/REVIEW.template.html)。

## 输入与范围

确认用户指定的 PR/MR、分支、提交区间或工作区差异，记录实际覆盖范围。按证据规则保留可识别的差异基线；新材料从最终差异生成，已有材料先检查基线是否变化。

读取项目配置中的 PR/MR 模板、输出语言、审核说明偏好，以及项目术语表。配置未指定模板时查找仓库现有模板；有多个适用模板时按任务类型选择。项目模板的字段、顺序和必填项优先。模板无法读取时先完成差异调查，交付可用草稿并标明未核对字段。

读取受影响代码、相关规格、实际验证结果和已有审查发现，确认改动的动机、前后行为与影响。缺少信息时保留待填项。审查结论引用其来源，未审查时写明状态。

## 正式 message

在过程区生成 `PR.md`；项目没有模板时使用 [通用模板](assets/PR.template.md)。用户只要对话中的正文时直接交付。

先说明具体问题和交付后的行为，再写必要的变更、验证、影响和回退信息。用项目的领域语言；文件清单只保留有助于审阅的职责变化。内容长短按改动决定，简单修复用短段落即可。

验证引用实际执行的命令、结果和环境。必要的局部检查可在已有授权内补跑，发现实现问题时报告或交回实施任务。缺少运行结果、外部测试报告或需求级别时明确标记，不推断为通过。

## 审核者说明

用户要求 HTML，或跨模块、协议、状态流转等改动需要额外解释时，在过程区生成 `REVIEW.html`。简单改动且用户只要 message 时，交付 `PR.md` 即可。

根据审核者需要说明动机、前后行为、关键代码关系、验证证据和审阅重点。选择能解释该改动的图示、代码片段或前后对照，按需调整页面模板，删除空栏目。将文件和验证来源放在对应解释附近，保持与正式 message 一致。

两份材料使用同一差异基线。正式 message 按模板允许的位置引用审核说明；过程区的本地绝对路径仅供本机使用，远端 PR 使用可访问的相对附件或链接。尚未上传时，将待补链接留在交付说明中，保留正文可用。

## 检查与交付

核对模板必填项、事实来源、代码位置、验证状态和影响范围。生成后重查差异基线；发生变化时更新受影响内容，再核对两份材料。

HTML 实际打开检查导航、图示、代码片段、窄屏布局和链接。没有渲染能力时保留文件，标明只完成源码检查及待确认项目。

交付正文或文件位置、实际覆盖范围、验证结果和待补信息。创建、更新或上传远端材料按已有授权与平台能力执行；报告实际远端链接和结果。生成材料本身不修改产品实现。
