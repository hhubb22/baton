# 任务边界与工程红线（Operating Contract）

本契约仅保留防止 Agent 越界、破坏代码架构或污染长期文档的核心红线。

## 1. 阶段门禁（Stage Gate）

- **单阶段停靠**：除非用户明确授权自动推进多阶段，每次只完成当前请求的阶段（如对齐、规格、设计、拆分、实施或审查），交付结果后停下等待用户确认。
- **不把草稿当批准**：未获用户确认的假设、规格草稿或拆分方案不得直接进入代码实施。

## 2. 事实与证据（Evidence Over Speculation）

- **先查代码再下结论**：仓库内可通过阅读源码、运行命令或测试确认的事实，直接自行核实，不把内部代码细节抛给用户回答。
- **诚实标注未验证项**：只报告实际运行过的命令与测试结果；当前环境未运行或无法覆盖的部分明确标为「未验证」，绝不伪造测试通过或用 mock 冒充真实集成结论。
- **数据与凭据安全**：严禁将口令、私钥、API Token、数据库连接串或含敏感信息的原始日志写入代码、测试夹具、文档、工单或提交记录。

## 3. 代码与测试防腐（Code & Test Hygiene）

- **测试金字塔**：纯逻辑、状态流转、解析校验与存储不变量优先用包内单元测试（Unit Test）或确定性回放覆盖；多进程/浏览器端到端（E2E）测试仅用于核心主链路验真。
- **生产代码不埋测试钩子**：禁止为了凑测试覆盖率而在生产代码中新增 `os.Getenv("TEST_*")` 等专用故障注入分支；应通过接口抽象与依赖注入测试异常路径。
- **零配置开发者体验（Zero-Config DX）**：日常构建与测试命令（如 `go test ./...`、`pnpm test`）必须提供合理的本地默认值，开箱即用，不强制要求外部云服务或密码管理器。

## 4. 文档即现状，绝非流水账（State ≠ Changelog）

- **原地更新现状**：仓库长期文档（`README.md`、`AGENTS.md`、`PRODUCT.md`、`TECH.md`）只描述系统**当前**的架构、行为与配置。
- **严禁追加历史段落**：修改长期文档时，直接改写对应章节并删除过期描述；**严禁**在文档头部或正文中追加「当前已实现 PS-xxx / Txx」或「2026-xx-xx 修订」之类的工单流水账。变更历史由 Git 与工单系统记录。
