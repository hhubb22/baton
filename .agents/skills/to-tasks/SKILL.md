# To Tasks — 粗粒度垂直切片拆分

## Goal

仅针对**跨多天、跨多会话的大型特性**，将已批准的设计拆分为 **3～5 个**可独立交付的垂直切片（Vertical Slices）。单次会话（1～2 小时内）能直接写完的特性，直接进入 `implement-specs`，**不走本拆分流程**。通用红线见 [operating-contract.md](references/operating-contract.md)。

## Workflow

1. **评估是否需要拆分**：
   - 若需求可在当前会话一次性实现并验证，直接建议用户进入 `implement-specs`，不生成任务卡。
2. **按粗粒度垂直切片拆分（通常 3～5 个任务）**：
   - 每个切片必须是一个**用户或调用方可感知的完整增量能力**。
   - **严禁水平切分或过度切碎**：不要把「建表迁移」「写内部 struct」「补一个测试」「修一个报错」拆成独立任务（绝不再出现一个特性拆 20～30 张碎卡的情况）。
3. **极简任务描述（每个任务 ≤ 8 行）**：
   - **标题**：动宾结构，表达交付的能力。
   - **依据**：指向 `specs/<feature>/PRODUCT.md` 或 `TECH.md` 的具体章节，**不重复抄写设计正文**。
   - **依赖与完成标准（Done When）**：前置任务 + 2～3 条核心验证点（遵循测试金字塔，优先包内单测）。

## Guardrails

- 默认先在对话中输出 3～5 个切片的精简草案（或写入本地 [TASKS.template.md](assets/TASKS.template.md)）。
- 仅在用户明确要求同步到外部工单系统时，才调用 `issue-tracking` 创建工单。

## Stop Rules

- 输出拆分草案后停下，等待用户确认。
