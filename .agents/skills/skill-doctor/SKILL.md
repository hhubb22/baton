# Skill doctor

根据真实任务记录，找出可以改善后续会话的具体问题。改进对象可以是 skill、项目指令、代码导航、自动检查、工具或环境。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。处理会话前读取 [证据与隐私](references/evidence-and-privacy.md)；检查范围见 [会话复盘](references/session-review.md)，归因与改动依据见 [维护准则](references/rubric.md)，报告使用 [模板](assets/REPORT.template.md)。

## 选择材料

只使用当前请求授权的会话与相关文件、工具或配置。明确给出的文件直接处理；用户指定当前会话时直接分析。"最近这些会话"无法定位时，询问一次具体范围。没有样本时可以审计指令结构，并说明行为改进尚未得到证明。

需要整理导出的文本或 JSONL 时，可以运行 [离线收集器](scripts/collect_sessions.py)，先查看 `--help`。收集器在本地运行，不调用模型、不上传，但不保证完全脱敏；云端模型读取材料时，材料可能发送给模型提供方。按项目数据规则选择脱敏导出或本地模型。

## 诊断与修改

以任务目标、实际工具结果及产物为依据，检查 skill 选用、执行停顿、权限、验证、文件导航、自动检查、工具成本、信息获取和跨会话交接。任务最终完成时，也检查中途有证据的反复失败和无效操作。按严重性和重复出现的程度排列候选，数量以证据为准。

核对当时加载的指令版本；只有当前版本时，标记版本不确定。区分触发或加载问题、指令缺口、指令冲突、模型波动和工具或代码缺陷。某个 skill 出现在失败会话中，不能证明它导致了失败。已有的正确规则被忽略时，先查加载与冲突，再考虑修改。

检查现有命令、脚本与 CI，再决定是否补自动检查。可机械判定的错误优先由确定性检查处理；需要判断的约定放在项目已有审查规则中。导航、日志、CLI 和环境问题修在所属位置，减少对每次实现都要读取的指令的占用。

提出能解释问题、可复用且最小的修改，优先删除或替换。报告证据位置、改进对象及所属文件、预期变化和副作用。分析期间只在报告目录生成 proposed 文件和 diff，正式规则与环境保持原样。依据不足时保留观察或不提出修改。

## 比较与交付

用原案例检查修正，用未参与修改的相邻案例检查回归；优先比较任务结果和越界、停顿情况。保持模型、工具、任务与代码基线可比；版本缺失或未重跑时明确标记。

默认交付 Markdown 报告、候选补丁和验证状态。无法实际调用目标宿主时，给出可执行的试验计划，静态检查只作为结构证据。证据不足以支持修改，也是有效结论。

用户明确要求应用候选补丁时，核对正式文件未漂移，保留回滚版本后应用并检查。验收标准在本次评价中保持不变。一次复盘结束后交付候选，由用户选择；不自动反复执行诊断和修复。定时任务和持续监控不在本 skill 范围内。
