# 会话复盘

根据会话中的具体问题选择检查项。每项发现引用消息、工具结果或产物位置，说明任务预期、实际影响和归因限制。

| 检查项 | 证据与候选改进 |
|---|---|
| 选用与执行 | 检查误触发、漏触发、停顿、越权和无效验证；先核对实际加载版本与冲突，再考虑改 skill |
| 代码导航 | 反复搜索、读错模块或遗漏依赖时，检查已有入口文档和模块索引；在合适位置补简短导航 |
| 自动检查 | 对照实际错误读取项目已有 lint、类型检查、测试命令和 CI；区分检查缺失、未接入、失败被忽略及覆盖不足 |
| 项目指令与审查 | 检查 AGENTS.md 等文件中重复、冲突或没有明确动作的规则；机械规则交给检查器，需要判断的约定由项目审查规则承载 |
| 工具使用 | 输出过大、重复读取、无关调用或 CLI 不可用时，核对实际输出与环境；优先使用过滤、摘要、批量查询或已有命令 |
| 信息获取 | 关键日志、运行结果或只读信息缺失时，说明它怎样影响判断；提出获取方式和所需权限，权限变更交给用户决定 |
| 上下文与交接 | 压缩或换会话后要求、基线或授权丢失时，检查已有任务状态和交接记录；把稳定且反复需要的要求放到所属文档或 skill |

先查已有机制能否覆盖，再提出最小改动。检查器候选应写明要捕获的错误、误报风险与运行位置；工具改进应保留下一步需要的错误细节。日志里没有 token 用量时，只描述观察到的输出量和重复次数。

单次失败按其证据判断；成功会话可以没有改进建议。缺少 CI、文件较长或某条规则未被调用，只能作为调查线索，结论需要结合任务和已有机制。
