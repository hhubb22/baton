# 技术文档写作指南（Technical Writing）

技术文档的目标是让人类开发者与 AI Agent 快速建立准确的心智模型，而非堆砌晦涩的教条或文字墙。

## 1. 结构化优先于密集散文

- **多用表格与列表**：状态迁移、配置项、接口字段、错误码与模块职责优先使用 Markdown 表格或清晰的要点列表，避免把几十条规则塞进超过 5 行的散文大段。
- **先给全景，再写细节**：文档开头用简短段落或 ASCII 架构图说明核心目标与组件关系，让读者在 30 秒内看懂全局。

## 2. 清晰、可检验的表达

- **条件与结果明确**：写清「触发条件 → 系统行为 / 可观察结果」，一条规则只表达一件事。
- **自然流畅的工程语言**：使用准确、直白的技术中文；不要机械套用僵硬的翻译腔或把可读句子压成难以理解的电报体。
- **术语前后一致**：同一概念在代码、规格（`PRODUCT.md`）与技术设计（`TECH.md`）中使用相同名称。

## 3. 保持文档高信噪比

- **只写当前生效的设计**：文档反映系统当前状态。修订时直接原地更新对应章节，**严禁**保留「旧方案 vs 新方案」的历史演进长文或追加每张工单的改动摘要。
- **不跨文档复制**：`PRODUCT.md` 写外部可观察行为与验收边界，`TECH.md` 写进程职责、数据模型与关键机制；两处通过链接互相引用，不重复抄写同一内容。
