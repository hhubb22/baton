# Work

把目标推进到当前授权范围内的完成状态。主路径给出默认顺序，每一步都有跳过条件；明确的小任务直接完成。

首次使用本库且尚未读取同版时，读取 [任务边界](references/operating-contract.md)。选好路径后用一句话告诉用户，然后开始。

开始时读取项目配置 `PROJECT.md`，位置见任务边界。项目还没有这份文件时，提示一次可以按 [模板](assets/PROJECT.template.md) 创建，然后按通用默认继续。主路径中标注"按项目配置"的步骤，只在配置声明了相应内容时出现。

## 选择起点

| 手头有什么 | 从哪里开始 |
|---|---|
| 已评审的外部评审文档（TR、PRD 等） | `align`，以文档快照为输入 |
| 想法、口头需求或 issue | `align` |
| 可行性不确定，需要先试 | 快速验证 |
| 已知缺陷或异常现象 | 修 bug 路径 |
| 只想弄清代码、标准或机制 | `research` |
| 已批准的设计 | `to-tasks` 或 `implement-specs` |

## 主路径：需求到交付

1. **对齐** `align`：复述目标、范围和验收，列出补充的假设与阻塞问题。有阻塞问题或关键假设待定时，等用户确认；当前请求已授权继续时，记录复述后进入下一步。
2. **能否在讨论中定下来？** 需要运行才能回答的问题，例如性能、硬件或第三方系统的行为、协议互通，先走快速验证，再带着结论回到第 1 步。
3. **行为规格** `write-product-spec`：外部行为、CLI、边界或错误情形需要书面约定时编写。局部改动且行为明确时跳过。
4. **技术设计** `write-tech-spec`：跨进程或模块、改接口、或存在真实取舍时编写。
5. **拆分** `to-tasks`：工作跨多个会话或需要多次进入隔离环境验证时拆分。一个会话能完成时跳过。
6. **实施** `implement-specs`：逐个任务实现并验证。按项目配置：有开发环境无法直达的验证环境时，用 `lab-request` 生成需求单。
7. **审查** `code-review`：审查最终差异，包括需求符合性。
   需要准备 PR/MR 描述时，用 `write-pr` 基于最终差异整理正式 message；复杂改动或用户要求时补充 HTML 审核说明。已有描述需要更新时可以直接进入 `write-pr`。
8. **评审材料**：按项目配置。声明了外部评审文档及对应 skill（例如 `write-tr`）时，用它准备评审、整理评审结论，或回报基线后的偏离。评审结论影响规格或设计时，回到第 3、4 步更新。

第 3、4 步的长期文档与代码一起提交；第 1、5 步的产物和隔离环境的请求与结果留在过程区。

## 快速验证

用最小代价回答一个具体问题，不产出长期文档。

- 在过程区记下问题、做法和结论。
- 原型代码放在独立分支或目录；得出结论后删除或归档。
- 结论决定正式开发时，从主路径第 1 步进入，原型只作为证据引用。

## 修 bug 路径

`diagnose-bugs` 建立反馈回路、定位根因并修复 → `code-review`。

修复牵涉跨模块改动时，定位完成后转 `implement-specs`。修复改变了对外行为时，同步更新行为规格。

## 阶段边界

- 第 1–5 步尽量在同一会话完成，让对齐、规格和拆分基于同一份理解。
- 上下文接近上限时，在阶段之间用 `handoff` 交接，避免在阶段中途切换。
- 实施阶段每个任务可以开新会话，从过程区的任务清单和长期文档恢复上下文。
- 方向不清或用户表示没理解时，用 `wait-what` 暂停并重新对齐。

## 其他能力

| 需要 | 选用 |
|---|---|
| 整理术语、概念关系或重要决策 | `domain-modeling` |
| 向知情者收集缺失的事实或决定 | `to-questionnaire` |
| 编写 PR/MR 描述或向审核者解释已有改动 | `write-pr` |
| 复盘 Agent 行为、skill 质量、工具或开发环境 | `skill-doctor` |

用户要求复盘，或想检查反复失败、工具低效、上下文丢失时，选定会话交给 `skill-doctor`。它交付候选改进，由用户选择；主路径完成后不自动进入复盘修复循环。

按宿主的 skill 发现功能定位能力；同名冲突时先确认采用的来源。缺少目标 skill 时说明缺失，并直接完成力所能及的部分。专项 skill 结束后回到用户，由用户决定下一步，或在已授权范围内按主路径继续。

## 完成

用户要的结果已交付且验证有结果，或者阻塞原因和待决定事项已具体说明。选好路径不等于任务完成。
